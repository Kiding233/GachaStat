## 2. 适配器契约

```python
class Adapter(Protocol):
    name: str                 # 路径标识，写入每条 RunResult
    is_user_path: bool        # inline 为 False，其余为 True
    def available(self) -> bool: ...        # 本环境能否跑（无 PyQt6 则不报错，跳过）
    def run(self, plan: Plan) -> RunResult: ...
```

**职责**（详见 `01-理论.md` §3 驱动复用约束）：

1. 建起这条路径的运行环境
2. 把 `Plan` 翻译成这条路径的输入
3. 在**正确的进程与线程边界**上挂计时器与剖析器
4. 以这条路径自己的方式等待结束
5. 归一成同一个 `RunResult`

**禁止**：新写驱动。只能修复或包装已有入口。

**已知未验证项**：`gui-qt` 适配器的面板分发段（见 `01-理论.md` §9.2）。初版覆盖面定到 `SimulationThread` 结束。

## 3. Plan（测量规格）

```python
@dataclass(frozen=True)
class Plan:
    config_path: str
    strategy_key: str
    strategy_params: dict
    n: int
    workers: int
    seed: int
    chunksize: int | None = None      # None = 交给 run_batch_parallel 自算
    path: str = 'cli'
    grain: str = 'stage'              # batch | stage | single | function
    repeats: int = 3                  # 取中位数；建基线时强制 >=3
    py_spy: bool = False
    note: str = ''
```

## 4. RunResult（记录）

```python
@dataclass
class RunResult:
    run_id: str
    timestamp: str
    path: str
    is_user_path: bool
    fingerprint: EnvFingerprint       # cpu / cores / os / python / 代码版本
    plan: Plan                        # 完整规格，保证可复现
    wall_median: float
    wall_samples: list[float]         # 各次原始值，用于判断方差
    stages: dict[str, float]
    single: SingleStats | None
    functions: list[FuncStat] | None  # (name, ncalls, tottime, cumtime)
    resources: ResourceStats          # 序列化字节数、RSS 峰值
    samples_meta: SamplesMeta | None  # py-spy: duration / samples / errors
    not_comparable: bool = False      # function 档为 True，被基线比值排除（P83 §3.8 D6）
    warnings: list[str]               # 含 repeats_downgraded 等
```

## 7. 阶段划分（设计中，待用户确认后展开为可执行子任务）

| 阶段 | 内容 | 交付判据 |
|------|------|---------|
| 1 | 内核 + `cli` 适配器 + 基线登记与比对闭环 | 能回答「cli 路径这次比基线慢了多少」 |
| 2 | `inline` 适配器（接管修复后的 profile_sim 逻辑） | 纯计算基线可复现 |
| 3 | `gui-qt` 适配器（offscreen）+ 阶段口径对齐 profile_gui 分段 | GUI 路径可进自动化 |
| 4 | `webui` 适配器 + `py-spy` 采集层与解析 | 四条路径齐备，现场勘查可用 |
| 5 | `function` 档（cProfile 在 worker 侧的注入与合并）。机制见 P83 §3.8：`env` 四字段触发、围绕单次 `_run_single` 调用的开闭窗口、结果走文件不经三元组通道 | 函数级判据可进基线 |

阶段 5 单独列出的原因：`cProfile` 在 `multiprocessing` 子进程侧的注入需要改 `_wk_init` / `_wk_run_single` 的调用形态，是唯一需要触碰被测量代码的阶段，风险高于其余各阶段。

## 8. 阶段 5 的接口约束（P83 §3.8 摘要）

阶段 5 是全平台唯一触碰被测量代码的地方，三条约束不可回退：

1. **`SimulationEnv` 新增 4 字段**：`profile_enabled` / `profile_dir` / `profile_skip` / `profile_count`，全部带默认值以保持跨进程 pickle 兼容（照既有 `return_compact` / `n_heatmap_bins` 的模式）
2. **采样窗口在 `_wk_run_single` 内开闭**，不在 `_wk_init` 里做进程级 enable。依据是 `multiprocessing.pool.Pool.__exit__` 走 `self.terminate()`（本机 Python 3.12.5 源码核验），worker 被强杀、`atexit` 不执行
3. **剖面结果走文件**（`dump_stats` + 父进程 `pstats.Stats.add()` 合并），不动 `CompactResult`、不动 `_RESULT_VERSION`、不改 `_wk_run_single` 的三元组 arity（其 docstring 有 ⚠ 明确契约，父进程有 `len(result) == 3` 守卫）

失败一律软降级，绝不因剖析失败导致模拟失败。
