## 对计划编写方法的教训

**教训一：判定的「依据面」被同轮修复之后，判定本身必须重发或显式作废。**
实证：门控 `依赖顺序` 判 `NEEDS_CLARIFY`，其唯一未达标面是 S2a-1 的基类 `apply` 默认实现引用 M2 的 `_apply_delta`（按字面施工即 `NameError`）。同一轮的第 11 次审查已用 `AUDIT-BREAK-3` 把该处改为「M1 期占位实现」两期形态（第 2339 行、第 2663 行、第 2667 行三处同步），而阻塞章节仍以「非 PASS 项 2 个、各附 `clarify_suggestions`」原样呈现，审查条目亦自述「本轮不改变其判定」。同一章节内 `文件清单` 的依据面则确实仍在（§四 无 `scripts/p82_baseline.py` / `tests/fixtures/p82_baseline/` 登记行）。可复用规则：**审查产物的每项判定须绑定它所依据的具体文本位置；任何修复落在该位置上时，须同批更新或作废该判定，否则读者无法区分「判定反映快照时刻」与「判定反映现行文本」。**

**教训二：同一份核对结果里出现两个生效值，等于没有结论。**
实证：阻塞章节的机械复校段先判「第 2697 行实为第 2712 行」，随后同段偏移表又写「2697→2700」，而 2700 与所述互指无关（实测第 2712 行才是含 `S4b` / `max_triggers` / `rotating_inverse` 三处互指的条目）。同型形态还有锚点计数：同节首句 410、紧接括注 428、第 3128 行又写 410（独立复跑值 428，`.py` 409 / `.md` 19，去重 256 / 243）。可复用规则：**机械核对的产出只允许保留一个权威值；旧值须单列为「时点记录」并标注作废，不得与现行值并列在同一段内。**

**教训三：枚举类声明（「仍开放 N 处」）不能凭人工列举，须由机核生成。**
实证：阻塞章节的口径补充声明「正文各节仍开放 4 组 `⚠ 待人工裁决`」另加两处同类（共 6 处）；机核全篇得 13 处标注、归并 8 组，未列的两组是 §3.1.1 第 3 条的 ISSUE-928 与 §四 `core/strategy.py` 行的 ISSUE-730 / ISSUE-944。其中 ISSUE-928 在上一轮报告（2026-09-30）中是待裁决清单**第 1 项**，属「上一轮认得、本轮漏掉」。同处还有位置归属错误（ISSUE-702 记为 §1.3，实为 §3.1.1）。可复用规则：**凡「共 N 处 / 仍开放 N 组」的声明，须附提取命令与机核输出，且该声明本身要被下一轮复核。**

**教训四：可自行复跑的机核，其结论应固化为一处可执行入口，「已在正文核过」不等于「有回归能力」。**
实证：本计划自陈「`tools/refcheck/` 对本文零关系登记、`scripts/` 下亦无『锚点落在空行即报错』的一次性机核脚本」；实测 `scripts/` 目录确无同类产物，而该机核已在本计划的历史核对中证明可零人工判读地抓出 20 处必错项。本报告以同一正则独立复跑，即复现 428 / 0 / 0 / 0 四个数，成本极低。可复用规则：**把一次性核对固化为脚本（提锚点 → 读目标行 → 空行 / 越界 / 缺失即报错），使每轮只判增量，而非重述总量。**
