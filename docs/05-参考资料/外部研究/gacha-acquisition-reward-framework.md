# 「获得卡牌时触发额外资源产出」通用框架设计

> 适用范围：抽卡概率模拟系统（多卡池、资源积累、保底）。  
> 目标：用尽可能少的原语覆盖「获得卡牌 / 执行抽卡时产出额外资源」的全部机制，向后兼容，且不排除合理扩展。
>
> 修订记录：v2（2026-07-25）——采纳"仓库 = 累计获得次数、卡本体永不消耗"假设，取消转化型/附加型维度与 `consumeCard` 标记；新增可折叠判据（强制单一路径的溢出分解 ≡ 直接产出）。

---

## 0. 事实核查：案例验证与校正

设计之前先验证事实。对背景中描述的机制逐一做了独立检索，结论如下——**两处描述不准确，一处未能证实**，校正后的事实反而是更好的设计输入。

| 游戏       | 背景描述                         | 核查结论         | 校正后的精确规则                                                                                                  |
| -------- | ---------------------------- | ------------ | --------------------------------------------------------------------------------------------------------- |
| 原神       | 抽到5星给10星辉，满命后再抽到给25          | ✅ 基本准确       | 5星角色**第2~7次获得**（任何途径：祈愿/商城兑换/系统赠送）→ 命星×1 + 无主的星辉×10；**第8次起** → 仅星辉×25。4星同构（2星辉→5星辉）                       |
| 星穹铁道     | （同原神）                        | ✅ 同构，且提供了新形态 | 5星角色第2~7次 → 星魂×1 + 星芒×40，第8次起 → 星芒×100；**光锥只要抽到就给星芒（5星40 / 4星8），无持有数/次数维度**                               |
| 明日方舟     | 6星未满潜给10黄票，满潜后给15            | ✅ 基本准确       | **首次获得任何干员给1黄票**（"新干员"标记）；第2~6次获得6星 → 黄票×10；满潜后（第7次起）→ 转化为信物，信物可在交易所按1:15兑换黄票。公开招募/商店兑换/卡池抽取均生效           |
| 阴阳师      | 40抽送随机SSR，送的卡按持有数给御札（溢出自动生效） | ⚠️ 部分准确      | 40抽送随机SSR/SP属实，但官方公告明确"**不计为召唤获得**，不影响召唤成就与活动次数统计"；御札**并非获得时自动产出**，需玩家在神龛手动返魂（SSR=750御札，首次返魂某SSR额外给10金御札） |
| NIKKE    | 不同池子抽到同一张SSR给不同数量金票/银票       | ❌ 不准确        | 金票/银票**按抽卡次数发放，与抽到哪张卡无关**（UP池1金票/抽、普池1银票/抽，200金票兑换当期UP，跨期保留）；抽到重复SSR → 自动转备用躯体；满星后溢出躯体 → 转躯体标签（SSR=6000）  |
| 火影忍者手游   | 重复碎片自动转换为通用碎片                | ✅ 基本准确       | 重复获得转升星碎片（同类资源）；**满5星后**溢出碎片可兑换通用货币玉石（S=20/A=8/B=2/C=1）——手动兑换，非自动                                         |
| 明日方舟：终末地 | 六星首次获得（任何方式）给额外奖励            | ⚠️ 该具体规则未证实  | 已验证的相关机制：**抽出六星送2000武库配额（十连无六星送380）——产出流向另一个池子的资源体系**；累计240抽送当期UP信物（每240一次）；30/60抽送十连，且**赠送的十连不计入保底计数**   |

### 核查带来的四个设计输入

1. **获得路径的区分是真实存在的官方行为**：阴阳师"不计为召唤获得"、终末地"赠送抽不计入保底"——系统必须记录"这张卡/这次抽是怎么来的"。
2. **大型溢出规则往往是路径无关的**：原神、方舟明确"任何途径获得都按同一规则转化"——规则跟卡走，不跟池走。
3. **NIKKE 证明了规则挂池子的真实需求**：金银票是池子的促销返利，与卡无关。
4. **终末地证明了跨池资源产出的真实需求**：角色池出六星，产出的是武器池配额。"产出归属 = 触发池"的假设需要修正。

## 1. 核心抽象

所有案例收敛为同一个句式：

> **当系统事件流中的某类事件发生时，若某段可观测状态满足条件，则向资源流注入产出。**

统一原语只有一条：

```
规则（Rule） = 触发（Trigger） × 条件（Condition） × 产出（Output），挂载于宿主（Host）
```

所谓"机制设计"，就是在这条原语的四个槽位上取值。下面逐维度分析。

---

## 2. 维度分析：六个正交维度

### D1 触发面 —— 什么事件启动规则检查

| 取值                         | 语义               | 负载                         | 实证                              |
| -------------------------- | ---------------- | -------------------------- | ------------------------------- |
| **CardAcquired** 卡牌获得      | 一张卡进入系统视野        | 卡ID、稀有度、获得路径、来源池、获得后的计数器快照 | 原神、方舟、NIKKE躯体                   |
| **DrawPerformed** 抽卡行为     | 一次付费抽卡动作完成，与结果无关 | 池、单抽/十连、消耗的资源类型            | NIKKE金银票、阴阳师"每召唤1次得1个异世之结"      |
| **MilestoneReached** 里程碑达成 | 池抽数计数器跨越配置阈值     | 池、当前抽数                     | 阴阳师40抽送SSR、终末地240抽送信物、30/60抽送十连 |

**边界外（排除）**：玩家主动分解/兑换（阴阳师返魂）不是"获得时触发"，而是独立的资源处置系统。本框架产出的货币可以作为那些系统的输入，但那些触发点不纳入本框架——纳入会让"获得"与"处置"两个生命周期阶段纠缠在一起。（例外：强制单一路径的溢出兑换不是决策而是管道，按 §5 可折叠判据折叠进获得规则，如火影玉石商店、方舟满潜信物兑换。）

**设计要点**：系统中恰有 **3 个触发点**。DrawPerformed 与 CardAcquired 的区别是根本性的——前者按"次"结算、与结果无关，后者按"卡"结算。NIKKE 同一游戏里两者并存（抽一下给票 + 重复SSR给躯体），证明它们必须是一等公民的两个触发点，而非一个触发点的两种参数。

### D2 路径面 —— 获得事件从哪来

取值：`draw`（池子随机抽出）/ `milestone_gift`（里程碑赠送）/ `exchange`（兑换）/ `event_gift`（活动或系统赠送，未来）。

**关键判断：路径不是第四个触发点，而是 CardAcquired 事件的必备属性。** 理由：

- 阴阳师送的SSR和抽出的SSR是同一张卡、走同一个入库流程，只是统计口径不同——如果是两个触发点，入库逻辑要写两遍；
- 但路径必须被**记录为事实**，因为规则需要按路径过滤：原神"任何途径都转化"（白名单=全部），而"第N次抽出给称号（仅抽卡触发）"（白名单={draw}）——两个需求共用同一条获得管道，只是过滤器不同。

### D3 状态面 —— 拿什么计数器做比较

**基础假设（v2 修订）：仓库 = 累计获得次数。** 卡本体永远不被消耗，系统对每张卡只维护一个单调递增的计数 `n`；突破/命座/潜能/星级不是独立状态，而是纯派生 `level = min(n-1, cap)`——满突需7张时，抽到3张即2突，抽到10张仍是6突，除阈值以上的附加资源外无特殊处理。于是"持有数"与"累计获得次数"合二为一，D3 的取值空间随之收敛：

| 取值                | 语义                        | 单调性         | 实证                                                         |
| ----------------- | ------------------------- | ----------- | ---------------------------------------------------------- |
| `none`            | 恒真，不读状态                   | —           | NIKKE金银票、星铁光锥星芒                                            |
| `card_count`      | 该卡累计获得次数 `n`（可按路径切片），只增不减 | ✅ 单调        | 原神"第2~~7次/第8次起"、方舟"2~~6次/7次起"、火影"满5星后"（= n≥6 段）、NIKKE"满星后" |
| `pool_draw_count` | 该池**累计抽数**                | ✅ 单调（按池按周期） | 阴阳师40抽、终末地240抽                                             |

**单调性原则（本框架最重要的隐性约束）**：条件依赖的计数器必须对玩家行为单调不减。在"仓库=计数"假设下这一点自动成立——`n` 只增不减，派生突破等级也单调，"满潜后每次获得"就是分段表的高段，不存在"先分解再获得以重复领取高段奖励"的套利窗口。各游戏实证与该假设一致：原神命星、星铁星魂、NIKKE 备用躯体这类中间材料虽真实存在，但获取后默认应用于突破（模拟系统取"默认突破"行为），突破等级因此等价于 `min(n-1, cap)` 的纯派生。

"是否需要'抽出几次'和'持有几张'两个计数器"的答案随之简化：**不需要——它们是同一个 `n`**。唯一需要区分的是**路径切片**：若机制只认抽卡路径（称号案例），对 `n` 按路径维度切片计数即可，不引入新概念。

### D4 条件形态 —— 怎么比较

| 取值   | 形态             | 实证                                  |
| ---- | -------------- | ----------------------------------- |
| 恒真   | 无条件，触发即产出      | NIKKE每抽1票、星铁光锥                      |
| 单次阈值 | 仅 N==k 时产出一次   | 明日方舟首次获得给1黄票（N=1）                   |
| 分段表  | 按计数器值分段，每段不同产出 | 原神 [2,7]/[8,∞)，方舟 [1,1]/[2,6]/[7,∞) |

**框架最大的收敛点：三者是同一机制的不同参数化。** 恒真是"只有一段且不带计数器"，单次阈值是"只有一个非零段的分段表"。明日方舟就是天然的三段表，原神是两段表。因此：

> **"首次获得""第N次获得""持有≥N后每次获得"不是三种机制，而是分段表这一种机制的三组参数。**

分段表的两条良构约束：① 分段区间**互斥且完备**（覆盖 [1,∞) 不留空洞）；② 统一约定以**获得后的计数**求值（本次获得是第几次），避免边界歧义。

### D5 产出面 —— 给什么，卡去哪

产出物类型的取值空间：通用货币（星辉/黄票/金票/玉石）、卡绑定养成材料（命星/信物/备用躯体）、抽卡券（终末地送十连）、**异池资源**（终末地武库配额）、装饰品（称号/头像框，暂无实装）、**另一张卡**（里程碑送SSR）。

~~转化型 vs 附加型~~（v2 已取消）：初版曾用 `consumeCard` 标记区分"卡被消耗转化"与"卡入库+附加产出"。在"仓库=计数"假设下这个区分消解了——**卡永远入库（n+1），规则只决定附加产出**。原神满命后"不给你角色、只给25星辉"，与"计数+1、突破已封顶、附加25星辉"在系统行为上完全不可区分；前者是表现层话术，后者是系统真相。于是产出面只剩一个问题：给什么。

**产出资源的归属**：背景约束称"资源流单通道、按触发池子归属"。终末地提供了反例——角色池出六星，产出的是**武器池**配额。修正方案：单通道不变，但**归属依据从"触发池"改为"产出项自己声明的资源账目"**；触发池降级为审计标签（记录"这笔资源因何而来"），不再决定入账科目。这样既不破坏单管道汇总，又容纳跨池产出。

里程碑产出"另一张卡"时，该卡**递归进入 CardAcquired 流程**（路径标记 `milestone_gift`），但**不回填里程碑计数器**——这就是阴阳师"不计为召唤获得"的官方语义，也是框架的防递归保险丝。

### D6 挂载面 —— 规则配置写在哪

| 挂载位置        | 适用规则            | 理由                                                 | 实证            |
| ----------- | --------------- | -------------------------------------------------- | ------------- |
| **卡片定义**    | 卡计数分段规则（重复、溢出）  | 价值锚定卡本身（命座/潜能是卡的属性）；原神、方舟实证跨池、跨路径行为一致              | 原神、方舟、NIKKE躯体 |
| **池子定义**    | 返利型规则（每抽发票）与里程碑 | 商业动机锚定池子（促销、保底补偿）；NIKKE金银票若挂卡上，无法实现"同卡在不同池待遇不同"的诉求 | NIKKE、阴阳师、终末地 |
| **稀有度全局默认** | 按稀有度一刀切的规则      | 避免在每张卡上重复配置；卡片级规则可覆盖默认                             | 星铁光锥星芒、火影玉石比率 |
| 池×卡（预留）     | "本池抽此卡额外给X"     | **暂无实装**，但 NIKKE 的设想版说明策划能想到它                      | 预留，不实现        |

**解析优先级**：池×卡规则 > 卡片规则 > 稀有度默认规则。池规则与卡规则不冲突——它们挂在不同触发点上（DrawPerformed/MilestoneReached vs CardAcquired），是平行评估的两个规则集，而非竞争关系。

## 3. 对关键设计问题的直接回答

**Q：「抽到固定给资源」和「满命溢出给资源」是同一机制吗？**  
是。同一分段表的不同参数。（v2 修订后连"转化型/附加型"的分界也不再存在——卡永不消耗，满命溢出只是分段表的高段产出。）真正剩下的机制分界只有一处：**按卡计数 vs 按抽计数**（CardAcquired vs DrawPerformed）。

**Q：溢出规则绑卡还是绑池？有没有反例？**  
卡侧规则绑卡，池侧规则绑池。反例就是校正后的 NIKKE：金银票名义上是"池子的促销返利"，若绑在卡上，"同一张SSR在不同池子给不同票"这个商业诉求就必须在每张卡的配置里枚举所有池子——配置爆炸且违反商业直觉。挂载位置由**价值锚定物**决定：锚定卡的挂卡，锚定池的挂池。

**Q：不同路径获得，溢出行为应有差异吗？哪些游戏有？**  
两种都有实装。原神/方舟：**无差异**（路径无关，规则挂卡）。阴阳师/终末地：**有差异**（赠送不计入召唤/保底统计）。结论：路径必须作为事件事实被记录，规则通过路径白名单声明自己是否区分路径——**差异能力内建于框架，差异与否交给具体规则**。

**Q：首次/第N次/持有≥N，三种机制还是一种？**  
一种。分段表参数化（见 D4），明日方舟的三段表是天然实证。

**Q：需要"抽出几次"与"持有几张"两个计数器吗？什么场景需要前者？**  
需要，且实际要的是一组按路径切片的计数器族。必须用"累计获得/抽出次数"而非"持有数"的场景有两类：① 机制语义绑定"运气/行为"而非"库存"——"第N次抽出某卡给称号"奖励的是抽卡行为本身，若按持有数，兑换来的卡也能领称号，语义就错了；② 卡牌可被消耗的游戏——持有数可逆，用裸持有数做条件会被套利（见 D3 单调性原则）。

**Q：未实装但合理的机制，预留到什么程度？**  
预留**概念位置**，不预留**实现分支**。具体：枚举值留位（装饰品产出类型）、挂载层级留位（池×卡）、优先级留位（池×卡 > 卡 > 默认的解析顺序现在就定义好）；但**不写**任何无实例支撑的求值逻辑（如跨卡条件的表达与求值）。

| 8 | 获得卡  | 全部  | 卡计数          | 分段表（K次后每段追加） | 养成材料                | 卡     | ⚠️ 设计合理，暂无实装（累计K次后每次额外碎片）       |
| 9 | 获得卡  | 全部  | 无            | 恒真           | 异池资源                | 池（或卡） | **终末地**出六星送武库配额                 |

矩阵的可读结论：**触发面 × 挂载面基本决定规则的"家族"**（卡家族=计数分段，池家族=返利/里程碑），计数器与条件形态是家族内部的微调参数。

## 5. 排除清单：明确不支持的组合

| 排除项                          | 排除理由                                                            |
| ---------------------------- | --------------------------------------------------------------- |
| 存在真实决策的处置系统作为触发点（返魂选卡、多路径兑换） | 属"处置"生命周期而非"获得"；玩家有选择（分谁、何时分、换什么），不是产出规则的参数化。框架产出的货币可作为其输入，单向依赖 |
| 跨卡条件（"持有A且获得B时"）             | 无实装；破坏规则的局部性（评估一张卡要读全仓库）；仅在扩展清单留决策记录，结构都不预留                     |
| 预言型条件（"下一次抽卡双倍"）             | 条件只允许读**已发生**的状态；指向未来的条件实质是另一种机制（buff/状态机），不是产出规则               |
| 负产出（获得时扣资源）                  | 违背"额外产出"语义；扣费是价格系统的职责                                           |
| 裸 `holdings`（可逆持有数）作为高价值分段条件 | 违反单调性原则，可被套利；必须用只进不退的养成状态替代                                     |
| DrawPerformed × 持有数/养成状态     | 无因果意义的组合——单次抽卡行为与某张卡的库存状态无关；无实装                                 |
| 池×卡挂载（当前实现）                  | 无实装需求；仅在解析优先级中留位                                                |
| 分段表区间重叠或留空洞                  | 良构约束，配置校验时拒绝（这不是"排除组合"，是非法配置）                                   |

**可折叠判据（v2 新增）**：上表第1条的另一面——若分解是**强制且单一路径**的（溢出物除固定比率兑换外无任何其他用途、无时机选择、无路径选择），则它不是决策而是管道，建模时应**折叠为直接产出**：火影满5星后的S碎片 ≡ 直接获得玉石×20；明日方舟满潜后的6星信物 ≡ 直接获得黄票×15。模拟系统按折叠后的形态配置规则即可，手动点击兑换只是表现层包装。阴阳师返魂不满足判据（分谁、留不留二号机是真实决策），仍留在框架外。

## 6. 统一规则模型

概念层面的规则模型（非数据结构定义，是配置的最小完备描述）：

```
Rule（规则）
├─ host        挂载宿主：卡片 / 池子 / 稀有度默认   [池×卡为预留层级]
├─ trigger     触发事件：CardAcquired / DrawPerformed / MilestoneReached
├─ pathFilter  路径白名单：{draw, milestone_gift, exchange, event_gift} 的子集，默认全部
│              （DrawPerformed 与 MilestoneReached 类规则无此槽位）
├─ counter     条件计数器：none / cardCount（可按路径切片）/ poolDrawCount
├─ bands[]     分段表：若干 [min, max] → outputs，区间互斥且完备覆盖 [1, ∞)
│              （恒真 = 无计数器的单段；单次阈值 = 只有一个非零段）
└─ outputs[]   每段的产出清单：{resource 资源账目, amount 数量}
               （卡永远入库 n+1，不存在"消耗卡"分支——v2 修订）
```

**用同一模型重述全部案例**（表达力证明）：

- **原神5星角色**：host=稀有度默认(5星角色)，trigger=CardAcquired，pathFilter=全部，counter=cardCount，bands=[1,1]→{空}（突破派生自动点亮命座）+ [2,7]→{星辉×10} + [8,∞)→{星辉×25}
- **明日方舟6星**：同上骨架，bands=[1,1]→{黄票×1} + [2,6]→{黄票×10} + [7,∞)→{黄票×15}（满潜信物按可折叠判据折叠为直接产出）
- **星铁光锥**：counter=none，bands=单段→{星芒×40}
- **NIKKE金银票**：host=池，trigger=DrawPerformed，counter=none，单段→{金票×1}
- **NIKKE躯体标签**：host=卡，counter=cardCount，bands=[满Core段,∞)→{躯体标签×6000}（溢出躯体折叠为直接产出）
- **阴阳师40抽**：host=池，trigger=MilestoneReached(40)，单段→{随机SSR×1}（产出物以 milestone_gift 路径递归进入获得流程，不回填池抽数）
- **终末地武库配额**：host=池，trigger=CardAcquired(稀有度=六星)，counter=none，单段→{武库配额×2000}（resource 声明武器池账目，跨池归属）
- **第N次抽出给称号（未实装）**：host=卡，pathFilter={draw}，counter=cardCount 的 draw 切片，bands=[N,N]→{称号×1}
- **累计K次后每次额外碎片（未实装）**：host=卡，bands=[1,K]→{空} + [K+1,∞)→{碎片×x}

向后兼容天然成立：**规则集为空 = 系统行为与现状完全一致**；计数器在首张配置规则出现时惰性建立。

## 7. 挂载策略

1. **卡计数分段规则挂卡片定义**（或稀有度默认 + 卡片覆盖）：价值锚定卡，路径无关、跨池一致（原神/方舟实证）。
2. **返利型与里程碑规则挂池子定义**：商业动机锚定池，生命周期随池子开关（NIKKE/阴阳师/终末地实证）。
3. **稀有度默认做兜底**：同稀有度同规则的游戏（星铁、火影）不必逐卡配置；卡片级配置覆盖默认。
4. **两个规则集平行评估**：池规则集在 DrawPerformed/MilestoneReached 求值，卡规则集在 CardAcquired 求值，互不竞争、可叠加生效（NIKKE 一抽同时给票和躯体，正是两个规则集各自命中的结果）。
5. **解析优先级现在就固定**：池×卡 > 卡 > 稀有度默认——即使池×卡暂不实现，优先级语义先占住，未来引入时不产生二义性。

## 8. 执行流：三个触发点在核心循环中的位置

概念层面的扩展后循环（保底逻辑原位保留，与本框架正交——保底决定"出哪张卡"，本框架决定"出卡后附带什么资源"）：

```
① 选择池子 → 支付资源
② 【DrawPerformed】评估该池的返利规则集（如：金票+1）——按"次"结算，无状态
③ 随机抽出一张卡；该池 poolDrawCount +1
④ 【MilestoneReached】检查该池里程碑规则（如：第40抽 → 赠送随机SSR）
      └─ 赠送的卡以 path=milestone_gift 进入步骤⑤（不回填 poolDrawCount，防递归）
⑤ 【CardAcquired】卡牌获得事件（主产物与赠送产物走同一管道）
      a. 事件携带：卡ID、稀有度、路径、来源池
      b. 更新该卡计数 n（按路径切片 +1）；突破等级随派生公式 min(n-1, cap) 自动刷新
      c. 规则匹配：按优先级（池×卡 > 卡 > 稀有度默认）取规则，路径白名单过滤
      d. 以获得后计数定位分段 → 结算该段产出
      e. 卡永远入库（仓库=计数，无"消耗"分支）
      f. 产出按各自声明的资源账目汇入资源流（单通道；来源池作为审计标签随行）
⑥ 检查保底（原有逻辑，不受规则影响）→ 回到①
```

三条执行纪律：

- **顺序即真相**：计数器先更新、规则后求值——"第N次"的 N 永远包含本次，全系统只有一种解释。
- **递归有保险丝**：里程碑产物的获得不再反哺任何里程碑计数器（阴阳师"不计为召唤获得"）。
- **资源流不改道**：产出物无论类型（货币/券/异池配额/卡），都从同一条资源管道入账，归属科目由产出项自己声明，来源池只做审计标签。

## 10. 设计决策摘要（ADR）

**ADR-1 用单一分段表统一阈值语义。** 首次/第N次/持有≥N 不作独立机制，全部为分段表参数。代价：配置略抽象（策划要理解"段"而非"档位开关"）；收益：机制数量收敛，明日方舟三段表、原神两段表直接落地。

**ADR-2 挂载由价值锚定物决定。** 计数分段挂卡、返利型挂池、稀有度默认兜底；池×卡预留不实现。代价：同一物理货币可能在卡、池两处各有规则（NIKKE 恰是如此）；收益：每处配置都符合其商业直觉。

**ADR-3 路径是事件事实，不是触发点。** 所有获得走同一管道，路径白名单做过滤。代价：事件负载多一个字段；收益：入库逻辑单一，"赠送不计入统计"只是过滤器配置。

**ADR-4 条件计数器必须单调。** 拒绝裸持有数做高价值条件，用累计计数或只进不退的养成状态。代价：火影式"满5星"需要养成系统保证星级只进不退（各游戏本就如此）；收益：结构性消除套利。

**ADR-5 处置系统与产出规则单向依赖；强制单一路径的分解折叠为直接产出。** 存在真实决策的处置（返魂选卡、多路径兑换）留在框架外，与本框架单向依赖（本框架产出 → 彼系统输入）；而强制单一路径的溢出兑换（火影满星碎片、方舟满潜信物）按可折叠判据折叠，建模为获得时直接产出。代价：折叠后丢失"中间道具库存"的可见性（模拟系统不需要）；收益：规则配置无需为表现层包装建模。

**ADR-6 仓库 = 累计获得次数，卡本体永不消耗。** 系统对每张卡只维护单调计数 n，突破/命座/星级为派生 min(n-1, cap)。代价：不覆盖"销毁整卡本体"类机制（阴阳师返魂二号机）——已显式排除在框架边界外；收益：取消 consumeCard 维度，"持有数"与"获得次数"合一，单调性原则自动成立，规则模型少一个槽位，执行流少一个分支。
