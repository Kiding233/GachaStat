## 一、定位：这个工具是什么

**可复现的抽卡模拟实验台。** 用户是"研究员"，工作对象是"实验"而非"数据文件"。

| 用户心智 | 对应 | 交互特征 |
|---------|------|---------|
| "我设计什么实验" | 配置 | 编辑型 |
| "我做实验拿证据" | 模拟 | 生成型（有耗时） |
| "证据意味着什么" | 分析 | 即时型（读数据） |
| "进一步的实验" | 派生配置 | 迭代（回路） |

推论：配置与结果（数据集）是两个第一等公民。配置是"可复现实验"的前提（黄金标准：同配置同种子行为等价），结果是分析对象。

## 二、对象模型（用户"拿着"什么）

**工作区 = 文件夹树。** 资产树不是内存假数据，而是基于实际文件夹解析的视图：每个条目是独立文件，文件夹是容器。左栏命名为「工作区」。

| 对象 | 类型 | 定义 | 心智 | 从属 |
|------|------|------|------|------|
| **配置** | file | 卡池/保底/策略/目标/资源的定义。真相源是 config.toml 文本 | "我的实验设计" | 工作区根 / 用户文件夹 / 配置与数据组 |
| **数据集** | file | 一次模拟的结果（meta + result） | "我的证据" | **严格从属其来源配置**（可复现） |
| **派生配置** | file | 从分析结果生成的配置变体（活例子：最差影响的"后续池子"） | "改进的实验" | 从属其来源分析/配置 |
| **统计分析条目** | file | 数据集下的方法块集合（GDR / 分布 / 过程 / 脆弱性 / 最差） | "证据解读" | 从属数据集（幽灵创建，可多个） |
| **搜索任务** | file | 方案搜索 / 敏感性分析的配置（模式 + 参数 + 目标 + 引用配置） | "邻域探索" | 工作区根（独立一级） |
| **配置与数据组** | **folder** | 文件夹容器，挂搜索生成的全部配置 + 数据集 + 搜索结果 | "搜索产物" | 从属搜索任务 |
| **搜索结果** | file | 搜索摘要（最优策略 / 分布结论） | "探索结论" | 从属配置与数据组 |
| **对比分析任务** | file | 多数据集对照（纳入 / 排除 + 运行 + 矩阵） | "跨数据集结论" | 工作区根（**多实例**，可对同一数据集建多个） |
| **用户文件夹** | **folder** | 手动创建的整理容器，可放任意条目（含配置及其下属） | "归置" | 工作区根 / 任意层级 |

**规则：**
- 根节点的语义是"配置"（有配置-数据-分析三层结构）；纯分析对象（统计分析 / 对比分析 / 搜索结果）不设根节点语义。
- 任意数据集产生（手动模拟、搜索生成）都挂一个幽灵「统计分析」入口：hover 数据集显示灰色幽灵条目，点击才真实创建，避免条目爆炸。
- 任何条目可序列化为独立文件（config→TOML，其余→JSON）；「保存工作区」导出为真实目录结构。

## 三、核心回路（用户"做什么"）

```
  配置 ──模拟──▶ 数据集 ──分析──▶ 结论
   ▲                              │
   └──────── 派生配置 ────────────┘
     （分析结果 → 配置变体 → 继续迭代）
```

**这个回路是工具的工作本质。** 现有功能都是回路上的环节：

| 功能 | 在回路中的位置 | 代码事实 |
|------|---------------|---------|
| 配置面板 | 回路起点（编辑） | config_panel / config_toml |
| 批量模拟 | 配置 → 数据（收敛为「任务管理器」的模拟任务） | batch_simulator run_batch_parallel |
| 统计分析 / 过程分析 | 数据集的分析操作（统计分析条目） | analysis_panel / process_analysis_panel |
| 脆弱性分析 | 数据集的分析操作（**纯分析，不跑新模拟**） | retreat_panel 调 `compute_vulnerability_analysis(simulation_results)` |
| **最差影响** | **回路复合环节**：输入已有结果 + 用户构建"后续池子"配置 → 跑新模拟 → 分析新池子数分布 | worst_impact_panel 组装 `custom_pool_config`，`WorstImpactAnalyzer.analyze(num_simulations)` |
| 方案搜索 | 搜索任务（给定配置 + 起始状态 + 目标：最少资源 / 最多目标卡 / Pareto / 退路方向） | plan_search_panel / retreat_search |
| 敏感性分析 | 搜索任务（配置邻域探索：单参数变化范围 → GDR 折线） | main_window 占位 |
| 比较分析 | 跨数据集操作（对比分析任务） | comparison_analysis_panel |

### 3.1 关键推论：分析 → 派生配置 是一等能力
最差影响已经在做"分析时构建配置再跑模拟"，但它是**面板内临时配置、不可保存复用**。架构应把"分析 → 派生配置 → 继续迭代"提升为一等能力（可保存为配置条目、带来源标注、可继续模拟/分析/搜索）。

## 四、信息架构（导航形态）

**主导航按对象（资产）组织 + 上下文操作，不按动作分 tab。**

### 4.1 工作区（左侧树，文件夹/文件两层模型）

```
工作区
├─ 周年庆(config 文件) ─ 模拟01(dataset 文件) ─ 统计分析(analysis 文件)
│                     ├ 模拟02 ─ 统计分析
│                     └ 变体·退守策略(derived 文件)
├─ 武器特选(config) ─ 模拟03 ─ 统计分析
├─ 📁 配置与数据组(group 文件夹)      ← 搜索运行后生成
│    ├─ 搜索配置A(config) ─ 模拟A1 ─ 统计分析
│    ├─ 搜索配置B(config) ─ 模拟B1
│    └─ 搜索结果(search_result 文件)
├─ 对比任务1(compare_task 文件)      ← 工作区根，可任意多个
└─ 📁 我的整理（用户文件夹）
```

- **folder（文件夹）**：group / 用户文件夹。树行用 📁 图标 + 浅灰底 + 加粗（「文件夹脸」）。
- **file（文件）**：config / dataset / analysis / search / search_result / compare_task。树行用类型色点 + 文件名（「文件脸」）。
- **UI 缓解「有子条目的条目像文件夹」**：即使 config/dataset 有展开三角，folder/file 图标语言一眼区分。
- **状态**：running 转圈徽标；locked（group 运行中）行 opacity 0.55 + 灰「锁定」徽标，锁定穿透后代（工作区顶部只读横幅）。

### 4.2 选中驱动的工作区（右侧）
| 选中对象 | 工作区可用操作 |
|---------|---------------|
| 配置 / 派生配置 | **编辑**（块式，仅此一项；模拟/搜索收敛到任务管理器） |
| 数据集（单选或多选） | **数据集信息页**（元信息：来源配置 / 种子 / N / 均值 + 「创建统计分析」「创建对比分析」入口；多选条目增多） |
| 统计分析条目 | 分析方法块（GDR / 分布 / 过程 / 脆弱性 / 最差，可自由添加移除） |
| 搜索任务 | 左文本右块（与一般配置一致，块集合为搜索专用）+ 派发搜索任务 |
| 配置与数据组 / 用户文件夹 | 子条目只读列表（运行中锁定横幅） |
| 搜索结果 | 搜索摘要 |
| 对比分析任务 | 纳入数据集（跨配置）+ 排除数据集 + 运行 + 对照矩阵 |
| （工具栏「任务管理」） | 任务队列 + 资源监控页 |

**核心原则：点击什么右侧就显示什么本身，不直接跳到它的分析。**

### 4.3 跨对象操作
- **运行 = 任务管理器**：生成型操作（模拟 / 搜索 / 敏感性）统一收敛为「创建模拟任务」（label 随选中资产联动：配置→创建模拟任务、搜索→创建搜索任务、数据集→重跑模拟）→ 任务队列（排队/进度/取消/结果跳转）+ 资源监控（CPU/内存/worker）。
- **统计分析的幽灵条目**：hover 数据集显示灰色幽灵「统计分析」，点击真实创建（不自动创建，避免条目爆炸）。
- **搜索**：独立一级资产（工作区根）。运行搜索 → 其下生成「配置与数据组」文件夹（运行中灰色可查看、锁定操作，完成后解锁）→ 搜索完成自动生成「搜索结果」条目挂组下 → 组内配置/数据集可继续分析/重跑。
- **对比分析**：工作区根多实例条目。悬停任务节点 → 高亮其纳入的数据集树行。

### 4.4 流程引导套件（交互层包装回路）
从配置出发，"我要看最差影响" → 系统自动补足中间步骤（该配置的标准模拟 → 最差分析），用户感知为一步。**灵活性与连贯性分层**：
- 数据模型层：任何配置可做任何分析（统一、灵活）
- 交互引导层：常用路径包装为连贯一步（引导）

## 五、交互模式（有限几种，内部统一）

| 模式 | 覆盖 | 统一骨架 |
|------|------|---------|
| **编辑型** | 配置、搜索任务 | 块式编辑器（左文本 + 右块，结构化表单 + 防抖自动保存）+ 定位高亮 |
| **生成型** | 模拟、搜索 | **任务管理器**：任务队列（参数 + 运行 + 进度）+ 资源监控 |
| **即时分析型** | 数据集分析 | 方法块：方法选择 + 参数 + 即时结果 |
| **比较型** | 跨数据集 | 对比任务：纳入/排除选择 + 对照矩阵 + 显著性标记 |

跨类不强求一致，**类内部高度统一**（统一骨架语言）。

## 六、配置编辑器设计（实体中心渲染器 + 自由分页 + 模板）

- **结构**：左配置文本（TOML 真相源，可编辑）+ 右渲染的配置块，双向同步（parse / serialize）。**搜索任务复用同一外壳**，仅块集合不同（搜索目标 / 策略 / 扫描参数 / 引用配置），文本模型扩展 `[[search]]`。
- **实体中心**：以"实体"为聚合单元（一个 Banner 块内含池子 / 保底 / 分布 / 生命周期）。
- **可自由分页**：页是用户自由组织的容器（默认「全局配置」页 + 各 Banner 页，可新建 / 命名 / 放块）。
- **块类型（基于 config.toml 穷举）与添加块 UI 层级**：实体块 7 种（可复制）、全局单例 2 种（不可复制）、嵌套子块（块内操作添加）。
- **配置页操作收敛**：配置页仅「编辑」；生成模拟 / 搜索 / 敏感性作为任务从工具栏派发。
- **插件移出 config.toml**：移入独立软件配置文件。
- **顺序无关解析**：引用用显式 ID + 阶段化加载（config_toml 已支持）。

## 七、视觉方向（约束，已定）

- **严肃、专业、朴素、不华丽**；统计工具定位
- **直角**（不圆角）；**蓝白灰**为主
- 彩色只做语义点缀：蓝（操作/图表主系列）、绿（成功/达标）、红（危险/劣势）、黄（警告）
- 结构感：色块层次 + 轻阴影，不用硬边框
- **无内容切换动画**；Tab 切换反馈在 Tab 行本身
- 顶部工具栏（品牌 + 菜单 + 新建按钮 + 任务按钮）+ 内容区 + 底部状态栏
- **文件夹脸 vs 文件脸**：folder 用 📁 + 浅灰底 + 加粗；file 用类型色点 + 文件名（缓解"有子条目像文件夹"）
- 信息密度优先；中文字体 Microsoft YaHei / PingFang SC；字号 12-14px

## 九、已裁决 / 待细化

### 已裁决（2026-08-07 v2）
1. ✅ 数据集严格从属某个配置（无独立共享数据集库）
2. ✅ 配置块式编辑器先做 demo 验证效果，再定完整实现
3. ✅ 流程引导形态 = 侧栏一步一打勾的指引
4. ✅ 探索结果持久化：搜索任务 / 对比任务作为资产存进树
5. ✅ 纯工作区树导航，不设独立「探索」区
6. ✅ **工作区 = 文件夹树**：group 是文件夹（可挂配置/数据集/搜索结果）；条目是独立文件（可序列化）
7. ✅ **运行 = 任务管理器**：工具栏「创建模拟任务」（联动 label）+「任务管理」（任务队列 + 资源监控）
8. ✅ **对比分析任务**：工作区根多实例（非全局单例、非根节点语义），可对同一数据集建多个；悬停高亮纳入数据集
9. ✅ **统计分析幽灵条目**：hover 数据集显示灰色幽灵，点击创建（不自动创建）
10. ✅ **数据集信息页**：单/多选共用，多选条目增多，含「创建统计分析」「创建对比分析」入口
11. ✅ **搜索配置 UI = 一般配置一致**（左文本右块，块集合不同，运行方式不同）
12. ✅ **配置页仅保留编辑**（移除 edit/sim/search/sens 切换）

### 待细化
- **派生配置的来源标注**：从哪个分析派生、哪些参数带入、如何避免配置库膨胀
- **任务管理器的资源监控数据源**：CPU/内存经 js_api 从 Python（psutil）获取，阶段 1b 定接口
- **幽灵条目之外的快捷入口**：数据集信息页为完整入口，幽灵条目为树上便捷入口，两层是否并存
