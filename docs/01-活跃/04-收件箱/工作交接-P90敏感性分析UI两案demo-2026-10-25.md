## 一、P90 是什么，demo 为什么存在

**计划文件**：`docs/01-活跃/panels/敏感性分析/P90 敏感性分析：参数扫描与结论稳健性.md`
**同目录**：`00-档案.md`、`01-理论.md`

P90 做的是「某个参数变了，我关心的量怎么变，结论到哪个点翻转」。它与现有 10 个分析项的根本差别有三个，这也是 demos 存在的理由：

- **要填规格，不是点一下**。现有分析项是「勾选 → 运行 → 出一张图」，没有"扫描区间"这种输入。
- **一种方法内部分出成本悬殊的两条路**。分析口径类（GDR 阈值、权重、VaR α）改动只需在已有样本上重算，毫秒级；策略 / 池子 / 保底类必须重新模拟，一次几秒到几分钟。这个分野在 UI 上必须可见。
- **一次运行产出 N 个子配置 + N 个数据集**，而不是一个结果。所以有"结果组"这个概念。

**当前阶段**：设计阶段。实施依赖 P86（`service/analysis/` 分析服务层抽象）与 P87（`service/workspace/` 派发编排），两者均未落成。P90 自带一个**无依赖的阶段 0**（ChartSpec 扩展、`core/curve_analysis.py` 提取），可独立提前做。

## 四、用户 2026-10-12 的九条意见与处置状态

这是交接的核心。按「已核实的结论」而非「用户的措辞」记。

### 1. 枚举选项写死（成立，未改）

demo 里 `策略类型` 写死 4 个、`保底类型` 写死 6 个、`策略参数` 写死 `['count','pity_threshold_pct']`。用户原话「我要是添加更多策略你要一直这样堆下去吗」。

**注意堆的不是数据，是结构**：现在每加一个策略要在四处各改一行（类型选项、参数选项、参数形态映射、单位）。声明驱动的话一处都不用改。

### 2. 参数表单不该在右栏（成立，未改，**这是本轮主战场**）

用户原话：

> 按之前说的运行等于新建组来说，参数不应该在右侧填，否则视觉上不成立。

**他的理由是语义的，比字面推理更硬**：「运行 = 新建一组」意味着右栏是**一条按时间追加的产出流**（#1、#2、#3…），每格都是"已经跑出来的东西"。参数描述的是"下一次要跑成什么"。把参数放进产出流，同一容器就同时承载了过去与将来，视觉上立不住。

**掌权的是 §5.8，不是 §5.5。** 我起初只引 §5.5（管**发起**入口），漏了 §5.8（管**参数**位置）。§5.8 原文：「参数放在各自的结果块内，不放左栏。理由：多选时每个方法各有自己的参数集，左栏只有一列，只能显示其中一份。」

**那条理由站不住，有两条独立论据**：

1. **对 P90 不适用**：敏感性分析只有一个方法，不存在「多选时每方法各有参数集」。
2. **对全体方法也不成立**（另一位 agent 独立查到，我给不出）：真 GUI 用「每项可展开、默认收起」解掉了同一个约束。`AnalysisItemWidget` 的 `_config_widget` 默认 `setVisible(False)`，点 ▶ 才展开，所以左栏一列能装 N 套参数。**§5.8 当时的取舍不是唯一解。**

**旁证**：`analysis_panel.py` 是 `gui/` 下唯一有「左栏列表 ＋ 右栏结果」结构的面板，它的参数就在左栏每一项的展开区里，运行按钮在左栏底部（`:1975`）。见第六节。

**方向**：参数与运行按钮回左栏，§5.8 与 §5.5 相应收窄。**两份交接结论一致，但用户还没正式裁，也没写回文档**，动手前确认一次。

### 3. 「软保底参数」命名不对（成立，未改）

策略那项是「策略类型 / 策略参数」两级，保底却锁死成「软保底参数」，且第一级选择器标签写「对象」。应统一为「保底参数」，第一级选**保底对象**（哪个 `PityDef`），第二级选**参数**（该 btype 声明里的哪个）。

### 4. 形态定错了层（**最根本的一条，未改**）

demo 里把形态写成了维度的固有属性：

```js
{ k: '保底类型', form: '枚举', ... }
{ k: '策略参数', form: '数值栅格', ... }
```

实际形态由**选中参数的类型**决定。查注册表：

| 策略 | 参数 | 类型 | 该给的形态 |
|---|---|---|---|
| `fixed_count` | `count` | `IntParam` | 数值栅格 |
| `pity_reserve` | `pity_threshold_pct` | `FloatParam` | 数值栅格 |
| `stop_on_target` | `stop_on_featured` / `stop_on_any_target` | `BoolParam` | 勾选 |
| `target_hunting` | `target_pool_ids` | `StringListParam` | 列表 |
| `pool_quota` | `pool_quotas` | `PoolIntMapParam` | 映射表 |
| `smart` / `no_draw` | 无 | | **没有可扫参数** |

八个策略里 `draw_target` 是 `internal=True`，其余七个中**只有两个组合是数值型**。

保底侧同理，`BEHAVIOR_REGISTRY[k]['params'][p]['type']` 直接给了 `int`/`float`/`str`/`bool`/`deltas`。

**这条解释了用户说的「表达式列表逻辑不大对」**：表达式列表不该是一个维度，它是 `deltas` 这类复合参数的**形态**。选到 `soft_step` 时就该出现一条可编辑分段表，而不是先选「表达式列表」再填。

### 5. 结果组条应永远是右栏首行（成立，未改）

现在两案都是「规格块 / 发起块 → 组条 → 结果」，组条被夹在中间。它其实是右栏的视图切换器，该紧跟锚点栏。

### 6. 初始资源（**用户自己当场更正，已撤回**）

先说「只能属于单参数」，随即补：「也不大对，如果想比较多种初始资源组合也是合理的，只是意义有变化」。记法是：单参数扫描问「数量多寡的影响」，多组合比较问「配置选型」，两者是不同东西，前者数值栅格、后者列表。

### 7. GUI 左栏要用 PyQt6 惯例（成立，未改）

用户原话「gui的左栏还是应该与大部分对齐，用pyqt6自己的组件做，你看看惯例是什么样的」。惯例见第六节。现行 `gui.html` 左栏是「假树（带 `▼` 折叠头的 div 清单）+ 下方独立规格块」，**PyQt6 里两样都没有先例**。

### 8. 排查 GUI 案是否有同类问题（已做）

两案共用同一份 `DOMAINS`（逐字段对比只差换行），所以第四节的形态问题、第 1 条的硬编码、第 3 条的命名**三案同病**。GUI 案另有第七节的第 1 条不适用（不是 Vue，没有 in-DOM 模板陷阱）。

### 9. 折叠摘要（用户说「可能更好，但也说不确定了」）

我没实施。判断：改成"参数回左栏"之后，规格是选中才展开的，不占地方，右栏也不会被挤，折叠问题会被结构本身解决。**没跟用户确认过这个判断。**

## 五、声明驱动：真源在哪（2026-10-25 实测）

### 策略

### 一个命名分叉，别踩

`PityDef` 是 26 字段的 dataclass，其中软保底语法糖字段叫 **`soft_start` / `soft_end` / `soft_increment` / `soft_deltas`**（`core/config_store.py`）。

## 七、必须保留的两处缺陷修复（重写时最容易丢）

两处都是**静默失败**，不报任何错，只靠肉眼或断言才能发现。

### 1. in-DOM 模板的自闭合陷阱（乙案）

`webui.html` 是把 `#app` 的 innerHTML 当模板（in-DOM template），浏览器**先于 Vue** 解析它。HTML 规范里自定义元素不接受自闭合语法，`<el-input-number ... />` 被当成**开标签**，后续兄弟节点全嵌进去；而 `el-input-number` 不渲染默认插槽，嵌进去的整个消失。

症状：「区间」行只画得出一个输入框，第二个连同 `→` 与单位一起被吞。

修法：自定义元素一律写显式闭合。已在 `1bdd050` 修掉 8 处。**`layout_demo/index.html` 一直是显式闭合的，照抄它的写法**。Vue SFC 或 `template:` 字符串没有这个问题，只有 in-DOM 模板有。

### 2. 行③柱子的横坐标（`chart3.js`，两案共用）

柱子必须坐在自己那个 θ 上，与行②的采样点、底部刻度同一根竖线。早先按 `plotW/n` 等分铺开，5 个点时整排右移半格（刻度在 62/262/462/662/862，柱子在 86/246/406/566/726）；11 点时误差小看不出来，5 点时露馅。

修法：`x = X(p.th) - bwid/2`，柱宽 `Math.max(8, Math.min(stepX*0.55, 64))`。

**另**：行① 的判据线 τ 要按**响应值轴**定位（`L + (tau - sBot)/(sTop - sBot) * plotW`），不是按 θ。我一度把分数当 θ 传给 `X()`，算出 x = −938 画到画布外。
