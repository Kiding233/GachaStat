# 影响 GUI 路径的问题：独立排查报告

调查日期：2026-09-30。调查者：独立只读子 agent（无前置会话上下文）。
调查范围：`gacha_simulator/gui/` 及其对 `service/batch_simulator.py` 的调用。
证据纪律：每条给出「文件:行号」；实测部分附原始输出；推断部分标注「待确认」。

---

## 一、高危（GUI 独有）

### 1. 模拟完成后的主线程后处理没有任何异常兜底，一旦抛错整个 GUI 进程静默消失（实测确认）

- `gacha_simulator/gui/main_window.py:342-508`（`on_simulation_finished`）、`gacha_simulator/gui/gacha_panel.py:339-370`（`on_simulation_finished` + `self.simulation_finished.emit`）
- 这两个方法都是通过 Qt 信号调用的槽。方法体内要构造 `ComparabilityFingerprint`、调 `compute_config_hash`、构造 `StoredDataset`、写 `result_store.add`、再扇出到 5 个面板。**全程一个 try/except 都没有**。
- PyQt6 的行为：从 C++ 事件循环调进 Python 槽的异常会走 `qFatal()` 直接 abort，不弹窗、不打印、不留状态。本机实测（PyQt6 6.11.0 / Qt 6.11.0 / Python 3.12.5，用 `QTimer.singleShot` 回调抛 `RuntimeError` 复现，与槽调用同一条派发路径）：

  ```
  returncode = 3221226505      # 0xC0000409 STATUS_STACK_BUFFER_OVERRUN，即 abort
  stdout = ''
  stderr = ''                  # 连 traceback 都没输出
  ```

  对照组（同一脚本不抛异常）：`rc = 0`。
- **为什么是问题**：一次已跑完、可能花了几分钟的主模拟，会在最后 1 秒的落库阶段让整个程序无声退出，用户看到的是「窗口不见了」，且结果没有进 `ResultStore`。
- **影响面**：只在 GUI。WebUI 的等价代码（`webui/api.py:269-360`）整个函数体被 try/except 包住并把错误推给前端；CLI 是普通脚本，异常只打印 traceback。项目里没有自定义 `sys.excepthook`，也没有 `qInstallMessageHandler`，所以没有兜底网。
- 附带证据：`benchmarks/perf/adapters/gui_qt.py:107-110` 记录了「GUI 的完成判据只能靠副作用轮询、不能靠信号」，`_await_completion` 专门为「线程结束但副作用没出现」写了错误分支（`gui_qt.py:415-437`），说明这条链路的脆弱性已被间接观察到。

### 2. 模拟运行期间配置仍可编辑，完成回调读的是「此刻」的 store，导致落库数据集的指纹与实际运行不一致

- 读侧：`main_window.py:387-390`（无 target_specs 时从 `self._store.target_cards` 兜底）、`:397-400`（`pool_types` 取自 `self._store.pools`）、`:428-429`、`:432`、`:442`（`pool_ids`）、`:449-456`（`compute_config_hash(self._store.banner.banners, ...)`）
- 写侧（运行期间仍会触发）：`main_window.py:155-156` 的「重置为默认配置」菜单项直连 `_load_default_config`，其 `load_toml` 会先 `store.clear()`（`core/config_toml.py:58-61`）；`gui/config_panel.py:6013-6027` 的 500ms 去抖预览，其 `_do_update_preview` 调 `get_config()`，而 `get_config()` 第一行是 `self.apply_to_store()`（`config_panel.py:6240-6242`），`apply_to_store` 会整段重建 `banner.banners`、`target_cards`、`card_defs`、`initial_resources`、`stop_condition`。
- **为什么是问题**：`GachaPanel.start_simulation` 只禁用了自己那颗按钮（`gacha_panel.py:317`），没有禁用 Tab、没有 `_simulation_running` 标志（已全文搜过，不存在）。用户在这段时间里改配置或点「重置为默认配置」，落库的 `config_hash` / `target_specs` / `pool_ids` / `pool_types` 就会指向一份**没有用来跑这次模拟**的配置。在比较分析面板里，这直接污染「可比性指纹」判据（`core/result_store.py:334-350` 的 `compare_fingerprints` 以这些字段判定 `same` / `different`）。
- **待确认（较窄）**：`gacha_panel.py:295` 的 `apply_to_store()` 与 `:49` 的 `from_config_store()` 之间存在竞态窗口。未构造出稳定复现。
- **影响面**：只在 GUI。WebUI 在 worker 线程开头用前端文本重新解析成独立 store（`webui/api.py:274`），CLI 从磁盘文件加载，两者持有的是快照。

### 3. 未知策略键在 GUI 被静默替换成 smart，CLI 则报错

- `gui/config_panel.py:7495`：`display_name = _sr[store.strategy_key].display_name if store.strategy_key in _sr else '按需追卡'`。`'按需追卡'` 恰好是 `smart` 的显示名（实测：`'smart' -> '按需追卡'`）。
- 紧接着 `config_panel.py:7197-7198`：`store.strategy_key = strategy_type_to_key(display_name)`，即反向查显示名（`core/strategy.py:394-403`），于是 `'按需追卡'` 被写回成 `'smart'`。
- **为什么是问题**：`apply_to_store` 是每次点「开始模拟」、每次 500ms 预览、每次导出都会调的路径。一条键不存在的策略（如 config.toml 写的是 `plugin/xxx` 而插件文件已删）会在用户毫无察觉下被换成 smart 并跑出看起来正常的结果。旁边的 `_invalid_state` 分支（`config_panel.py:7474-7493`）是有 `QMessageBox` 警告的，唯独「键完全不在注册表里」这条没有。
- **对照**：`core/strategy.py:358-360` 对未知键抛 `ValueError`。CLI 原样传下去，最终以空结果 + `np.percentile` 的 `IndexError` 大声失败。

### 4. `BatchResult.warnings` 在 GUI 上完全不可达

- `gui/gacha_panel.py:82-92` 不接 `warnings`，`:125-175` 组装的 result_bundle 里也没有这个键；`main_window.py:342-508` 从头到尾没读过它。
- 核心层在这个槽里塞的是真东西：`service/batch_simulator.py:900-907` 的「路径降级」告警、`service/gacha_service.py:618`、`:625` 的「零进度 / 迭代预算耗尽」告警。
- **为什么是问题**：这三条告警的存在理由写在注释里就是「使读的人能区分路径降级与剖析器坏了」，而唯一会被路径降级影响的正是 GUI 与 WebUI 的默认路径（`batch_simulator.py:703-705` 原话：「兜底路径正是 MPPool 异常时 GUI / WebUI 主模拟实际走的路径」）。
- **影响面**：GUI + WebUI + CLI 都没有消费者（全仓 grep `.warnings` 只命中 `batch_simulator.py` 自身与 `gacha_service.py`），属「通道建好了但三边都没接」。GUI 侧最可惜，它有日志框（`gacha_panel.py:249-255`）可以显示。

### 5. 并行路径下失败计数永不累加，`n_failed` 对 GUI 恒为 0

- `service/batch_simulator.py:848-854`：

  ```python
  if on_result is not None:
      if compact is not None:
          on_result(compact)
      else:
          n_failed += 1
  elif compact is not None:
      results.append(compact)
  ```

- GUI 设了 `env.return_compact = False`（`gacha_panel.py:66`），worker 返回三元组第一分量恒为 `None`（`batch_simulator.py:514-516`），且 GUI 不传 `on_result`（这一点还被 `tests/benchmarks/test_adapter_contract_gui_qt.py:113-118` 对源码文本断言着）。两条合起来：既不进 `results`、也不进 `n_failed`，于是 `:875` 的 `logging.warning("%s/%s simulations failed")` 在 GUI 路径上**结构性地不可能触发**。
- **影响面**：GUI + WebUI（`webui/api.py:283` 同样设 `return_compact = False`）。**CLI 不设该字段，因此幸免**。这是三条入口行为不一致的一处，且沉默的一方是用户最多的两条入口。

## 二、中危

**6. `SimulationThread` 用 `pyqtSignal(object)` 覆盖了 `QThread.finished`**（`gacha_panel.py:25`）。实测：当前不会重复触发、也不会传 None。但 `QThread.finished` 被遮蔽后，任何靠 Qt 原生 finished 做清理的写法（如 `thread.finished.connect(thread.deleteLater)`）都会静默失效。判定：潜在风险，非现存缺陷。

**7. 取消/重入路径用 `QThread.terminate()`，而线程正在跑 multiprocessing 池**（`gacha_panel.py:323-325` 及 5 个面板同类写法）。Windows 上 `terminate` 落到 `TerminateThread`，`with MPPool(...)` 的 `__exit__` 不执行，子进程不回收，且可能留下解释器级死锁。`gacha_panel` 那条基本不可达（按钮已禁用）；`plan_search_panel` 那条可达性明显更高（`:1219` 在翻看历史快照时会 `run_btn.setEnabled(True)`）。**待确认**。

**8. 完成后的状态栏消息被更不具体的一条立刻覆盖**（`main_window.py:508` 写入含数据集名的消息，随后 `gacha_panel.py:370` 把它盖掉）。用户在界面上不知道结果已自动存进 ResultStore、存成了什么名字。

**9. `tabs.setCurrentIndex(2)` 魔数**（`main_window.py:507`），同文件 `:602-609` 用的是按 `tabText()` 查找的正确写法。Tab 顺序一变就会跳错页。

**10. `seed = -1`（随机种子）时指纹仍写 `-1`**（`gacha_panel.py:309-310`、`main_window.py:416/467`）。两次随机种子的运行会被 `compare_fingerprints`（`core/result_store.py:343`）判为 `same`，而实际种子不同。GUI + WebUI 共有。

**11. `env.n_heatmap_bins` 往未声明字段上写**（`gacha_panel.py:62-63`、`webui/api.py:281-282`）。`SimulationEnv` 字段表里没有它，写错名字不报错，核心层 5 处 `getattr` 会静默用 50。

**12. GUI 直接把 store 的 dict 引用交给核心函数**（`gacha_panel.py:91` 传 `strategy_params=config_store.strategy_params` 无拷贝，WebUI 是 `dict(...)`）。当前无可见差异，属「运行参数与配置对象共享可变状态」。

**13. 「目标达成率」的语义**：`gacha_panel.py:393/402` 用「卡牌份数之和 ÷ 目标卡种类数」，若某张目标卡 `quantity = 3`，抽满时该行显示 300%，而列名写的是「率」。`quantity` 导致超过 100% 是 GUI 与 CLI 共有的口径问题。另 `:399` 的 SSR 口径与 CLI 不同（即入口统一报告中的 E1）。

## 三、依赖关系问题

**14. `benchmarks/` 深度驱动 GUI 内部，且对 GUI 源码做文本断言**：`benchmarks/perf/adapters/gui_qt.py:284-288` 按 `isinstance` 从 Tab 里找面板、`:295-297` 写控件属性名、`:469-474` 读状态标签文本、`:512-516` 置 `window._restarting`；`tests/benchmarks/test_adapter_contract_gui_qt.py:113-118` 读 `gacha_panel.py` 的**源码文本**断言实参里不出现 `on_result`。**这是反向依赖**：产品代码动一下就打断开发侧资产，会成为 GUI 重构的隐藏约束。

**15. GUI 调用 core 的私有函数**：`main_window.py:232/260` 用 `from gacha_simulator.core.config_toml import _build_plugins`（下划线私有），且各自重复了一遍「用 tomllib 重读文件」的逻辑，而 `load_toml` 已在 `:221`/`:250` 调用过一次。同类：`config_panel.py:4575/6538/7163`、`process_analysis_panel.py:552`。

**16. `main_window` 横向调用其他面板的私有方法**：`main_window.py:217`（`data_manager_panel._refresh_table()`）、`:392`/`:564`（`worst_impact_panel._load_last_pool_config()`，它会在每次模拟完成后重设该面板的池时长/成本/分布控件，覆盖用户手改的值）、`:416`（`gacha_panel._last_seed`）。

**17. `gacha_simulator/gui/batch_simulator.py` 是 0 字节空文件**，与 `service/batch_simulator.py` 同名。`import gacha_simulator.gui.batch_simulator` 会成功但拿到空模块，错误要等到属性访问才暴露。仓库里有踩过的历史证据（`.recycle_bin/_fix_p2.py:48`）。其去留此前被明确「归 P81、本项不做」。

## 四、已核对、判定无害（供后续排查省步）

- heatmap 分箱边界：GUI 的 `np.linspace` 参数与 `core/streaming.py:254-256` 逐字一致，不会错位。
- GUI 把 numpy 数组原样放进 heatmap_data，但 `core/result_store.py:17-24` 的 `_NumpyEncoder` 覆盖了 `np.ndarray`，`save_all` 不会炸。
- `pool_types` 的键：`core/config_store.py:375-389` 返回的就是全限定键，与注释相符。
- `final_time` / `pity_triggers` / `banner_end_resources` 在 `extract_aggregate` 里都真实存在。
- `store.simulation_count / max_workers / seed`：`config_toml.py` 完全不序列化它们，`SimulationEnvBuilder` 也不读，实际影响仅限内存共享。
- `SimulationThread` 覆盖 `finished` 不会导致完成回调被调用两次或收到 `None`（已实测）。

## 五、顺手发现的小问题

- `gui/retreat_panel.py:389`：`_on_error` 里调 `traceback.print_exc()` 但此处没有活动异常上下文，只会打印 `NoneType: None`。
- `gacha_panel.py:301-305`：两条软提醒只写进面板日志框，主窗口状态栏与落库指纹里都没有痕迹；CLI/WebUI 连这条提醒都没有。
- `gacha_panel.py:110-114`：基线的 `run_batch_parallel` 调用**不传** `strategy_params`，于是继承用户策略的参数。no_draw 当前不读参数所以无害，但这是「基线不是纯粹的中性对照」的写法漂移。
- `main_window.py:589-590`：用 `assert` 做线程断言，`python -O` 下会被剥掉。
- `gacha_panel.py:14-18` 与 `retreat_panel.py:21-22`：把包目录本身插入 `sys.path[0]`，是与 `main.py` 不同的第二种路径约定，登记为卫生问题。
