# P77 资源生命周期——限时货币强制兑换与清零

> 日期：2026-08-08 设计定稿 | 2026-08-22 扩展为可实施计划 | 状态：已规划（可实施）

## 一、问题

### 1.1 限时资源无生命周期（G6 + FGO 清零）

手册登记三款游戏 + FGO 存在「池结束 → 限定货币到期处理」机制，当前无法建模：

| 游戏 | 机制 | 到期行为 |
|------|------|---------|
| 幻塔 | 回火铸金（限定） | 卡池下架 → **等额转换**黑市铸金（常驻） |
| 蔚蓝档案 | 天井点数 | 卡池下架 → **转换**制造石碎片 |
| 赛马娘 | 天井点数 | 卡池下架 → **转换**四叶草 |
| FGO | 天井点数 | 卡池下架 → **清零**（不转任何常驻货币） |

**根因**：当前 `resource_defs: Dict[str, str]` 仅是「资源 id → 显示名」映射（`core/config_store.py` `ConfigStore.resource_defs` 字段），资源是**全局永驻**的一等公民，没有「到期时间」和「到期行为」两个属性。任何「限时货币/池专属货币」都无法表达。

**到期语义界定**：真实机制中「卡池结束」是**时间性下架**（卡池开放期结束），与玩家抽卡行为无关。模拟里 banner 的 `available_until`（秒）即此语义；玩家抽空池子（`pool_exhausted`/`max_draws` 耗尽）不应触发货币到期——故本计划以**时间触发**而非「Banner 结束事件」触发。

### 1.2 为什么不是 P61 lifecycle action / banner 结束事件

P61 `[[banner.lifecycle]]` 是「池的规则」：`condition → action`（`switch_to` / `exhaust_banner`），管池子可用性与切换。把资源转换塞进去变成「池结束 → 转换资源」，规则散落在每个 banner 配置里，同一资源被多池共用时需重复声明，且无法表达「到期清零」（无转换目标）。

更深一层：**P61 的 banner 结束并非单一事件**，而是两条独立路径——① lifecycle 规则（`_check_transitions`，事件驱动）；② ISSUE-001 时间窗口过期直接 `_exhaust()`（`gacha_service.py` 等待期 `real_time >= bet` 分支，**不经过 lifecycle 规则**）。若把资源到期挂「Banner 结束事件」：
- 挂 lifecycle 事件 → 纯 `available_until` 关闭（无 lifecycle 规则的常见形态）不触发，资源永不过期；
- 挂 exhaust 事件 → 玩家抽空池子也触发到期，语义错。

**强制兑换的主体是资源，到期时刻本质是时间**。故本计划由资源持有 `expire_at`（或对齐某 banner 的 `available_until`），时间驱动——与 P63（溢出挂在卡上）、P65（标签挂在卡上）「数据自描述」范式同构，且复用 P61 现成的时间检查点。

## 二、目标

- 资源支持「到期时间 + 到期行为」——`expire_at`（绝对时间）/ `expire_with_banner`（对齐 banner 下架时刻）+ `on_expire`（转换/清零）
- 时间驱动触发，复用 P61 现有时间检查点，不新建事件系统
- **策略可知性**——到期信息经 `StrategyContext` 注入策略，策略可感知「某资源剩余 N 天到期、到期变什么」并据此决策
- **记账语义**——转换 = 源 `total_consumed` + 目标 `total_gained`（对齐 P58 milestone 资源并入 total_gained 先例，对账天然成立；GDR 分母固定为 draw_resource 与限定货币不相交，口径自然隔离）
- 覆盖游戏：幻塔/蔚蓝档案/赛马娘（G6）+ FGO（清零）
- 保持 `resource_defs: Dict[str, str]` 结构不动——不破坏 gdr.py 与 11 处 GUI 引用
- **UI 适配纳入本期**——P78 已实现「资源定义 Tab」（方案 X），本计划在其 lifecycle 占位区落地到期编辑（**实施顺序：P78 先、P77 后**）

## 三、方案

**设计决策（2026-08-08 二次评审修订）**：

1. 不修改 `resource_defs: Dict[str, str]`（波及 gdr.py 的 `for rid, rname in resource_defs.items()` + 11 处 GUI），**新增独立配置段** `resource_lifecycle`——只有声明了生命周期的资源才参与到期结算，其余资源行为完全不变。
2. **触发模型改为时间驱动**（原「Banner 结束事件触发」废弃）。到期时刻两个来源，互斥二选一：
   - `expire_at`：绝对到期时间（秒，TOML/UI 层以天书写，解析边界 `*DAY`，与 P61 一致）
   - `expire_with_banner`：快捷选项——对齐某 banner 的 `available_until`，覆盖「限时货币与卡池同步失效」的常见场景，免手写绝对秒数
3. **策略可知性**——`StrategyContext` 新增 `resource_expiry` 预览字段，由 `build_strategy_context()` 集中构造，与 `pending_transitions`/`future_resource_gains` 同一惯例。
4. **`on_expire` 仅两态（第三次裁决）**——`转换` / `清零`，**无「保留」态**，且**到期时间与 `on_expire` 必须成对出现**（声明了 `expire_at`/`expire_with_banner` 就必须有 `on_expire`）——「有到期时间但到期后什么都不做」的中间态无意义，与「无生命周期声明」重合，徒增配置歧义。`ctx.resource_expiry` 只承载「明确声明了到期动作」的资源（见 3.4）。
5. **转换比例支持精确整数对（第三次裁决）**——`on_expire = { convert_to, from: int, to: int }`，语义为「每 `from` 个源资源换 `to` 个目标资源」；可表达非等额比例（3 A 换 2 B）。整数对避免 `rate` 浮点乘法取整的语义含糊：余额 `balance` 可换 `(balance // from) * to` 个，**零头 `balance % from` 随源资源一并清零**（到期即作废，无找回）。

### 3.1.5 TOML 结构定位

`[resources.lifecycle]` 是 `[resources]` 命名空间下的**第四个平级子表**，与 `[resources.defs]`（id → 显示名）、`[resources.initial]`（id → 初始数量）、`gain_rules`/`day_overrides` 平级，**不嵌套进 `defs`**（嵌套会把 `resource_defs: Dict[str, str]` 的值类型从 `str` 变 `dict`，破坏签名与全部只读消费者）。

def apply_resource_expiry(self, rule: ResourceLifecycle, state: GachaState,
                          total_consumed: Dict, total_gained: Dict) -> None:
    """P77——到期时刻到达，执行资源到期结算。

    记账语义：转换 = 源 consumed + 目标 gained（对齐 P58 milestone 资源并入
    total_gained 先例）——对账恒等式（final = initial + gained - consumed）
    天然成立，无需新增结果字段或序列化版本号。
    """
<!-- REVIEW-R1-FIX: ISSUE-102 -->    import math
    balance = state.resources.get(rule.resource_id, 0)
    if balance <= 0:
        return
    # 限时货币按整数量纲解释：小数余额先 floor 再做整数对整除，零头随源清零
    # 约束见 §3.1 校验——限时货币产出应为整数；出现小数时按 floor 语义可预期处理
    if rule.on_expire and 'convert_to' in rule.on_expire:
        f, t = rule.on_expire['from'], rule.on_expire['to']
        q, r = divmod(math.floor(balance), f)      # 完整兑换对 q，零头 r 作废（含小数零头）
        amount = q * t
        # gain/spend 均为 Dict 单参（state.py:42/85），不存在键由 gain/spend 内部初始化/钳制
        state.spend({rule.resource_id: balance})   # 源全额扣减（含零头）
        if amount > 0:
            state.gain({rule.on_expire['convert_to']: amount})
        total_consumed[rule.resource_id] = total_consumed.get(rule.resource_id, 0) + balance
        if amount > 0:
            total_gained[rule.on_expire['convert_to']] = total_gained.get(rule.on_expire['convert_to'], 0) + amount
    elif rule.on_expire and rule.on_expire.get('clear'):
        state.spend({rule.resource_id: balance})
        total_consumed[rule.resource_id] = total_consumed.get(rule.resource_id, 0) + balance  # 清零 = 消耗
    # 配置校验已保证：on_expire 必为转换/清零之一，且到期时间与 on_expire 成对出现

### 3.5 记账与对账口径（2026-08-08 评审修订）

**记账**：转换 = 源资源 `total_consumed` + 目标资源 `total_gained`（目标按完整兑换对计算，**零头随源作废**——只记源全额消耗，零头不折算进目标，不产生额外收益）；清零 = 源资源 `total_consumed`。对齐 P58 milestone 资源并入 `total_gained` 的先例（`run_simulation` 循环收尾的 `merged` 合并块）——`total_gained` 本就含非抽卡获得，转换到账并入与先例一致。

**对账**：`final_resources = initial_resources + total_gained - total_consumed` 天然成立（源和目标各平），无需新增结果字段、无需序列化版本号变更。

**GDR 隔离**：GDR 转化效率分母固定为 `draw_resource`（抽卡资源），转换涉及的是限定货币（回火铸金/天井点数），**口径自然隔离**——GDR 结果不受转换影响（`final_resources` 反映转换后果，余额类统计不受影响）。若未来出现以限定货币为分母的 GDR 配置，需另行评估（配置约定，非代码守卫）。

**结算顺序**：<!-- REVIEW-R1-FIX: ISSUE-306 -->转换结算**先于** `banner_end_resources` 快照（等待期 / 每抽后 / 循环收尾同检查块内，固定顺序——先资源到期后 banner 快照，见 §3.3 时序纪律）——快照语义是「banner 生命周期结束时的最终资源」，应含收尾动作结果。
