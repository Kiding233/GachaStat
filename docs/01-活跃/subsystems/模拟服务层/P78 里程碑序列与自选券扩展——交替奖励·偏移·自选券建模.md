# P78 里程碑序列与自选券扩展——交替奖励·偏移·自选券建模

> 日期：2026-08-08 | 状态：设计中
> 触发：手册 §二十一 G18（终末地武器池交替循环）+ 自选券奖励的普遍机制。2026-08-08 设计评审收敛——里程碑扩展与资源生命周期（G6，P77）分为两个独立计划；同日二次评审收敛——交替节点锚定累计抽数（砍 `start_after`）、自选券只记资源不落卡、候选集独立 `[[select_voucher]]` 段。
> 三次评审（外部审计 D4-D7）裁决：D4 交叉点记录不耦合、D5 本期只建模保可查询性、D6/D7 用 warning 而非 ConfigError。
> 依赖：P58✅（MilestoneEngine）、P61✅（事件总线——提供 after_draw 事件）、P63✅（溢出管道——bonus 卡走 state.add_card）

## 一、问题

### 1.1 里程碑引擎缺序列能力（G18）

终末地武器池交替循环（手册 §16.4，公测版）：

```
80 抽大保底（必出当期 UP，1 次）→ 之后每 80 抽一个节点：
100 → 补充武库箱（自选 1 把非 UP 的 6★ 武器）
180 → 当期 UP 武器
260 → 武库箱
340 → UP 武器
…   （无限交替，A/B 循环）
```

当前 [MilestoneEngine](gacha_simulator/core/milestone.py) 只支持：
- `at=N` 单次触发（一次性）
- `every=N` 周期触发（**同奖励**重复）

**缺失能力**：**交替奖励序列**——`every=N` 触发时奖励 A/B 循环切换，无法表达「武库箱 ↔ UP」交替。

**锚定语义（2026-08-08 裁决）**：100/180/260/340 是**累计抽数的绝对节点**（锚定累计抽数），不是「大保底触发后第 N 抽」。100 = 累计第 100 抽，与是否提前出金无关。因此：
- **不需要 `start_after` 字段**——节点位置由累计抽数决定，与任何事件解耦
- 大保底（80 抽必出当期 UP）是 pity 的事，由现有 `hard` pity 覆盖（手册 §16.6 已配置 `endfield_wp_large`），**不属于本计划的建模范围**

### 1.2 自选券是普遍机制，候选集每池不同

「补充武库箱」= 发一张**自选券**，玩家从中自选 1 张 6★ 武器。自选券（self-select voucher）在手册覆盖的游戏中是普遍机制，但候选集每池不同：

| 场景 | 候选集范围 | 确定时机 |
|------|-----------|---------|
| 终末地武器池 100 抽武库箱 | **本池 6 个陪跑 6★ 非 UP 武器**（每池不同） | 配置时（本池配置一次，各池各异） |
| 终末地新手池 40 抽自选箱 | 标准 6★ 角色 | 配置时（跨池固定） |
| 星铁 300 抽常驻自选 | 标准常驻 5★ | 配置时 |
| 异环 120 抽音波自选 | 已解锁 S 角色 | 模拟运行中（依赖持有状态） |

**建模决策（2026-08-08 裁决）**：
1. **只记券，不落卡**——自选券建模为一种**资源**（进入 `state.resources`），引擎不替玩家选、不把结果写进 `acquired`。自选卡在模拟中不成为「获得卡」，GDR/目标达成分析中它是「持有券但未选择」状态。
2. **候选集显式列表**——每个自选券一个配置条目，显式列出可兑换的卡 id（不引用池子、不做标签过滤、不做「排除 UP」的运行时推导）。「每池范围不同」由不同资源 id + 各自候选列表自然承担。
3. **独立 `[[select_voucher]]` 配置段**——候选集定义不属 milestone，是资源的元数据声明，分析/展示层可查询「这张券能换什么」。

## 二、目标

- `MilestoneDef` 支持 `alternate_rewards` / `offset`
- `alternate_rewards` 交替项支持资源类型奖励（发券）——复用 `_resolve_bonus` 的 resources 注入
- 新增 `[[select_voucher]]` 段——候选集定义（独立于 milestone）
- 覆盖终末地 G18 交替循环 + 自选券普遍机制
- 全部新字段/新段带默认值，向后兼容——不配置的旧 TOML 行为完全不变

## 三、方案

### 3.1 MilestoneDef 扩展（2 个新字段）

**新增位置**：[core/milestone.py](gacha_simulator/core/milestone.py) + [config_store.py](gacha_simulator/core/config_store.py) 的 `MilestoneDef`

```python
@dataclass
class MilestoneDef:
    name: str
    threshold: int = 40
    repeat: bool = False
    max_triggers: int = 0
    bonus_reward: dict = field(default_factory=dict)
    banner: str = ""
    # ── P78 新增（全部带默认值，向后兼容）──
    alternate_rewards: List[dict] = field(default_factory=list)  # 交替奖励序列（空=原行为）
    offset: int = 0            # 首节点相位偏移（0=从 threshold 起）
```

> 语义：`offset` 是**首节点专用相位偏移**——`threshold_eff = threshold + (offset if 从未触发 else 0)`，**仅首节点生效**；repeat 归零后回退到裸 `threshold`（ISSUE-001 修正——若 offset 叠加在每次 repeat 判定上，节点序列会漂移为 100/200/300 而非 100/180/260/340）。不改变 `threshold` 的周期语义。
> **D6 裁决**：`offset` 与 `at=N`（`repeat=False`）组合——`threshold=80, offset=20, repeat=false` 在第 100 抽触发一次，offset 整体后移触发点，**语义易混淆但不报错**（用户可能误以为「80 抽后再偏移 20」）。力度：**解析期 `warning` 而非 `ConfigError`**——P77 归档对同类冲突（alternate 与 bonus_reward 并存）用的也是「文档明确」软约束，`ConfigError` 过重。
> **D7 裁决**：`alternate_rewards` 配 `repeat=False`——单次触发只取到 A 就结束，B 是死配置，几乎必然笔误。力度：**解析期 `warning`**（退化「只用第一条」不崩溃，`ConfigError` 过重）。
> **D6/D7 warning 通道决策（ISSUE-105）**：沿用 `config_toml.py` 既有先例——`warnings.warn`（L82-86 旧 `[[pools]]` 段残留警告同通道，输出 stderr）。**可见性边界**：CLI/测试可见，GUI 会话不可见（G18 目标用户场景恰是「手工写 TOML → GUI 加载交互」）；若需 GUI 内可见提醒，须另行经 store/logger 路由到 GUI 状态栏——本期不实现，仅记录通道决策。
> **REVIEW-R1-FIX: ISSUE-112 —— `alternate_rewards` 空列表/空项解析期校验（与 ISSUE-006 同构校验一并完成，区分「未配置」与「显式空配置」）**：
> 1. **显式空列表抛 ConfigError**：TOML 中**显式写了 `alternate_rewards = []`** 时抛 ConfigError（用户写了以为在交替、实际静默回退 `bonus_reward`，无任何提示）；**键缺失（走默认值 `[]`）不抛**——保持「不配置旧 TOML 行为完全不变」验收。解析器须区分「键存在与否」而非只看解析后值。
> 2. **空 dict 项抛 ConfigError**：`alternate_rewards` 每项必须至少含 `cards`/`resources`/`random_cards` 之一——空项 `{}` 会触发 `_resolve_bonus_from({})` 返回空奖励（consumes 一次触发周期），静默吞掉一次节点。逐项校验复用 ISSUE-006 的全量校验入口（cards 存在性/resources 数值/random_cards 结构），`{}` 在此入口直接不通过。
> 3. **单元素交替列表发 warning（ISSUE-120，与 D7 同处完成）**：`alternate_rewards` 长度 == 1 时发 warning（`warnings.warn`，ISSUE-105 通道，stderr）提示「单元素交替列表等价于 bonus_reward，疑似笔误」（本意可能是 bonus_reward 或漏写第二项），不崩溃。与 D7（`repeat=False` + alternate 仅取 A）同属笔误高发区，但 D7 warning 只覆盖 repeat=False 组合——`len==1` + `repeat=True` 此前静默通过（`% len(...)` 恒返回同一项，行为与 bonus_reward 完全等价）。示例文档（config/config.toml）注明该语义。
>
> **REVIEW-R1-FIX: ISSUE-113 —— 写出侧条件写键纪律（与 ISSUE-112 解析侧规则配对，缺一不可）**：ISSUE-112 规则 1 要求解析器区分「键存在与否」——显式 `alternate_rewards = []` 抛 ConfigError、键缺失走默认值。因此 `save_toml` 的 milestone 写出段（config_toml.py L166-177）**不得**沿用现有六字段的无条件全量写出模式（否则 GUI 保存会给每个无交替里程碑写出 `alternate_rewards = []` 空键，下一次 load_toml 命中 ISSUE-112 规则 1 抛 ConfigError——仓库自带 config.toml 的两个 milestone_example 与全部旧配置在首次 GUI 保存后即无法重载）。**写出侧纪律（强制）**：
> 1. `if m.alternate_rewards: entry['alternate_rewards'] = m.alternate_rewards`——**空列表省略键**（不写 `alternate_rewards = []`），仅非空写出；
> 2. `if m.offset: entry['offset'] = m.offset`——零偏移省略键；
> 3. 与既有条件写键先例同构（`pity` 段 `if p.threshold is not None`、`card` 段 `if c.overflow_bands`、P69 strategy 段「仅写入与默认值不同的参数」）。
> 该纪律保证「round-trip 一致」（GUI 保存→重载不抛 ConfigError）与「不配置旧 TOML 行为完全不变」双验收同时成立；§七 验收须补「GUI 保存→重载」回归断言（用无交替/零偏移的既有 milestone 验证空键省略、重载正常）。
>
> **REVIEW-R1-FIX: ISSUE-121 —— 条件省略键纪律扩展到 get_config 输出侧（与 ISSUE-113 写盘侧配对，闭合 get_config→set_config round-trip）**：ISSUE-113 只约束 save_toml 写盘侧，但 ISSUE-101 要求 get_config（config_panel.py L4791-4798）的 milestone dict 携带 `alternate_rewards`/`offset`——get_config 输出的是**普通 dict**（非「TOML 显式键」语义），若按 ISSUE-101 字面「无条件携带」，无交替的合法里程碑输出 `'alternate_rewards': []`，set_config 恢复路径（ISSUE-114）构造 MilestoneDef 前过 `_validate_milestone_dict`（复刻 ISSUE-112 规则 1）时**无法区分「用户显式写空」与「程序默认空」**，按规则 1 抛 ConfigError → 任何 get_config→set_config→get_config round-trip（§七 ISSUE-102 验收、test_set_config_reads_p56_fields 同族、`main_window._export_json` L316 导出后恢复）对无交替/零偏移里程碑全部失败，与 ISSUE-102「milestone.milestones（含 alternate_rewards/offset）完整存活」验收直接矛盾。**纪律（强制，输出侧与写盘侧同规则）**：get_config 构造 milestone dict 时 `if m.alternate_rewards: entry['alternate_rewards'] = m.alternate_rewards`、`if m.offset: entry['offset'] = m.offset`——**空值省略键**（无交替/零偏移里程碑输出 dict 中**键缺失**，set_config 走默认值路径不抛；含交替/非零偏移里程碑键存在，ISSUE-102 存活验收不受影响）；`_do_update_preview`（L4528-4542）读摘要同样按「键存在才读」处理。**选型说明（保守方案）**：不采用「`_validate_milestone_dict` 区分来源」——程序生成 dict 与 TOML 显式键在 set_config 入口无法可靠区分来源，且会让校验入口带隐式分支；统一「条件省略键 + 键缺失=未配置」使输出/写出两侧同构（与 ISSUE-113 先例一致）。§七 验收补「get_config→set_config 对无交替/零偏移里程碑不抛 ConfigError」断言（与 ISSUE-114 的「非法值被拒」断言并列：合法默认值不抛、非法显式值拒绝）。
>
> **REVIEW-R1-FIX: ISSUE-118 —— `[[select_voucher]]` 段独立顶层键 + 独立写出 gate（与 ISSUE-113 平行，防 milestone gate 误伤）**：save_toml（config_toml.py L100）中 `[[select_voucher]]` 段**必须**写在 milestone 写出块（L166-177，`if store.milestone.enabled and store.milestone.milestones:`）**之外**，用**独立 gate `if store.select_vouchers:`**（与 milestone gate 无关）——若实现者把该段自然嵌套进 milestone 写出块（voucher 与 milestone 语义相近，是自然倾向），则 milestone 被禁用（GUI「启用累抽奖励」取消勾选）或 milestones 为空、但 select_vouchers 非空（券仍可被 gain_rules/initial_resources 或其他段引用）时，`[[select_voucher]]` 段被整体跳过，重载后候选集丢失且 ISSUE-005 自动补全不再触发。§七 验收补「milestone 禁用但 select_vouchers 非空 → 保存 → 重载段存活」断言。

### 3.2 引擎逻辑（MilestoneEngine）

```python
def __init__(self, defs, seed=42):
    # ... 原有状态 ...
    self._alt_index: Dict[str, int] = {}        # 交替奖励当前索引

def after_draw(self, banner_id, pool_id):
    for name, md in self._defs.items():
        if not self._active[name]:
            continue
        if md.banner and banner_id != md.banner:
            continue
        c = self._counters.get(name, 0) + 1
        self._counters[name] = c
        # REVIEW-R1-FIX: ISSUE-001 —— offset 仅作用于首节点：threshold_eff 只在从未触发时叠加 offset，
        #   触发后 repeat 归零回到裸 threshold——保证节点序列 100/180/260/340 而非 100/200/300。
        threshold_eff = md.threshold + (md.offset if self._triggered.get(name, 0) == 0 else 0)
        if c < threshold_eff:                    # offset 推后首节点
            continue
        # 触发——交替序列取奖励
        if md.alternate_rewards:
            reward = md.alternate_rewards[self._alt_index.get(name, 0) % len(md.alternate_rewards)]
            self._alt_index[name] = self._alt_index.get(name, 0) + 1
            bonus = self._resolve_bonus_from(reward)   # 从交替项解析（复用 _resolve_bonus 逻辑）
        else:
            bonus = self._resolve_bonus(md)
        bonuses.append({'name': name, 'bonus': bonus})
        # ... 原有 repeat / max_triggers 生命周期管理（不变）——repeat 归零后
        #     threshold_eff 回退为裸 threshold（因 _triggered ≥ 1），offset 不再叠加 ...
```

**`_resolve_bonus_from` 复用**：交替项的解析逻辑与 `_resolve_bonus` 完全一致（cards / resources / random_cards 三字段任意组合），仅数据来源从 `md.bonus_reward` 换成交替项 dict——抽公共私有方法，零重复。`_resolve_bonus(md)` 改为委托 `_resolve_bonus_from(md.bonus_reward)`。

### 3.3 自选券——资源 + 候选集

**只记券**：自选券就是一个资源 id（如 `endfield_supply_voucher`）。里程碑 `alternate_rewards` 或 `bonus_reward` 发券走**现有 `_consume_bonus` 的 resources 注入路径**（[milestone.py:173-179](gacha_simulator/core/milestone.py#L173-L179) 的 `state.resources[k] += v`），**引擎零改动**。

**候选集定义**——新增独立配置段 `[[select_voucher]]`（`config_store.py` + `config_toml.py`）：

```python
@dataclass
class SelectVoucherDef:
    """自选券候选集定义（P78）——资源 id → 可兑换卡片显式列表。"""
    voucher: str            # 关联资源 id
    cards: List[str] = field(default_factory=list)   # 候选卡片显式列表
```

> **REVIEW-R1-FIX: ISSUE-111 —— `[[select_voucher]]` 解析期边界校验（低成本约束，防错误配置静默通过）**：
> 1. **voucher id 去重（ConfigError）**：两条 `[[select_voucher]]` 声明同一 voucher id → 解析期抛 ConfigError，与 milestone name 去重同构——GUI 资源定义 Tab 详情面板按资源 id 关联编辑（回填/保存按 voucher id 查表），重复 id 时写入语义歧义（覆盖还是报错），必须解析期排除。
> 2. **空候选集语义明确**：`cards = []` **允许**（视为「可兑换空集」——持券但无可兑换项，模拟不崩溃），但解析期发 `warning`（同 ISSUE-105 通道，`warnings.warn` stderr）提示「候选集为空，该券不可兑换任何卡」，并在 `config/config.toml` 示例段注明该语义——不采用 ConfigError（空候选集是合法配置态，仅大概率笔误）。
> 3. 候选卡 id 存在性校验（ConfigError，与 milestone 的 cards 校验同构）保持 §3.3 既有约束不变。

**TOML 配置**（终末地武器池）：

### 3.4 与 P77 的交叉（D4 裁决）

P78 自选券与 P77 限时货币是**结构性交叉**：券是资源，若某券有到期机制（如 7 天不兑换作废），P77 的 `on_expire` 天然覆盖——`convert_to`/`clear` 对券同样适用，**零耦合**，P78 发券、P77 给券挂到期即可。

**但手册 §16.4 / §16.7 均无「武库箱券会过期」的记载**——到期机制是推测场景，非已确认事实。因此**不为不存在的机制加用例**：P77 验收不加「自选券到期」用例（D4 裁决），P78 只记结构性认识。

**实施顺序（2026-08-08 裁决）**：**P78 先做，P77 后做**——P78 实现资源定义 Tab（含 lifecycle 占位区），P77 实施时把 §3.6 从「扩列 5 列」改写为「填 P78 Tab 的 lifecycle 区域」。GUI 只重构一次；P77 数据层（`core/resource_lifecycle.py`）完全独立，仅 GUI 落点依赖 P78 的 Tab。两计划数据层独立段互不阻塞。
