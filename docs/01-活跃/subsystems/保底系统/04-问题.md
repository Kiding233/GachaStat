### 缺陷 11：多保底管道无优先级逻辑（中等）

- **来源**：全模块审查 §2.3 + P30 计划
- **严重度**：中等（实现局限，非代码错误）
- **位置**：`core/pity.py` 的 `_resolve_order()` / `_validate_behaviors()`
- **问题**：保底按定义顺序依次调整概率分布。当软保底和硬保底同时触发且目标集不同时，后处理的行为可能覆盖前者的调整。无冲突解决机制。
- **理论立场**：管道顺序语义是设计意图，允许配置者通过排列控制优先级。
- **原推荐方案**：
  1. 在 `pity.py` 模块 docstring 中说明管道顺序语义
  2. 在 `PityEngine.__init__()` 中增加冲突检测：若两个保底适用同一池且目标集部分重叠，发出 `warnings.warn()`
  3. 长期方向：支持显式 `priority` 字段（配置格式变更，需慎重）
- **处置结论**（P55/P56）：两道机制**只有冲突检测真正生效**。
  - **冲突检测：✅ 已生效**。`_validate_behaviors(behaviors)` 把原方案的 `warnings.warn()` 升级为**硬性 `ConfigError`**。四条规则：name 重名 → `ValueError`；同 scope 两个硬保底 / 同 scope 两个事件驱动型 / 同 scope 同 btype 两个软保底 → `ConfigError`。非法配置在 `PityEngine` 构造期即被拒绝，而非运行期告警
  - **顺序确定性：❌ 未接通**。`_resolve_order(behaviors, rarity_rank)` 确实存在、排序键也确为 `(稀有度 rank, btype 顺序, name)`，但其输出**只赋给 `self._behavior_list`**（`pity.py:1178`）。概率管道三个入口（`get_probabilities` / `before_draw` / `after_draw`）走的是 `get_behaviors_for_pool()` → `for pname in spec.pity_names`（`pity.py:1195`，定义于 `:1189`），而 `spec.pity_names` 由 `batch_simulator.py:173-177` 按 **TOML 定义顺序**逐个 append 生成。`_behavior_list` 的消费点只有 `_rebind_state` 重绑定（`pity.py:1247`），与顺序无关。**缺陷原文「顺序由定义顺序决定」在代码上仍然成立**
  - **未实施**：显式 `priority` 字段与「取最高概率」方案均未实施
- **2026-09-15 复核补充**：「互斥校验已强制 → 覆盖场景不可能发生」这一推论**过强**。四条校验只禁「同 scope 两个硬保底」「同 scope 两个事件驱动型」「同 scope 同 btype 两个软保底」三类；同 scope 的**「一软一硬」是合法配置**，而该场景下覆盖确实发生：`SoftStepBehavior._compute_probabilities` 重分配概率后，`HardPityBehavior._compute_probabilities` 触发时以 `result = {k: 0.0 for k in ctx.current}` 重建分布，软保底的调整被整体覆盖。跨稀有度场景由排序键的稀有度优先级保护，同 scope 内的覆盖未被防住
- **2026-09-18 补充（敏感集合修正）**：P64 §3.1.5.4 的反例实测显示，**`target_featured=True` 的 soft 与 hard 共存**时顺序敏感（12 抽对比中第 8–12 抽不同，第 8 抽 `[soft,hard]` 得 `ssr:0.5/ssr_featured:0.5`、`[hard,soft]` 得 `ssr:0.2/ssr_featured:0.8`），故敏感集合应表述为「含 `rotating_cr`，或 `target_featured=True` 的 soft 与 hard 共存」，而非仅后者含 `rotating_cr`
- **当前状态**：⚠️ **部分解决**。P30 已于 2026-09-14 归档；顺序问题整体由 P64 承接，**2026-09-18 已裁决为「接线」**（让排序生效，`priority` 保留为覆盖手段，见 P64 §1.5）
- **派生待办**：`_resolve_order()` 未接通概率管道是一个真实的功能缺口（可能有意留待后续，也可能是遗漏），需单独立项判定——**该项已由 P64 §1.5 的三项待裁决承接**
