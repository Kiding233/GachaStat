## 一、问题

### 1.1 组合爆炸（核心问题）

现有 [pity.py](gacha_simulator/core/pity.py) 10 类，事件驱动 6 个的正交组合已现裂痕：

```
rotating × soft = RotatingSoftBehavior
rotating × cr = RotatingCRBehavior
rotating × cr × soft = RotatingCRSoftBehavior
targeted × soft = TargetedSoftBehavior
```

[`SoftPityMixin`](gacha_simulator/core/pity.py#L549) 缓解了 soft 维度，但 cr 是 RotatingBehavior 子类（[pity.py:596](gacha_simulator/core/pity.py#L596)）、targeted 是独立类（[pity.py:654](gacha_simulator/core/pity.py#L654)）。新增任意拓扑维度（如 inverse 必歪），将与每个现有维度再组合。每类重复实现 `_scope_total_prob`/`_featured_slots`/`_is_trigger_rarity` 骨架（[pity.py:536-544](gacha_simulator/core/pity.py#L536-L544)、[pity.py:733-737](gacha_simulator/core/pity.py#L733-L737) 等 4 处），after_draw（状态更新）与 before_draw（概率效果）硬编码耦合在各类的 if/else 里。

## 二、目标

- 提炼 `EventDrivenBehavior` 通用骨架（状态容器 + before/after 调度 + 槽位工具 + 生命周期 + P75 rebind），现有 6 个事件驱动类退化为 **preset**（策略组合的具名配置）

- **soft 效果化（阶段二）**：`SoftBoost` 效果，3 个 `_soft` 类 + `SoftPityMixin` 退役，任意拓扑 × soft 彻底正交
- **等价性保证（P64 验收核心）**：同配置下旧类 vs 新引擎，固定种子逐场对比概率分布 + 状态快照完全一致
- 覆盖 G1（inverse preset）+ G16（独立先行 `reset="never"`）+ G5（调度层 `priority` 显式排序）
- PityEngine 调度层接口签名不变（`_resolve_order` 加 `priority` 排序优先级，不破坏现有签名），GUI 参数描述（params/ui_params）不变

## 三、方案

### 3.1 抽象层（新建 `core/state_machine.py`）

把事件驱动型的两个可变点抽成策略对象：**转移规则**（抽后：事件 → 状态更新）、**概率效果**（抽前：状态 → 概率分布）。公共骨架只写一次。

#### 3.1.1 动作原语 Action

现有状态只有 Flag/Counter 两种，操作只有 set/clear/incr/reset 四种。用命令对象：

```python
class Action(ABC):
    @abstractmethod
    def apply(self, ctx: 'PityContext', bh: 'EventDrivenBehavior') -> None: ...

class SetFlag(Action):          # state.set(name, flag, True)
class ClearFlag(Action):        # state.set(name, flag, False)
class IncrCounter(Action):      # state.incr(name, counter, delta)
class ResetCounter(Action):     # state.set(name, counter, 0)
```

#### 3.1.2 转移规则 EventRule

after_draw 的差异是「事件发生时哪些状态怎么变」。两级判定收敛现有 `_is_trigger_rarity` + `_is_hit`：

```python
class EventRule:
    """转移规则——触发稀有度出金时按 hit/miss 执行动作列表。"""
    def __init__(self, *, trigger="scope", judge="featured",
                 hit: List[Action], miss: List[Action], judge_fn=None):
        # trigger: "scope"（出触发稀有度才判定，默认）
        # judge:   "featured"（ctx.draw.is_featured）| "selected"（命中定轨卡）
        #          | "custom"（judge_fn 钩子）
        ...
    def apply(self, ctx, bh):
        if not self._trigger_hit(ctx, bh): return
        for a in (self._hit if self._judge(ctx, bh) else self._miss):
            a.apply(ctx, bh)
```

`judge="selected"` 从 `state.get(name, "selected_card")` 读取定轨卡（targeted 现有逻辑）。

#### 3.1.3 概率效果 Effect + 概率动作家族

before_draw 的差异是「状态满足时概率怎么调」。效果 = 条件谓词 + 概率动作：

```python
class Effect:
    """概率效果——条件满足时返回调整后概率，否则 None（继续下一个效果）。"""
    def __init__(self, condition, action):
        # condition: "guaranteed" / "forced_loss" / "fate_ready" / Always() / 函数
        # action:    ForceFeatured / ForceNonFeatured / ForceSelected / SoftBoost / CRIntercept
        ...
    def apply(self, ctx, bh, readonly) -> Optional[Dict[str, float]]:
        if self._condition_satisfied(ctx, bh):
            return self._action.apply(ctx, bh, readonly)
        return None
```

概率动作家族（全部复用现有 `_redistribute_scope` 的按基础权重分配逻辑，[pity.py:461-486](gacha_simulator/core/pity.py#L461-L486)）：

| 动作 | 语义 | 对应现有 |
|------|------|---------|
| `ForceFeatured(ratio)` | 目标槽位概率 = ratio | rotating/CR 的 guaranteed 分支 |
| `ForceNonFeatured(ratio)` | 非 UP 槽位概率 = ratio（**G1 新增**） | 幻塔必歪 |
| `ForceSelected(card)` | 定轨卡槽位 100% | targeted 的 `_resolve_selected_slots` |
| `SoftBoost(deltas)` | 按 counter 累计 boost 提概率（**阶段二**） | SoftStepBehavior._compute_probabilities |
| `CRIntercept(...)` | 随机拦截（cr_base_rate/cr_state_probs） | CR 的 before_draw 随机分支 |
| `BaseRatio()` | 按 current 比例 redistribute | rotating/targeted 的默认分支 |

**效果链契约（强制）**：骨架 `before_draw` 按效果列表**顺序应用、非短路**，每个效果在前一个效果的输出（`ctx.current`）上操作。覆盖型效果（ForceFeatured 把目标槽位之外的槽位置 0）在语义上覆盖前序效果的概率调整（soft 抬高的 scope 总量在 guaranteed 下全部流入 featured，soft 加成被保留而非消失，与旧 mixin「先 soft 后事件」等价）。等价性由此契约 + 等价性测试双重守门。

**CRIntercept 随机数消耗协议（H4，强制）**：rotating_cr 旧类 before_draw 用模块级 `random.random()`（[pity.py:616](gacha_simulator/core/pity.py#L616)、[pity.py:623](gacha_simulator/core/pity.py#L623)）做条件分支，消耗次数随分支而定（guaranteed/readonly 时 0 次、`cr_base_rate` 命中 1 次、`state_prob ∈ (0,1)` 且命中 1 次）。`CRIntercept` 必须在**完全相同的条件与顺序**下消耗相同数量的随机数，否则固定种子抽卡轨迹即刻分叉、逐场快照不可能一致。实现为**单决策效果**：guaranteed 或 readonly 时不触发（返回 None 交 BaseRatio）；非 guaranteed 时按 cr_base_rate / cr_state_probs 判定，命中返回 ForceFeatured 分布、未命中返回 None。等价性测试必须含 `cr_state_probs` 含 (0,1) 中间值的用例（默认 `[0,0,0,1]` 无中间概率、不消耗随机数，会掩盖该风险）。

#### 3.1.4 骨架 EventDrivenBehavior

```python
class EventDrivenBehavior(PityBehavior):
    """通用事件驱动保底骨架——转移规则 + 概率效果双策略注入。"""
    def __init__(self, *, name, state, scope="ssr", btype,
                 transitions, effects,
                 flags=None, counters=None,
                 lifecycle=None):
        self._name = name; self._state = state; self._scope = scope
        self._btype = btype; self.is_event_driven = True
        self._transitions = transitions; self._effects = effects
        # 状态集合声明化——替换每类 self._guaranteed = Flag(...) 的重复
        self._flags = {f: Flag(state, name, f) for f, init in (flags or {}).items()}
        self._counters = {c: Counter(state, name, c) for c, init in (counters or {}).items()}
        for f, init in (flags or {}).items():
            if init: self._flags[f].set()
        for c, init in (counters or {}).items():
            if init: state.set(name, c, init)
        # 生命周期（deactivate_on_early_hit/depends_on 统一进骨架——P64 增量能力）
        self._lifecycle = lifecycle if lifecycle is not None else LifecycleConfig()
        self._active = Flag(state, name, "_active")
        if self._lifecycle.depends_on is None:
            self._active.set()

    def _rebind_state(self, state):          # P75 纪律——骨架统一实现
        self._state = state
        self._active = Flag(state, self._name, "_active")
        for f in self._flags:  self._flags[f] = Flag(state, self._name, f)
        for c in self._counters: self._counters[c] = Counter(state, self._name, c)

    def before_draw(self, ctx, readonly=False):
        if not self._active.is_set(): return ctx.current.copy()
        for eff in self._effects:
            out = eff.apply(ctx, self, readonly)
            if out is not None: ctx.current = out      # 链式应用（非短路）
        return ctx.current

    def after_draw(self, ctx):
        if not self._active.is_set(): return
        for rule in self._transitions:
            rule.apply(ctx, self)
        if self._lifecycle.deactivate_on_early_hit and self.did_fire(ctx):
            self._active.clear()                       # 增量能力（旧事件驱动类无）

    def did_fire(self, ctx):
        return any(rule.is_hit(ctx, self) for rule in self._transitions)

    # 槽位工具（收敛 4 处重复）——_scope_total_prob / _featured_slots / _is_trigger_rarity
```

**did_fire 门控语义（M4，强制）**：`EventRule.is_hit` 仅判 judge（is_featured / selected），**不含 trigger="scope" 门控**——与旧类 did_fire（[pity.py:543-544](gacha_simulator/core/pity.py#L543-L544)、[pity.py:641](gacha_simulator/core/pity.py#L641)、[pity.py:738](gacha_simulator/core/pity.py#L738)）「任意稀有度的 featured/selected 即 True」一致，避免改变 `PityEngine.after_draw` 的 depends_on 激活传播（[pity.py:1425-1427](gacha_simulator/core/pity.py#L1425-L1427)）。

**键集语义（L4，等价性前提）**：flags/counters 声明中的键**仅当初始值为 truthy 时才预建 state 键**（`if init: set()`）——与旧 `_build_pity_state_init`（[pity.py:1055-1091](gacha_simulator/core/pity.py#L1055-L1091)）在 guaranteed_init=False 时不预建 guaranteed 键的行为一致。这是「状态快照完全一致」验收的隐性前提，实现不得改动。

### 3.2 preset 映射（现有 6 类 → preset）

registry（[pity.py:751](gacha_simulator/core/pity.py#L751)）条目新增 `preset` 字段（工厂函数），`class` 字段对事件驱动型置空。`create_behavior` 检测 `entry.get("preset")` 走 preset 路径，否则走原类路径（counter 驱动型不变）。

```python
def _preset_rotating():
    return dict(
        transitions=[EventRule(trigger="scope", judge="featured",
                               hit=[ClearFlag("guaranteed")],
                               miss=[SetFlag("guaranteed")])],
        effects=[Effect("guaranteed", ForceFeatured(1.0)),
                 Effect(Always(), BaseRatio())],
        flags={"guaranteed": False},
    )
```

| 现有 type | preset 配置要点（含完整状态声明，H2 补全） |
|-----------|----------------|
| rotating | flags={"guaranteed": False}；转移：scope 出金 → featured 命中 clear(guaranteed) / 未命中 set(guaranteed)；效果：[guaranteed→ForceFeatured, Always→BaseRatio] |
| rotating_soft | rotating + counters={"counter": 0}；转移补**触发稀有度重置抽数 counter**（hit/miss 两分支都挂 `ResetCounter("counter")`，对齐 [pity.py:574-577](gacha_simulator/core/pity.py#L574-L577) `reward_rarity==scope` 即重置）；效果：[SoftBoost, guaranteed→ForceFeatured, Always→BaseRatio] |
| rotating_cr | rotating + counters={"cr_counter": 0}；转移补 **was_guaranteed 守卫**：仅在抽前 guaranteed 未置位时更新 cr_counter（hit: reset / miss: incr；大保底命中 cr_counter 不动，对齐 [pity.py:631-640](gacha_simulator/core/pity.py#L631-L640)）；效果：[guaranteed→ForceFeatured, CRIntercept, Always→BaseRatio] |
| rotating_cr_soft | rotating_cr + soft（含 counter 重置 + was_guaranteed 守卫） |
| targeted | flags={"guaranteed": False, "lost_rotating": False}；counters={"fate_points": 0, "losses": 0}；转移：scope 出金 → selected 命中 clear(guaranteed)+clear(lost_rotating)+reset(fate_points)+reset(losses) / 未命中 set(guaranteed)+set(lost_rotating)+incr(fate_points)+incr(losses)（**补全 losses/lost_rotating**，对齐 [pity.py:668-669](gacha_simulator/core/pity.py#L668-L669)、[pity.py:706-714](gacha_simulator/core/pity.py#L706-L714)）；效果：[Or(guaranteed, fate_ready)→ForceSelected, Always→BaseRatio] |
| targeted_soft | targeted + soft（含 counter 重置） |

`_btype` 保留，故 `_resolve_order`（[pity.py:984](gacha_simulator/core/pity.py#L984)）/ `_validate_behaviors`（[pity.py:1001](gacha_simulator/core/pity.py#L1001)）排序校验逻辑零改动。`params`/`ui_params` 保留，GUI 参数控件零改动。

### 3.3 G1 inverse preset（新增）

注册为 `rotating_inverse`（display_name「反向轮换保底（连中必歪）」）。`ForceNonFeatured(1.0)`：非 featured 槽位 = 1.0（featured = 0），复用 `_redistribute_scope` 的反向调用。

### 3.4 soft 效果化（阶段二）

`SoftBoost` 效果移植 [SoftStepBehavior._compute_probabilities](gacha_simulator/core/pity.py#L266-L329)（60 行复杂逻辑）+ `_cumulative_boost`（[pity.py:241](gacha_simulator/core/pity.py#L241)）。soft 的抽数 counter 由骨架 counters 声明，`SoftBoost.apply` 内部 `readonly` 用 `value()` 否则 `incr()`：

```python
class SoftBoost:
    def __init__(self, deltas, target_featured=False): ...
    def apply(self, ctx, bh, readonly):
        c = bh._counters["counter"]
        v = c.value() if readonly else c.incr()
        boost_pct = SoftBoost._cumulative_boost(self._deltas, v)
        if boost_pct <= 0: return ctx.current.copy()
        # ... 移植槽位分组 + 非目标概率抽取 + 目标槽位按基础权重分配 ...
```

`rotating_soft` preset = rotating 效果列表 `[SoftBoost, ForceFeatured, BaseRatio]`（顺序复现现有 mixin「先 soft 后事件」语义）。**效果链顺序 = 应用顺序**契约保证 soft × 事件组合等价。**deltas 展开职责移交（M6）**：`SoftPityMixin._init_soft_pity` 是当前唯一做 `soft_start/soft_end/soft_increment → deltas` 展开的地方（[pity.py:551-567](gacha_simulator/core/pity.py#L551-L567)），退役后该展开逻辑须移入 preset 工厂（依赖 create_behavior 已透传的 soft_* 参数，[pity.py:933-939](gacha_simulator/core/pity.py#L933-L939)）。3 个 `_soft` 类 + `SoftPityMixin` 一起退役。

### 3.5 生命周期统一（P64 增量能力）

`deactivate_on_early_hit` 目前只在 counter 驱动型（soft/hard 家族，[pity.py:333-339](gacha_simulator/core/pity.py#L333-L339)、[pity.py:448-456](gacha_simulator/core/pity.py#L448-L456)）实现，且 config_toml 对事件驱动型配置该参数直接抛 ConfigError（[config_toml.py:577-585](gacha_simulator/core/config_toml.py#L577-L585)）。P64 统一进骨架（§3.1.4 after_draw 尾部），使事件驱动型也可用。**必须同步移除 config_toml 的拒绝分支（H3）**，否则增量能力无法配置、验收用例无法构造。**此为增量能力（旧事件驱动类无此能力），不在等价性范围内**。覆盖手册 §16.6 终末地 80/120 协调「若 120 用 rotating 表达」的场景。

### 3.6 与引擎/配置/GUI 对接

- **PityEngine**（[pity.py:1206](gacha_simulator/core/pity.py#L1206)）：调度层接口签名不变，`before_draw`/`after_draw`/`get_probabilities` 调用链不变，P75 rebind 由骨架统一实现。**G5 priority**：`_resolve_order`（[pity.py:984](gacha_simulator/core/pity.py#L984)）排序 key 加 `priority` 优先级（位于稀有度 rank 之后、type order 之前）。**透传（M3）**：`PityDef` 新增 `priority: int = 0`，`create_behavior` 构造后设置 `behavior._priority` 属性（骨架与 counter 驱动类均带该属性，不改构造签名）——priority 全 0 时排序结果与现状完全一致（向后兼容），显式 priority 覆盖 type 顺序。**论证（2026-08-24 修正）**：当前 `_BTYPE_ORDER` hard=1 < targeted=3，绝区零福利保底（hard）本已先于 targeted；priority 的价值是「显式化现有隐式顺序 + 提供未来场景覆盖」，非新增所需
- **PityDef/TOML**：现有 type 名继续有效（preset 别名）；`rotating_inverse` 新 type 无需新字段；PityDef 参数透传（[pity.py:933-943](gacha_simulator/core/pity.py#L933-L943)）逻辑保留，目标从具体类变 preset 工厂
- **GUI config_panel**：保底 type 下拉自动读取 registry（出现 `rotating_inverse`）；reset 下拉加「永不重置」（G16）；priority 编辑控件（G5）；参数控件零改动
- **config/config.toml**：新增幻塔 `rotating_inverse` + G16 示例配置
- **GachaService 定轨识别（H1，强制）**：[gacha_service.py:155](gacha_simulator/service/gacha_service.py#L155) 用 `isinstance(bh, TargetedBehavior)` 识别定轨保底（`switch_epitomized_target`/`cancel_epitomized_path` 两条 NonDrawAction 流程）。targeted preset 化后 bh 变为 `EventDrivenBehavior` 实例，isinstance 恒 False → 定轨流程整体失效。须改为 `getattr(bh, '_btype', '') == 'targeted'`（或骨架加 `_is_targeted` 标记属性），波及范围表补 `service/gacha_service.py`

### 3.7 范围边界（不建模）

- **counter 驱动型（soft_step/hard）不进引擎**——它们已干净且与事件驱动正交，强塞进状态机是过度设计。**动态 threshold 扩展（G14 pity 层）**记为后续扩展方向（见 §1.3 关键洞察），本期不实施（G13 已 `counter_init=20` 配置即可，2026-08-24；G2 属 milestone 层动态 threshold，见 §1.3）
- **`switch_allowed`/`switch_resets_progress`（定轨切换规则）**属 GachaService 策略层职责（P56 NonDrawAction），切换逻辑 P64 不改；**定轨识别方式须适配 preset 化**（§3.6 H1，isinstance → `_btype` 判断），否则 P56 定轨流程失效
- **`type="custom"` 完全声明式 TOML 状态机不实现**（用户裁决，过度设计）——如需「组合内置片段」，在 preset 数据化之上小步扩展（阶段三预留，不承诺）

### 3.8 G16 独立先行（`reset="never"`）

幻塔「出金不重置」单行改动，**独立 commit 先行**，不并 P64 主线（counter 驱动型与事件驱动型正交，无冲突）：

```python
def _should_reset(self, ctx):                       # pity.py:204
    if self._reset == "featured":
        return ctx.draw.is_featured
    if self._reset == "never":
        return False                                # 新增：永不重置
    return ctx.draw.reward_rarity == self._reset
```

配套：PityDef/config_toml 的 reset 枚举加 `"never"`、GUI reset 下拉加「永不重置」、一条测试、手册 G16 从「待 P64」改「✅ 已覆盖」。
