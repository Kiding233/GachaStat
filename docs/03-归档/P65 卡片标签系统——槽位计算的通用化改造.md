# P65 卡片标签系统——卡牌多维属性与配置通用化

> 日期：2026-07-20 | 状态：设计中
> 依赖：P55 ✅ + P60 ✅（提供 DrawInfo / compute_scope_mappings / CardDef 基础设施）
> 与 P56 关系：正交——互不依赖。P56 的卡片级槽位（`ssr_featured:card_id`）由 P56 内置 `per_card_slots` 参数独立实现，不依赖标签系统。
> 相关决策：`is_limited()` 删除——P57 现场处理。`featured` 属池子级，不进入 CardDef.tags。

## 一、问题

当前卡牌只有单一 `rarity` 字段（`"ssr"` / `"sr"` / `"r"`），所有其他维度无处存储：

| # | 缺失能力 | 影响 |
|---|---------|------|
| 1 | **多维分组** | 无法按武器类型 / 元素 / 池子类别对卡牌分组——分析面板只能按稀有度看数据 |
| 2 | **跨卡引用** | 角色-武器配对（迪卢克↔狼末）无法建模——卡牌之间无法声明关联 |
| 3 | **策略 tag 筛选** | 策略无法表达「抽任意火系角色」——只能按稀有度选目标 |
| 4 | **`rarity` 硬编码为特殊字段** | 与 `featured`（池子级）/ `limited`（已删除）等概念缠绕——扩展新维度需改数据模型 |

本质：**稀有度以外的多维度属性应通过通用标签系统承载，而非硬编码字段。**

## 二、目标

| # | 交付 | 说明 |
|---|------|------|
| 1 | `CardDef.tags: Dict[str, str]` | 在 `rarity` 之外新增通用标签存储——`rarity` 保持独立字段（有运行时语义），其余维度进入 tags |
| 2 | TOML `[card.tags]` 解析 + round-trip | `rarity` 在卡片顶层（与当前一致），tags 作为可选子表——不存在 `[card.tags]` 的旧条目自动初始化为空 |
| 3 | `compute_scope_mappings` 无需改动 | `card.rarity` 字段直接读取——不做任何变更 |
| 4 | 运行时零改动 | `DrawInfo` / behavior / `_aggregate_probs_by_rarity` 完全不变 |
| 5 | 删除 `is_limited()` | P57 就地处理——不在全局层面定义「限定」概念 |

## 三、数据模型与配置

### 3.1 CardDefEntry 最终形态

> **类名说明：** 文档上下文中 `CardDef` 与 `CardDefEntry` 指同一概念——实际 dataclass 类名为 `CardDefEntry`（位于 `core/config_store.py`），文档为简洁起见使用 `CardDef` 作为口语缩写。本章使用正式类名以避免与步骤 1.1 的实现蓝图产生歧义。<!-- REVIEW-R1-FIX: ISSUE-017 -->

```python
@dataclass
class CardDefEntry:
    card_id: str
    name: str = ''                                                  # 显示名（独立）
    rarity: str = 'r'                                                # 稀有度（独立——有运行时语义）
    pools: List[str] = field(default_factory=list)                   # 所属池子——由引擎从池子分布反向推导，不在 TOML 中显式配置
    initial_count: int = 0                                           # 初始持有（独立——int 型模拟参数）
    tags: Dict[str, str] = field(default_factory=dict)               # 单值标签
    list_tags: Dict[str, List[str]] = field(default_factory=dict)     # 多值标签——如配对列表
```

**字段决策依据：**

| 字段 | 为何独立 | 为何不进入 tags |
|------|---------|----------------|
| `rarity` | 有运行时语义——参与 scope 匹配、保底触发、`rarity_rank` 排序 | 放入 tags 需 `@property` 代理且标签表需特殊行逻辑，独立字段更简单 |
| `name` | 显示元数据——引擎完全不读取 | 语义上不是属性：`tags["name"]` 读起来像「名字属性是钟离」 |
| `initial_count` | int 型模拟参数——影响 bonus 计算 | 放入 tags 需散落 `int(tags.get(...))` 类型转换 |
| `pools` | 引擎内部字段——由 `compute_scope_mappings` 从池子分布反向推导 | TOML 中不显式配置，不在用户可见范围内 |
| `featured` | 池子-卡片关系——属于 Reward 级别 | 不在卡片级定义 |
| `limited` | 已删除 | P57 就地处理 |

### 3.2 TOML 配置

**破坏性变更：** `[[cards]]` → `[[card]]`（段名单数化）、`id` → `card_id`（字段名统一）。不保留旧格式兼容路径——一次性手动升级。

```toml
[[card]]
card_id = "staff_of_homa"
name = "护摩之杖"
rarity = "ssr"
initial_count = 0

[card.tags]
card_type = "weapon"
weapon_type = "polearm"
element = "pyro"

[card.list_tags]
paired_characters = ["hu_tao", "zhongli"]
```

**tags 中的 key 分类：**

| tag key | 语义 | GUI 控件 | 可删除 |
|---------|------|---------|:---:|
| `card_type` | 卡牌类型 | 可编辑 QComboBox（推荐 `character` / `weapon` + 自由输入） | 否 |
| 其他任意 key | 自定义（单值） | QLineEdit 自由输入 | 是 |
| 任意 key（`list_tags`） | 自定义（多值） | QLineEdit，同一 Key 可多行 | 是 |

所有 tag 均为纯元数据——**新增维度不需要改任何代码**，在 TOML 的 `[card.tags]` 中加一行即可。

> **旧格式风险：** 若用户以旧格式 TOML（`[[cards]]` + `id`）启动，`_build_cards()` 将读取到空列表，触发保存后会静默擦除全部卡片数据。阶段二步骤 2.4 增加了防御性 `ConfigError` 阻断。`_migrated_from_legacy` 标记语义不变——仍仅覆盖保底配置迁移。<!-- REVIEW-R1-FIX: ISSUE-003 -->

- 「添加」：创建空卡片 → `card_id = card_N`、`rarity = 'r'` → 追加到列表 → 自动选中
- 「移除选中」：`pop(data)` + `takeItem(row)` → 清空详情面板 → 选相邻项

**控件规范：**

| 字段 | 控件 | 可编辑 | 说明 |
|------|------|:---:|------|
| `card_id` | QLineEdit | 是 | 自由文本 |
| `name` | QLineEdit | 是 | 自由文本 |
| `rarity` | QComboBox（不可编辑） | 否 | 选项从 `ConfigStore.rarity_rank` 动态读取。新增稀有度需先在 `[rarities].ranks` 声明 |
| `initial_count` | QSpinBox（0~9999） | 是 | 整数值 |
| `card_type` 的 Key | QLineEdit（只读） | 否 | 固定为 `card_type`，不可删除 |
| `card_type` 的 Value | QComboBox（可编辑） | 是 | 下拉选项 `['', 'character', 'weapon']`（空字符串=未设置）。`setCurrentText(tags.get('card_type', ''))` 初始化，支持下拉列表外的自由输入值（如 `material`）。保存时空值过滤不写出。<!-- REVIEW-R1-FIX: ISSUE-004 REVIEW-R1-FIX: ISSUE-008 --> |
| 其余标签 Key | QLineEdit | 是 | 自由文本，**单值表内不可重复**（见下） |
| 其余标签 Value | QLineEdit | 是 | 自由文本 |
| 多值标签 Key/Value | QLineEdit | 是 | 同名 Key 允许多行 |
| 所属池子 | QLabel（只读） | 否 | 从池子分布自动推导 |

**Key 唯一性校验**（仅单值标签表）：

连接 `QTableWidget.cellChanged(int row, int col)` 信号，编辑 Key 列（col=0）时触发：

1. 空文本 → 放行（未填写）
2. `card_type` → `QMessageBox.warning("系统保留", "'card_type' 是系统标签，不可自定义。")` → 清空格子
3. 已有相同 Key → `QMessageBox.warning("重复标签", "标签 Key 'xxx' 已存在。如需修改，请直接编辑现有行。")` → 清空格子
4. 新 Key → 放行

多值标签表不做此校验——同名 Key 多种值是正常用法。

**详情→数据的回写时机：** 不设「应用修改」按钮——`card_id`/`name`/`rarity`/`initial_count` 的 `textChanged`/`currentIndexChanged`/`valueChanged` 信号直接连接回写。标签表通过 `cellChanged` 回写。用户在左边切换卡片时，先 `_flush_current_detail()` 保存当前编辑。

### 阶段二：TOML 解析与 round-trip（~40 行）

**文件：** `core/config_toml.py`

#### 步骤 2.1 —— `_build_cards()` 改造

**前置：** `config_toml.py` 当前导入 `math` + `typing` + `tomllib` + `.config_store`，未导入 `warnings`。`_warn_cross_table_keys()` 需调用 `warnings.warn()`，因此在现有导入后追加 `import warnings`。<!-- REVIEW-R1-FIX: ISSUE-020 -->

定位 `_build_cards()`（约第 342 行）。改为读取 `[[card]]`（单数）和 `card_id`：

```python
def _build_cards(data: dict, store: ConfigStore) -> None:
    """[[card]] → store.card_defs"""
    for c in data.get('card', []):
        # ── 顶层字段 ──
        card_id = c['card_id']
        name = c.get('name', card_id)
        rarity = c.get('rarity', 'r')
        ic = c.get('initial_count', 0)

        # ── 标签 ──
        tags = dict(c.get('tags', {}))          # TOML [card.tags] → Dict[str, str]
        list_tags = {}
        raw_lt = c.get('list_tags', {})
        for k, v in raw_lt.items():
            if isinstance(v, list):
                list_tags[k] = [str(x) for x in v]
            else:
                list_tags[k] = [str(v)]          # 单值自动包装为列表

        store.card_defs.append(CardDefEntry(
            card_id=card_id,
            name=name,
            rarity=rarity,
            initial_count=ic,
            tags=tags,
            list_tags=list_tags,
        ))
```

**`tags` 与 `list_tags` 同名 key 交叉校验：** TOML 解析器天然禁止同一子表内重复 key，但 `[card.tags]` 和 `[card.list_tags]` 是不同子表——允许在两个子表中分别写入同名 key。例如 `[card.tags]` 中 `card_type = "weapon"` 同时 `[card.list_tags]` 中 `card_type = ["polearm"]`，加载后 `tags['card_type']='weapon'` 和 `list_tags['card_type']=['polearm']` 同时存在——下游代码行为不一致。解决方案：在 `_build_cards()` 中构建 tags/list_tags 后增加 `_warn_cross_table_keys()` 辅助函数，检测同名 key 并发出 `warnings.warn()`（不阻断加载，以单值 `tags` 为准，不删除多值表中冲突 key，由用户自行裁决）。检测逻辑：`set(tags.keys()) & set(list_tags.keys())`。空字符串 key 需 `discard('')` 排除。<!-- REVIEW-R1-FIX: ISSUE-015 -->

#### 步骤 2.4 —— 旧格式防御性检测（阻断静默数据丢失）<!-- REVIEW-R1-FIX: ISSUE-003 -->

**风险：** 用户以旧格式 `config.toml`（`[[cards]]` + `id` 字段）启动 GUI，`_build_cards()` 读取 `data.get('card', [])` 得到空列表。用户在 GUI 中触发任意保存后，`save_toml` 写出 `data['card'] = []`，原 `[[cards]]` 段全部卡牌数据丢失且不可恢复。

**<!-- REVIEW-R1-FIX: ISSUE-009 -->防御策略：** 两阶段检测。阶段一（段名级）：在 `load_toml()` 入口处增加检测——若 `data` 中存在 `'cards'` 键（旧格式段名）但不存在 `'card'` 键（新格式段名），抛出 `ConfigError` 并提示用户手动升级。若两键同时存在，也抛出 `ConfigError`（歧义）。阶段二（字段级）：遍历 `data.get('card', [])` 各条目，检测两种错误——①条目含 `id` 键但缺 `card_id` 键（用户将 `[[cards]]` 改为 `[[card]]` 后忘记改字段名），②条目同时含 `id` 和 `card_id` 键（用户新增 `card_id` 后忘记删除旧 `id`——歧义场景，`card_id` 优先但旧值被静默忽略会致用户困惑）<!-- REVIEW-R1-FIX: ISSUE-014 -->。均抛出 `ConfigError` 明确提示。两阶段检测集中在 `_check_card_format()` 和 `_check_card_fields()` 中，避免 `_build_cards()` 中出现晦涩的 `KeyError: 'card_id'`。

```python
# load_toml() 中 _build_cards() 调用前插入
def _check_card_format(data: dict) -> None:
    has_old = bool(data.get('cards'))      # 旧格式 [[cards]]
    has_new = bool(data.get('card'))       # 新格式 [[card]]
    if has_old and not has_new:
        raise ConfigError(
            "检测到旧格式卡片段（[[cards]]）。P65 已将段名改为 [[card]]、"
            "字段名 id 改为 card_id。请手动升级 config.toml：\n"
            "  1. 将所有 [[cards]] 改为 [[card]]\n"
            "  2. 将每个卡片条目中的 id = \"...\" 改为 card_id = \"...\"\n"
            "详情参见 docs/01-活跃/subsystems/保底系统/P65 卡片标签系统——槽位计算的通用化改造.md"
        )
    if has_old and has_new:
        raise ConfigError(
            "config.toml 同时包含 [[cards]]（旧格式）和 [[card]]（新格式）段。"
            "请移除 [[cards]] 段，仅保留 [[card]] 段。"
        )
```

```python
def _on_tag_cell_changed(self, row: int, col: int):
    """单值标签表 Key 列编辑完成 → 校验唯一性"""
    if col != 0:
        return
    item = self._card_tags_table.item(row, 0)
    if not item:

    if not key:
```

#### 步骤 4.4b —— 跨表 Key 冲突检测（回写时）<!-- REVIEW-R1-FIX: ISSUE-005 -->

`_read_tags_from_table()` 和 `_read_list_tags_from_table()` 分别读取单值表和多值表后，在 `_flush_current_detail()` 回写前增加交叉校验：若同一 key 同时出现在两个表中，以单值表为准，弹出警告提示用户。

```python
def _validate_cross_table_keys(self, tags: dict, list_tags: dict) -> bool:
    """检查单值标签表和多值标签表是否有同名 Key，返回是否有冲突"""
    overlap = set(tags.keys()) & set(list_tags.keys())
    overlap.discard('')  # 排除空字符串 key
    if overlap:
        QMessageBox.warning(self, "标签冲突",
            f"以下 Key 同时出现在单值标签和多值标签表中：{', '.join(sorted(overlap))}\n"
            f"将以单值标签表为准，多值表中对应的 Key 将被忽略。")
        return True
    return False
```

调用位置：`_flush_current_detail()` 中，先调 `_read_tags_from_table()` 和 `_read_list_tags_from_table()`，再调此校验，若返回 True 则从 `list_tags` 中删除冲突 key。

> **说明：** TOML 不同子表间允许同名 key（`[card.tags]` 和 `[card.list_tags]` 是独立子表，含相同 key 时 TOML 解析器不会报错）。TOML 直接编辑场景由步骤 2.1 的 `_warn_cross_table_keys()` 以 warning 方式处理。此处的 `_validate_cross_table_keys()` 仅针对 GUI 中两个独立 QTableWidget 之间的同名 key 冲突——以单值表为准并弹窗警告。<!-- REVIEW-R1-FIX: ISSUE-015 -->
