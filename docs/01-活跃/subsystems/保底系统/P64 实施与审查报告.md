- **`priority` 的排序方向**：计划只写了排序键的**插入位置**（rank 之后、type order 之前），未写方向。本块取「**数值大者先执行**」（键取 `-priority`）。依据：字段名是 `priority`（优先级），且手册 `主流抽卡游戏卡池机制配置转换手册.md:560` 把这个需求写作「福利保底和常规保底的**优先级**交互」、期望是「`hard` 先于 `targeted`」，即优先级高者先执行。两种方向下「全 0 时与现状完全一致」都成立，故该取向不引入回归。**若你要的是「数值小者先执行」，说一声即可，改动是把 `-priority` 的负号去掉（一处 + 对应断言的方向）。**

### S6b 审查登记的其余三项
- **`priority` 的量程与解析校验不对称**：GUI 量程 `-999..999`，而 `config_toml` 解析侧对 `priority` 无类型/范围校验（`config_store.py` 的 `priority: int = 0` 也无约束）。后果：TOML 写 `priority = 5000` 经「GUI 打开 → 保存」被静默夹成 999；写 `priority = 1.5`（float）会让 GUI 进程终止（`QSpinBox.setValue(float)` 抛 TypeError 于 Qt 槽内、无 Python traceback），后者与 `counter_init` / `fate_points_init` 同形的既有全局面。若要收口，正解是量程与解析白名单取同一常量。
- **`_apply_pity_edit` 的 `priority` 写回是冗余的**：`valueChanged` 的 flush 已把值写入 `_pity_defs`，该处再写一次。删掉它无功能后果，与 `set_config` 的 `_pity_defs` 字段表同类（登记为空转，不为它编造用例）。
- **`_apply_non_draw` 取池内第一条 `targeted`，落点会随 `priority` 变化**（**本条曾被我据实施者之说撤销，已由 S6c 审查恢复并订正机制**）：机制不是「同 scope 双 targeted」（那确实不可构造，规则 3 恒抛 `ConfigError`），而是**同 rank 跨 scope**：`[rarities].ranks` 是分层列表，一层可多名并取同一 rank，规则 3 只禁同 scope，故两条不同 scope 的 targeted 可落同一 rank；此时排序键退到 `-priority` 比较，`priority` 翻转池内序即翻转选靶，`selected_card` 落进另一个命名空间。已由 `test_same_rank_cross_scope_targeted_priority_flips_target` 钉住现状（钉行为、不主张它是缺陷）。**S7c 文档同步或 GUI 提示宜点明「改 priority 可能换掉定轨写入的命名空间」。**
- **`_apply_non_draw` 未覆盖分支清单（经 S6c 审查补全）**：`:254` 未注册 `action_id` / `:257` 缺 `pool_id` / `:269` 未注册池子 / `:295` 卡不在 `epitomizable_cards` / `:298` `switch_allowed=False`（实施者自报五条，准确），**另漏**：`:288`「未配置 targeted 保底」（正是判据回退变异实际触发的那个分支）、`:292` 缺 `card_id`、`:262` / `:267` 两条正向分支。**另记一条当前不可达的陷阱**：`:289` / `:302` 的 `if/elif` **无 else**，将来注册第三个 non_draw `action_id` 时会通过前置校验后**静默 no-op**。
