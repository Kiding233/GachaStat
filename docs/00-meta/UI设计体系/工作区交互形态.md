## 三、工作区树

### 3.1 没有文件夹层级

一级配置节点直接是工作区的顶层条目，树的根就是工作区本身。

**依据**：`信息架构梳理.md` v2 的「工作区 = 文件夹树」把 folder 定为一等对象（用户文件夹、配置与数据组）。用户 2026-10-06 裁决取消这一层。P87 §3.11 F 也已把搜索产物定成「派生批次标记」而不是实体文件夹，方向一致。

**连带**：节点类型只剩三种加一个视图节点（见 §3.3）；`subjectKind` 不再有 folder 分支。

### 3.2 节点类型用形状而非只用颜色区分

| 类型 | 形状 | 颜色 |
|------|------|------|
| 一级配置节点 | 圆 | 绿 |
| 子配置 | 方 | 蓝 |
| 数据集 | 菱形 | 青（单值产物为橙） |
| 批次 | 三角 | 紫 |
| 对比任务 | 右向三角 | 青 |

**依据**：用户 2026-10-06 指出「不同类型节点不仅要用颜色区分，形状也应该不一样，不应都是圆角矩形」。形状是比颜色更强的区分手段，也对色觉障碍友好。

**注**：`信息架构梳理.md` §七 的「文件夹脸 vs 文件脸」方案随 §3.1 一并作废（无文件夹）。

### 3.3 批次是折叠视图，不是实体

批次节点是 P87 §3.11 F2「派生批次标记」的渲染形式：同批次即一组，树上折叠成组，展开后是成员。它有自己的详情页，渲染的是**任务记录**（`tasks/<task-id>.json`，P87 §3.11 F 已定为独立实体），不是新造的实体。

这与 P87 §3.6「树是视图」不冲突：「组是查询而非实体」约束的是**数据模型**（不落 `groups.json`），不是渲染。P87 已否决的 F1（任务节点）是另一回事，它让产物挂到任务之下、动了归属规则。

## 四、详情页

### 4.1 配置详情按 tag 组织，与 GUI 一致

十一个标签页，与 `gui/config_panel.py` 的 `left_tabs` **同名同序**：

```
卡牌定义 / 资源定义 / 资源获取 / 卡池管理 / 保底机制 / 累抽奖励 /
抽卡策略 / 停止条件 / 目标卡 / 权重配置 / 满突溢出
```

其中「卡池管理」下再套二级标签页「池 / 生命周期」，对应 `config_panel.py` 的 `pool_sub_tabs`。

**二级标签的样式（2026-10-08 定）**：一级定为卡片式（有边框、相邻共边、选中项白底并与下方内容连体）之后，二级采用**一级同款缩小**：同边框、同圆角、同步共边，只把内边距与字号调小一号（一级 `5px 10px` / 12px，二级 `4px 9px` / 11px）。

两个要点：

- **共边必须一致**。`gap` 要为 0；留 6px 间隙会把共边拆开，一二级就不再是同一族。
- **同族的代价要认**：层级线索只剩「更小一号」这一条，两者靠近时可能看串。之所以接受：二级标签只在需要时才出现（见下），且一级与二级的**位置**本身就不同（二级在内容区之内），位置线索与尺寸线索叠加已经够用，不必再引入第二种形状语言。

对照页 `tabs_showcase.html` 里列了七种候选（换形状的 A–E、同族缩小的 F/G）与各自的取舍，选定的是 F。

**为什么二级标签是必要的（不是为过程分析发明的）**：见 §5.7 末段。

**依据**：用户 2026-10-06 要求「配置还应该是与 gui 的相对一致，按 tag 组织」。这同时保证迁移期两侧心智一致。

### 4.2 详情页是可编辑页，不是只读页

页头含：名称、文件态标签（未保存 / 已保存 / 已冻结 / 已派生新配置）、保存、另存为、复制为一级配置节点。

**依据**：P87 §3.10 ② 已定「改 → 存 → 跑」，保存是用户可感知动作；§3.10 已定配置一经跑过即冻结，保存会派生新配置文件。所以详情页必然带状态机，不是纯展示。

### 4.3 数据集详情只读

只展示元信息与运行记录。数据集节点**不能**被设为分析锚点（见 §5.1）。

## 五、分析页

### 5.1 锚点是一级配置节点

分析面板锚定在某个**一级配置节点**上，不是锚定在数据集上，也不是每个数据集挂一个分析条目。

- 选中该一级配置节点的**整个子树内**任何节点（含节点本人、任意深度的子配置、数据集、批次），锚点都不变，分析面板不发生变化。
- 在左侧换到**另一个一级配置节点**时才换锚点。
- 子配置与其数据集**不能**作为锚点，因此不能对它们套用一般分析方法。

**依据**：用户 2026-10-06 裁决，理由是「子配置往往样本量不足、可能不跑流式分析、且要切数据集才能看最差影响这类结果，统一禁止以保持与 GUI 的操作逻辑一致」。

**取代**：`信息架构梳理.md` §4.2 的「统计分析条目」（挂在数据集下的幽灵条目、hover 数据集创建）。该模型是「一个数据集一个分析入口」，与锚定配置模型不兼容。

**保留的一处**：锚定不解决数据装载问题。同一份合法数据集内部仍会有单项缺字段（`gui/analysis_panel.py:1343` 起：转变分析需要池结束时间，为空则跳过），所以**项级能力检测仍需存在**，对应 P86 §3.2 的 `requires` 声明。选择器层过滤与项级检测是两层，都要有。

### 5.2 数据集选择器按可分析性过滤

分析页顶部常驻「当前数据集」选择器（**单选**；多数据集的情形走「对比任务」锚点，见 §5.3）。候选集 = 该锚点子树内**能被普通分析消费**的数据集，判据 = 样本数 > 1 且跑过流式分析。被排除的（基线的单值产物、未跑流式的派发产物）列在选择器下方并注明原因。

**依据**：用户 2026-10-06 指出「根据我说的子数据集用户在面板里不可能切到它、点 GDR分布」。可用性过滤放在选择器这一层，使该失败路径由构造排除。

### 5.3 比较分析复用同一套页面骨架

对比任务也可作锚点。进分析模式后页面骨架与一般分析一致（顶栏 + 专题标签 + 左栏方法清单 + 右栏结果区），只是专题集合不同：只有比较方法（随机占优 / 分布对比）。

**依据**：P86 §3.1 已定 `comparison_analyzer.py` 留在 core，进 `service/analysis/` 的只是编排。

### 5.4 模式不因点选而退出

在一级配置节点之间、以及在配置与对比任务之间点选切换时，分析模式保持，只换内容，不弹回详情。

**依据**：用户 2026-10-06 指出「切换时分析页面不应该弹回应该直接切换内容」。实现上「能否进分析模式」由统一判据（一级配置子树 或 对比任务）决定，锚点消失不再强制退出。

### 5.5 需要派发模拟的分析在分析页内发起

派发型分析的发起入口在分析页内、各自所属专题的结果块里，**不在工具栏**。它们与即时分析项在同一份方法清单中并列，但形态不同：异步提交任务、可取消，结果块内给的是「发起」按钮与产出说明，而不是现成的图表。

按 §5.7 的专题划分，派发型方法分布为：**方案搜索**（方案搜索专题）、**敏感性扫描**（敏感性分析专题）、**最差影响分析**（最差影响专题）。

**依据**：用户 2026-10-06 要求「参考 gui 的设计完全放在分析页面里面」。GUI 里方案搜索、最差影响、敏感度分析都是独立 Tab，各有自己的参数表单与运行按钮。

**取代**：一度把三者收进一个「模拟派发」页签的做法。那个划分是按「操作形态」分类，与其余按「分析专题」分类的页签混在一层，于是同一专题会被拆散（最差影响与最差情形分居两处），而不相干的却被并在一起。

### 5.6 分析参数表单由声明生成

分析项的参数表单**不手写**，由 `AnalysisSpec.params`（`ParamDescriptor` 列表）自动生成（P86 §3.2、§3.6 精化一；`gui/param_renderer.py` 已支持从声明生成控件并回收值）。

前端流程三步，两个前端完全一致：

1. **取默认**：调 `defaults(dataset_id, key)`，拿到一份完整参数表（分析项声明的默认值 + 从数据集换算的配置参数，如目标卡与权重）
2. **表单改**：把第 1 步的值填进自动生成的控件，用户改
3. **提交**：控件收回成一个 dict，调 `run(dataset_id, key, params)`

### 5.7 分析页按专题组织，十一个专题

分析页的标签行是**专题**，不是「统计分析」面板下的那五个分类。原先的划分把不相干的方法挤在同一格里：风险分析一格装着 VaR/CVaR、最差情形、最好情形、条件分布、脆弱性五种；另有一个「模拟派发」格把最差影响、方案搜索、敏感性三件不相干的事凑在一起。

现按专题拆开，并**把 GUI 里原本各自独立成面板的都收进同一层**：

```
全局GDR分析 / 成功率分析 / 风险分析 / 时间演化 / 每池分析 / 脆弱性分析 /
过程分析 / 最差影响 / 间隔分析（构思中）/ 方案搜索 / 敏感性分析
```

各专题的方法如下（● 为该专题的主方法，见 §5.8）：

| 专题 | 方法 |
|---|---|
| 全局GDR分析 | ●GDR 分布 · GDR 指标统计 · GDR 指标相关性 |
| 成功率分析 | ●成功率分析 |
| 风险分析 | ●VaR / CVaR · 最差情形分析 · 最好情形分析 · 条件分布 |
| 时间演化 | ●GDR 时间序列 · 时间-GDR 热力图 · 抽卡数-达成率散点 · 3D 瀑布图 · 2D 压缩瀑布图 |
| 每池分析 | ●每池抽卡数 · 每池目标卡数 · 每池保底数 · 截止每 banner 的 GDR 分布 · 转变分析 |
| 脆弱性分析 | ●脆弱性分析 |
| 过程分析 | ●事件统计 · 成败统计 · 事件→成败 · 成败→事件 · 轨迹详情 |
| 最差影响 | ●最差影响分析（派发） |
| 间隔分析 | 构思中，见下 |
| 方案搜索 | ●方案搜索（派发） |
| 敏感性分析 | ●敏感性扫描（派发） |

**两处归属特意纠正过**：

- 「最差情形分析 / 最好情形分析」属于**风险分析**（`gui/analysis_panel.py` 的 `ANALYSIS_CATEGORIES` 即如此），**不属于**「最差影响」。
- 「最差影响」是独立面板（`gui/worst_impact_panel.py`），做的是「后续池子上线后大保底的资源够不够覆盖」，与最差/最好情形不是一回事，不要去合并。

**命名待办**：本表用「全局GDR分析」（用户 2026-10-08 命名），而 GUI 现名是「总体广义出率分析」。接线时需要择一。

**「间隔分析」是出卡间隔分析**（两次出货之间间隔了多少抽 / 多少天），用户 2026-10-08 给出含义，但**尚无实现，仍是构思**。落地前需要先定义：间隔按抽数还是天数计、跨池如何计算、模拟结束仍未出货算不算一段。

**为什么二级标签是必要的**：此处十一个专题用的是**一级**标签，而配置页的十一个 tag 也是**一级**标签，两者在界面上从不同屏出现，所以这一层不需要二级。二级标签的需求来自另外两处：配置页「卡池管理」内的「池 / 生命周期」，以及分析页里结果块数随数据增长的方法（§5.9）。也就是说，二级标签不是为某个页面发明的机制，而是「同一层里还要再分一次」时才出现。

### 5.8 分析项可多选，参数在各自结果块内

左栏的方法清单用**勾选框**决定哪些方法出结果，选中的在右栏**依序堆叠**；默认勾上该专题的主方法。全部取消时右栏给空态提示，不静默留白。

三件事要分清：

| | 含义 | 形态 |
|---|---|---|
| 勾选框 | 看不看这个方法的**结果** | 方框，可多选 |
| ● / ○ | 这个方法在该专题里**主不主** | 实心 / 空心圆点 |
| 即时 / 派发 | 操作**形态** | 文字徽标（§5.5） |

主次与多选是两件事：主方法默认被勾上，但仍可取消；附属方法默认不勾，勾了也会排在主方法之后（顺序按专题内的方法定义序）。

**参数放在各自的结果块内，不放左栏**。理由：多选时每个方法各有自己的参数集，左栏只有一列，只能显示其中一份。放到各自的块内，「参数 — 结果」的成对关系也不会因为多选而错位。

**依据**：用户 2026-10-08「分析项选择不大对，至少是可多选吧」。参数位置是在改多选时一并下沉的，原来的单栏参数区随之取消。

### 5.9 结果块数随数据增长的方法：总览常驻 + 逐项下钻

多数分析项的结果是**固定块数**（一个图、或一个图加一张表），堆叠即可。**脆弱性分析不是**：它的结果构成是

```
脆弱性总览（1 块，恒定）+ 各池资源分布总览（1 块）+ 每池（脆弱区间表 + PAVA 组合图）
```

即 **2 + 2×池数**。样例配置 8 个池只是下限，实测配置可到十几个至几十个池，于是 3 池 8 块、5 池 12 块、24 池 50 块。这种量级下，平铺成一长条或铺成一排标签都不成立。

做法（脆弱性分析专用，不是通用机制）：

- **总览常驻**，不折叠、不随下钻切换。它承载「一眼看全所有池」：横轴为资源剩余，每个池一行分布，浅红带标脆弱区间、红虚线标均值、绿点标不抽卡基线。
- **总览本身就是选择器**，每行可点。**不要另设一个池选择器**：池子在两处各列一遍，到几十个池时是荒唐的重复。
- **山脊区限高、内部滚动**，池数再涨也不把页面其余部分顶掉。横轴用百分比配 `preserveAspectRatio="none"` 拉伸到容器宽，图内不放文字，所以拉伸不扭曲字形；池名与轴标走 HTML。
- 顶部给**摘要**（池总数 / 检出脆弱的池数）与**筛选**（只看检出脆弱的）。这是「一眼看到重点」的落点：几十个池时「全部」不可能真的一眼看完，必须让读者能主动收敛。
- 筛选把当前选中的池藏起来时，**自动改选筛后第一行**，避免「筛选说只看脆弱的，下方详情却是无脆弱池」。

**依据**：用户 2026-10-08 指出「真实的配置可能有十几个到几十个池子」，以及同日的「避免纵向堆叠、各带小节标题这种需要滚动的、重点不清晰的方式」「应该让人一眼能够看到所有重要部分和重要信息」。后者全盘接受，前者正是它在该场景下的落法：不是靠堆叠，而是靠「常驻的总览 + 收敛的筛选 + 单块下钻」。

**这决定了界面上不再需要「权重配置」这类共享设置页**。目标卡与权重是**配置参数**（P86 `01-理论.md` §1.1），它们出现在分析界面的原因是「本次分析要按什么口径读」，默认值从数据集指向的配置换算，可在本次分析里覆盖。配置面板那个「权重配置」tab 管的是**产生数据**用的那份，两处职责不同。

**参数分三类的界面含义**（判据见 P86 `01-理论.md` §一）：

| 类 | 界面上住哪 |
|---|---|
| 配置参数 | 配置面板（含目标卡、权重） |
| 分析方法本身的参数 | 分析项的参数区，由声明生成 |
| 界面状态与偏好 | 不进参数表单；工作区级的落 `workspace.json` 的 `prefs` 块 |

**「控制显示哪些指标」不做成参数**，它是工作区级偏好。分析页的指标下拉框按 `prefs` 过滤，候选集本身每次派生。

## 六、切换机制、运行模拟、任务管理

### 6.1 两页与道

| 项 | 值 |
|---|---|
| 详情页 | 固定不动（实测展开收起时左缘坐标不变） |
| 分析窗 | `translateX(calc(100% - 34px))` → `0`，`.34s cubic-bezier(.25,.8,.35,1)` |
| 道 | 宽 34px，整高；详情态贴工作台右端，分析态贴左端（它就是分析窗的左边缘） |
| 道配色 | `#eef1f5` 底 / `#5a6272` 文字（无色系，颜色在本项目留给语义） |
| 道的箭头 | 用 SVG 画，不用 CJK 的「》」字形 |

**箭头为什么用 SVG**：CJK 的「》」墨迹在字身框里偏一侧，实测箭头墨迹中心与竖排文字中心差 13px；SVG 的墨迹边界即元素边界，改后箭头、竖排文字、道三者同轴（实测三者的 box 中心均为 page x 359.67）。

**边距随道走**：详情页留右 46px（道在右端），分析窗留左 46px（道在左端）。给分析窗留右 46px 是错的，那 46px 会被白留。

**层叠必须显式**：两页都要给 `z-index`（详情 1 / 分析 2）。分析窗带 `transform` 会自建层叠上下文，与详情页都取 `z-index: auto` 时相对层序落到 UA 默认判定上，实测会出现两页互相透出（配置页的表格与标签页压在分析内容之上）。命中测试不能用来判断视觉层序，只有截图能。

### 6.2 工具栏与道并存

工具栏的「切换到分析 / 详情」按钮与道同时存在，两者都能切换。

### 6.3 运行模拟：分体按钮 + 参数浮层

```
[ 运行模拟：<配置名> | ▾ ]
```

- 主按钮：用当前参数直接派发
- 右箭头：开参数浮层（模拟次数 / 随机种子（-1 = 随机）/ 并行进程数）
- 浮层右缘与按钮右缘对齐，上方留 6px，入场自上而下 `.18s`
- 该配置已有运行中任务时，按钮转「运行中」并禁用（防重复提交）

**为什么是这个形式**：

1. 运行参数只有三个（GUI 批量模拟面板的「模拟参数」组与 WebUI 新建任务对话框都是这三个），不需要一整块表面；
2. 它必须与「跑哪个配置」绑定，而配置来自树选中，所以入口只能是上下文按钮；
3. 它是**一次性**的、不进配置身份（P87 §3.1），所以不该落进配置文件，也不该出现在配置详情页里。

**浮层里要落的两条 P87 语义**：

- 运行参数不进入配置身份（§3.1），改它不产生新配置
- 同配置同参数重复跑是新建数据集（§3.12 O18），提示「已跑过 N 次」

**运行按钮的门控**：只对一级配置节点开放（子配置的模拟由分析面板派发）；配置未保存时禁用（P87 §3.10 ②）。

**「运行」统一为「提交任务」**（P87 §3.11 J4）：派发后进任务队列，不在原地等结果。

### 6.4 任务管理：顶部抽屉

从工作台顶部下滑的抽屉，覆盖在右页之上，不替换任何页面。

- 标题行：任务管理、运行中计数、运行对象、收合提示
- 左：任务队列。列与 WebUI 的 `RunWorkbench` 对齐：任务（名 · 所属配置）/ 类型（搜索 / 模拟）/ 状态（完成 / 失败 / 运行中 / 排队，失败带原因 tooltip）/ 进度 / 耗时(s) / 操作（取消 / 查看）
- 运行中任务的耗时按 `startTime` 实时计算
- 右：资源监控。CPU%、内存%、并行 worker。worker 的算法与后端一致：**运行中任务声明的并行数之和 / 逻辑核数**，不是任务计数
- 收合：再点工具栏「任务管理」按钮，或点抽屉下方任意处（标准 popover 行为，该次点击不穿透到下面内容）

**为什么不用独立页或弹窗**：

- 独立页会与「详情 / 分析」争同一块内容区，成为第三个并列状态，于是必须加一条「点树即离开任务管理」的特例规则；且退出路径不明确。
- 弹窗是模态的，打开时不能操作底下，与「边跑边看分析」冲突。
- 抽屉方向与「分析窗左右滑」正交，语义不打架；打开时不占导航状态。

**未含「新建任务」对话框**：WebUI 的 `RunWorkbench` 有这个入口（在对话框里重选运行对象 + 参数）。本设计里派发入口在分析面板内与工具栏的运行按钮上，任务管理器只做监控与取消 / 查看，不再问一遍运行对象。

**已知实现坑**：抽屉关闭时只用 `translateY(-101%)` 藏不住阴影（`0 12px 26px` 的下缘比那一层位移更长），会从工作台上沿漏出一条常态阴影。关闭态必须把阴影也收掉。

### 6.5 动画的适用范围

面板级切换有动画（分析窗滑入、抽屉下滑、浮层自上而下）。这一点与 `信息架构梳理.md` §七「无内容切换动画」相反，按用户 2026-10-06 的要求改。

### 9.1 探针的纪律（2026-10-08 加）

裁决在接线前只以探针形态存在，**探针就是唯一可看的证据**，所以探针本身必须可信。两条硬要求，都是踩着事故加的：

- **依赖本地化，不许依赖 CDN。** 出过一次真事故：探针从 cdnjs 取 Vue + Element Plus，CDN 一抖动两个库都没加载，整个应用退化成裸模板，表现为工具栏显示 `{{ mode==='analysis' ? ... }}`、文件树一个节点都没有、对比任务显示 `{{ c.label }}`，而界面上毫无提示，看起来就是应用坏了。依赖现放在 `tools/poc_webview/layout_demo/libs/`，版本钉死（Vue 3.5.13 + Element Plus 2.9.1，外观是按这两个版本验过的，换小版本会动样式）。项目里 `echarts.min.js` / `plotly.min.js` 本来就在仓库中，这是既有做法。
- **改完必须验渲染，且验证在强制离线条件下做。** `tools/poc_webview/layout_demo/shot.py` 已拦掉所有非 `file://` 请求。这个技术栈的失败大多是**静默**的，不会报错：自闭合的自定义标签会吃掉整棵子树（曾导致右侧面板全空）、`viewBox` 被 HTML 解析器小写成 `viewbox` 会让图标按原始坐标画进小框里被裁掉、模板未渲染只留下一屏 `{{ }}`。看一眼截图不算验证，要有 DOM 断言。

### 9.2 图表标准（2026-10-09 加）

探针里的图不再手绘 SVG，全部走 **ChartSpec → ECharts** 这条真实管线：每个图都喂一份与 `gacha_simulator/visualization/chart_spec.py` **同名同构**的对象，所以探针同时是设计样品和渲染契约的样品，接线时 `libs/gs-charts.js` 是原型而不是废稿。标准页是 `charts_showcase.html`，它同时是全图型的冒烟测试（每种 `chart_type` 至少一个实例，改渲染器先看这一页）。

**配色是算出来的，不是挑出来的。** 用 dataviz skill 的 `validate_palette.js` 在浅色表面 `#ffffff` 上跑：

- 分类色 `#1976d2` / `#00897b` / `#7b1fa2`：亮度带、色度下限、CVD 分离（全对最差 ΔE 10.8 deutan）、常视分离（最差 ΔE 16.1）、对比度五项全通过。只三槽，第 4 条序列不是再挑一个色相，而是折进「其他」或改小倍数图。
- 单色阶 `#82b5e9` → `#083a80`：亮度单调、相邻级差、亮端对白底 2.16:1、单一色相四项全通过。
- 语义色（good / warn / danger）**不进分类序列**：图上出现红色必须意味着「坏」，若某条序列用了红，读者就再也分不清那是「第 3 个方案」还是「出问题了」。发散色阶的红是唯一例外，且同一张图里不得兼作状态。

令牌定义在 `libs/gs-charts.css` 的 `:root`（`--gsc-chart-*`），JS 侧从 `getComputedStyle` 读，读不到才回退同值字面量。**改配色只改 CSS 一处**，图内与图外（数据带、表格、图注）会同时跟上。

几条与直觉相反、但都有理由的决定：

- **默认 SVG renderer，不是 canvas。** canvas 拿不到 `font-variant-numeric`，「等宽数字」这条标准就只能靠换字体近似；SVG 下 ECharts 的文字是真 DOM 节点，一条 CSS 就生效。元素超过 3000 个时自动切 canvas。
- **图题不画在图里。** 图注体系要求「图题在图下、表题在表上」，标题、导语、图注、口径脚注全部由 HTML 承载，主题里 `title` 默认关闭。
- **轴名默认不画。** 每个结果块的导语已经写明「横轴＝X，纵轴＝Y」，图里再画一遍是重复，而且轴名与刻度、工具箱、数据标注抢位置，是一整类排版事故的来源。需要单独看一张图时开 `layout_hints.axis_names`。注意这个开关只管轴名，不管山脊的行名。
- **表不画进画布。** `chart_type='table'` 时 renderer 返回 `null`，由页面渲染真 HTML 表。把表塞进画布是把可选中、可复制、可读屏、可排序的文本降级成像素，而表主型（型 5）本来就没有主图。
- **大字号主数字用比例字形。** `tabular-nums` 只给成列对齐的数字（轴刻度、表格单元格）。等宽数字会让 `121` 这种数在展示尺寸下发松。

**山脊的行是选择单位，不是柱子。** 脆弱性的每行柱子高矮不一，若按柱子命中，行内大量空白点不动，违背「图本身即选择器」。所以山脊的点击在 zr 层按 y 坐标定位行，点行内任意位置都算选中；选中行保持原色，其余降透明度，否则读者点完在图上找不到自己选了哪一行。这条是**显式声明**的（`layout_hints.pick_rows`），不是 `ridge` 图型的固有属性：P80 的出卡间隔也用山脊，但它的行是按配置维度分档，点行没有选中语义。

**山脊不挂横轴缩放。** `inside` 型 dataZoom 会接管整个图表元素上的滚轮，而山脊装在 `overflow-y:auto` 的容器里、垂直滚动是它唯一的导航方式，两者会打架（实测是两者都没发生，滚轮被整个吞掉，第 16 行往后够不着）。而且山脊的用途是一眼看全所有池的完整区间，缩放横轴恰好破坏这个用途。同理，`zoomOnMouseWheel` 一律设成 `'shift'`：默认的「滚轮即缩放」在会滚动的页面里会静默吃掉滚动，而 `inside` 型没有可见滑块提示这件事。

**表格视图（图的孪生）。** 可达性要求：提示只能增强，不能成为读数的唯一途径。一张 34 箱的直方图，悬停第 17 箱能看到它的频数，不悬停的话这个数字在页面上任何地方都不存在。做法是 `GS.tableOf(spec)` 与 `specToOption` 并列、共用同一批计算，把同一份 spec 派生成表，所以**图和表保证是同一份数据**（两边各自算的话迟早不一致，而不一致的图和表比没有表更糟）。两条裁决：

- **入口放结果块标题栏，粒度按结果块。** 块才是「一次分析的产出」这个单位；按图给开关的话，脆弱性的下钻块一张里三张图就会有三个开关，读者得分别切三次才能把一块看完。
- **表一律是 HTML 表，不画进画布。** 画布里的表是像素，选择、复制、读屏、排序全拿不到，而 HTML 表这些都是白送的。**注意这是对现状的改变**：`TableData` 的注释写的是「替代 QTableWidget，统一在 ChartWebView 中渲染」，`visualization/plotly_charts.py` 里有绘制路径，`analysis_panel.py` 有 5 处构造，所以现在表是当图渲染的，接线时要作为迁移项处理。

图上那层标注（均值线、阈值线、着色区间）也要进表，否则切到表就丢了一半信息（山脊的「哪些池脆弱」就没了）。通用做法是把 `annotations` / `shaded_regions` 汇成一句放在表下；山脊的均值与脆弱区间是「每池一个值」，做成两列。表和图的互斥用 `v-if/v-else` 而不是 `v-show`：`v-show` 会把 ECharts 实例留在 DOM 里，它继续吃 ResizeObserver，容器变成 0×0 就重绘成空图。

**登记的偏差与待决**（都记在 `charts_showcase.html` §5）：

1. **后端 IR 的默认色阶 `Viridis` 在浅色底上不成立。** 校验器 ordinal 模式：亮度单调通过，但色相跨 144°（非单一色相），亮端 `#fde725` 对白底仅 1.26:1（门槛 2:1）。探针矩阵一律渲成单色蓝。接线时需决定改 `chart_spec.py` 的默认值，还是保留 Viridis 并接受这两条不通过。**现状：探针按标准渲染，偏差已登记未消除。**
2. **两处 token 文件不一致。** `tools/poc_webview/ui_compare/src/styles/tokens.css` 的 `--gsc-chart-palette` 是 matplotlib tab10（`#1f77b4,#ff7f0e,#2ca02c,#d62728,…`），含橙与红，与语义色纪律冲突；`--el-border-radius-base:2px` 与 `layout_demo` 的 6px 圆角也分叉。合并两套设计时要么改 tokens.css，要么退役该文件。
3. **深色模式未做。** 深色不是把浅色翻过来，而是从同一批色阶里另选步进并对着深色表面重新跑校验。当前只有浅色，登记为缺口而非「以后顺手翻一下」。长表（山脊 672 行）的可用性（长表要不要分组折叠、同一池的多行要不要合并）也还没定。

## 十、验收

- 树：无文件夹层级；一级配置节点为顶层；五类节点形状可辨；批次可折叠
- 配置详情：十一个 tag 与 `config_panel.py` 的 `left_tabs` 同名同序；卡池管理下的二级标签与一级共边、形状同族、尺寸小一号
- 分析专题：十一个，名与序见 §5.7；每个专题恰好一个主方法（●）
- 分析项多选：勾选决定哪些出结果；选中的依序堆叠；全取消时给空态而**不是**静默留白
- 参数：在各自结果块内，不在左栏；字段与 `gui/analysis_panel.py` 的 `add_config_row`（label + 控件成对）对齐，不是只读展示
- 脆弱性分析：总览常驻且自身即选择器（**不要另设池选择器**）；山脊限高内部滚动；顶部有摘要与「只看检出脆弱的」筛选；筛选藏起当前选中项时自动改选首行
- 锚点：固定在一级配置节点；同子树内点选不改变面板；跨一级配置或切到对比任务时直接换内容且不退出分析模式
- 数据集选择器：单值产物与未跑流式的数据集不出现，且给出排除原因
- 项级：选到缺池结束时间的数据集时，转变分析置灰并说明
- 数值显示：进度等由运算得出的数字不得露出浮点尾数（真实应用 `webui/api.py` 的 `pct = int(done / total * 100)` 已取整；探针的假造进度需自行取整）
- 切换：展开分析时详情页坐标不变（实测 343 恒定）；道从右端移到左端；两页不互相透出
- 运行：主按钮一步派发；浮层右缘与按钮右缘对齐；运行中禁用；派发后任务出现在队列
- 任务抽屉：任务队列列齐；资源监控三项；worker 数为并行数之和；再点按钮与点下方均可收起；关闭时顶部无阴影残留
- 图表：全部走 `ChartSpec` → ECharts（见 §9.2）；每个 `.gs-chart` 都挂上了实例（`shot.py chart` 断言 `mounted == boxes` 且 `empty == 0`）；改配色只改 `libs/gs-charts.css` 一处
- 图表交互：提示、工具箱默认开；图例只在 ≥2 序列时出现；分类超过 14 个才给缩放条；山脊点行即选中且选中行看得出来
- 图表版面：容器高度含轴标签带（不出现卡片内嵌套滚动条）；网格线是一档深于表面的灰、发丝、实线（虚线只留给阈值）
- **离线**：五个页面（`index` / `charts_showcase` / `archetypes` / `rightcol_showcase` / `tabs_showcase`）在**断网**条件下均能完整渲染，且图表不落成空白框
