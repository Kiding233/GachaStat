## P1：设计澄清

### 缺陷 12：所有策略均为贪婪/启发式，不满足贝尔曼最优性

- **来源**：全模块审查 §2.4 + P30 计划
- **严重度**：严重（设计澄清，非代码缺陷）
- **位置**：`core/strategy.py` + `strategies/builtin/*.py`——8 种策略全部
- **问题**：所有策略均为一阶前瞻（或零阶）：检查当前条件，立即行动，不递归评估未来状态的期望价值。
  - 没有策略能权衡「现在花费资源抽此池」vs「等待更好的池子」
  - 没有策略能预测保底计数器在未来池子中的价值
  - `future_schedules` 已传入 `StrategyContext` 但**没有任何策略使用它**
- **理论立场**：抽卡最优策略为 NP-hard 的随机动态规划问题，启发式是合理的工程选择。需要的是**文档化**而非重写。
- **原推荐方案**：
  1. 在 `strategy.py` 模块级 docstring 中明确说明启发式设计决策
  2. UI 中标注「启发式结果」
  3. `future_schedules` 使用或标注为预留字段
  4. 可选：贝尔曼基准（极简化场景的 DP 求解，研究级增强）
- **处置结论**（2026-06-13）：由**关于页面「策略行为说明」tab** 覆盖用户核心需求（`gui/about_dialog.py`）。四条推荐方案经逐条评估**均不予实施**——用户不读源码 docstring；关于页面已覆盖标注需求，额外 Tooltip 冗余；`future_schedules` 待需求明确再启用；贝尔曼基准为研究级增强、无用户需求。
- **当前状态**：✅ **已处置**。残余观察：`future_schedules` / `future_resource_gains` / `inter_pool_pity_links` / `time_discount` 四个未来信息字段至今无策略消费（见缺陷 14）。

## P2：改善与增强

### 缺陷 13：策略间无统一效用函数

- **来源**：全模块审查 §2.4 + P30 计划
- **严重度**：中等
- **位置**：`core/strategy.py` + `gui/comparison_analysis_panel.py`
- **问题**：各策略服务于不同隐式目标——成功率最大化 / 资源最小化 / 风险规避——无共同度量标准。「策略 A 优于 B」的断言在不指定元目标时无定义。
- **原推荐方案**：
  1. 策略比较面板文档：明确说明比较维度（GDR 阈值）
  2. 多维雷达图替代单一排名
  3. 元目标选择器：按成功率 / 按资源效率 / 按稳健性
- **处置结论**：**已委托 P19 Phase 3 #3「L5 偏好排序」**（λ 滑块 + CARA/CRRA 效用函数），P30 不再追踪。P19 Phase 3 八项整体**暂缓**（🟠）；P19 清单另拆出 **3a「极简前置」**（L1 表上方一行说明文字，零新功能，来源即本条），**经裁决暂不实施**（2026-09-14），该条仍挂在 P19 清单。
- **当前状态**：⏸ 已委托，随 P19 Phase 3 一并暂缓。

### 缺陷 14：StrategyContext 信息不完备

- **来源**：全模块审查 §2.4 + P30 计划
- **严重度**：中等
- **位置**：`core/strategy_context_builder.py` + `core/strategy.py` `StrategyContext` dataclass
- **问题**：原不提供未来资源收入预测、未来池奖励分布、时间贴现因子、池间保底链接关系。即使将来实现贝尔曼最优策略，也无法做出准确的跨期决策。
- **原推荐方案**（P30 增量补充，低风险）：
  1. `future_resource_gains`：从 `schedule_mgr` 计算未来每日资源收入
  2. `inter_pool_pity_links`：从 `PityEngine` 提取跨池保底继承关系
  3. 暂不补充：未来池奖励分布（超出配置范围）、时间贴现因子（需用户研究）
- **处置结论**（P69 阶段 2）：字段与计算分支已落地——`future_resource_gains` / `inter_pool_pity_links` / `time_discount` 三字段由 `build_strategy_context()` 统一计算，均带默认值；`future_schedules` 的派生计算同期补全（原先是「已传入但未计算未来窗口」）。
- **2026-09-15 独立复核勘误**：上述三字段（连同 `future_schedules`）**在实际模拟中恒为默认常量**——
  - `future_resource_gains` 恒 `{}`：计算受 `if resource_gain is not None and lookahead` 门控，而 `lookahead` 取自 `self.strategy.lookahead`，8 个内置策略**全为 `None`**（`future_schedules` 同门控，恒 `[]`）
  - `inter_pool_pity_links` 恒 `{}`：提取分支要求 behavior 具备长度 > 1 的 `pools`/`_pools` 属性，而 `create_behavior()` 从不传 `pools`，behavior 类也无 `_pools` 赋值点
  - `time_discount` 恒 `1.0`：唯一调用点 `gacha_service.py` 未传该参数，全库无其它传值处

  **基础设施已就位，数据源未接通。** 默认值掩盖了这一事实。
- **当前状态**：⚠️ **部分落地**——字段定义、计算分支、默认值齐备，但运行中恒为常量。残留缺口一项：**未来池子的奖励分布**仍未提供（需完整的未来卡池数据，超出当前配置范围）。遗留观察：四个字段当前无任何策略消费。
- **未做**：`PityState` 层无跨期价值预测（属策略侧问题，非本文档覆盖范围）
