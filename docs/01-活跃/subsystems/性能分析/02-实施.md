## 2. 适配器契约

```python
class Adapter(Protocol):
    name: str                 # 路径标识，写入每条 RunResult
    is_user_path: bool        # inline 为 False，其余为 True
    def available(self) -> bool: ...        # 本环境能否跑（无 PyQt6 则不报错，跳过）
    def run(self, plan: Plan) -> RunResult: ...
```

**职责**（详见 `01-理论.md` §3 驱动复用约束）：

1. 建起这条路径的运行环境
2. 把 `Plan` 翻译成这条路径的输入
3. 在**正确的进程与线程边界**上挂计时器与剖析器
4. 以这条路径自己的方式等待结束
5. 归一成同一个 `RunResult`

**禁止**：新写驱动。只能修复或包装已有入口。

**已知未验证项**：`gui-qt` 适配器的面板分发段（见 `01-理论.md` §9.2）。初版覆盖面定到 `SimulationThread` 结束。

## 3. Plan（测量规格）

```python
@dataclass(frozen=True)
class Plan:
    config_path: str
    strategy_key: str
    strategy_params: dict
    n: int
    workers: int
    seed: int
    chunksize: int | None = None      # None = 交给 run_batch_parallel 自算
    subject: str = 'simulation'       # simulation | startup（P83 §3.3）
    path: str = 'cli'
    grain: str = 'stage'              # batch | stage | single | function
    repeats: int = 3                  # 取中位数；建基线时强制 >=3
    py_spy: bool = False
    note: str = ''
```

## 4. RunResult（记录）

```python
@dataclass
class RunResult:
    run_id: str
    timestamp: str
    path: str
    is_user_path: bool
    fingerprint: EnvFingerprint       # cpu / cores / os / python / 代码版本
    plan: Plan                        # 完整规格，保证可复现
    wall_median: float
    wall_samples: list[float]         # 各次原始值，用于判断方差
    stages: dict[str, float]
    single: SingleStats | None
    functions: list[FuncStat] | None  # (name, ncalls, tottime, cumtime)
    resources: ResourceStats          # 序列化字节数、RSS 峰值
    samples_meta: SamplesMeta | None  # py-spy: duration / samples / errors
    not_comparable: bool = False      # function 档为 True，被基线比值排除（P83 §3.8 D6）
    warnings: list[str]               # 含 repeats_downgraded 等
```

## 7. 阶段划分（子任务拆分见 P83 §6.0，31 项 / 24.5 人时）

| 阶段 | 内容 | 交付判据 |
|------|------|---------|
| 1 | 内核 + `cli` 适配器 + 基线登记与比对闭环 | 能回答「cli 路径这次比基线慢了多少」 |
| 2 | `inline` 适配器（接管修复后的 profile_sim 逻辑） | 纯计算基线可复现 |
| 3 | `gui-qt` 适配器（offscreen，`QApplication(sys.argv)`）+ 阶段口径对齐 profile_gui 分段 + 启动时间线（`subject='startup'`） | GUI 路径全程可进自动化（G2）；启动速度可测（G6） |
| 4 | `webui` 适配器 + `py-spy` 采集层与解析 | 四条路径齐备，现场勘查可用 |
| 5 | `function` 档（cProfile 在 worker 侧的注入与合并）。机制见 P83 §3.8：`env` 四字段触发、围绕单次 `_run_single` 调用的开闭窗口、结果走文件不经三元组通道 | 函数级判据可进基线 |

阶段 6 单独列出的原因：`cProfile` 在 `multiprocessing` 子进程侧的注入需要改 `_wk_init` / `_wk_run_single` 的调用形态，是唯一需要触碰被测量代码的阶段，风险高于其余各阶段。

## 8. 阶段 6 的接口约束（P83 §3.8 摘要）

阶段 6 是全平台唯一触碰被测量代码的地方，三条约束不可回退：

1. **`SimulationEnv` 新增 4 字段**：`profile_enabled` / `profile_dir` / `profile_skip` / `profile_count`，全部带默认值以保持跨进程 pickle 兼容（照既有 `return_compact` / `n_heatmap_bins` 的模式）
2. **采样窗口在 `_wk_run_single` 内开闭**，不在 `_wk_init` 里做进程级 enable。依据是 `multiprocessing.pool.Pool.__exit__` 走 `self.terminate()`（本机 Python 3.12.5 源码核验），worker 被强杀、`atexit` 不执行
3. **剖面结果走文件**（`dump_stats` + 父进程 `pstats.Stats.add()` 合并），不动 `CompactResult`、不动 `_RESULT_VERSION`、不改 `_wk_run_single` 的三元组 arity（其 docstring 有 ⚠ 明确契约，父进程有 `len(result) == 3` 守卫）

失败一律软降级，绝不因剖析失败导致模拟失败。

## 10. gui-qt 覆盖率（P83 §3.10 摘要）

**覆盖完整 GUI 路径**，含面板构造与分发执行。根因已查明：此前探针失败是因为用 `QApplication([])` 传空 argv（WebEngine 初始化随之失败，进程以 `0xC0000409` 终止）；改用 `QApplication(sys.argv)` 后全部正常。

**实测数据：** `ChartWebView()` 构造 0.19s（offscreen）/ 0.65s（真实平台），`_loaded` 约 1.5s；`MainWindow()` 构造 0.36s，显示后 10 个 Chromium 子进程、RSS 412 MB、九个面板齐备。`offscreen` 与真实平台均可用，适配器采 `offscreen`（不弹窗）。

**三条实施要点（P83 §3.4 规则 6-8）：**

1. `QApplication(sys.argv)` 非空 argv + `AA_ShareOpenGLContexts` 先于 `QApplication`
2. 收尾显式回收 Chromium 子进程
3. 关闭 `MainWindow` 先置 `win._restarting = True`，否则弹「确定要退出吗」确认框阻塞

**噪声过滤：** `offscreen` 下 Chromium 会向 stderr 输出 GPU 错误（`Failed to make current since context is marked as lost`），不影响功能，报告时须过滤。

## 11. 启动测量（P83 §3.11 摘要，G6）

**`subject='startup'`** 时 `n` / `workers` / `chunksize` / `strategy_key` / `seed` 一律忽略，产出启动时间线。

**分段：** 解释器启动 / Qt 栈 import / `QApplication` 构造 / 主模块 import / 主窗口构造 / **窗口可见** / **启动工作完成** / 图表可用（聚合口径待定）。

**三条约束（P83 §3.4 规则 9-11）：** 全新冷进程内测量并由子进程回传时间线；先预热一次并丢弃、冷启动不在覆盖范围；RSS 取启动完成时刻的峰值。

**实测基线（2026-09-18）：** 窗口可见 2.3s；启动工作完成 6.5s；峰值 RSS 368 MB；Chromium 子进程 10 个。
