## P51 引入的新问题

P51 将核回归管线完全替换为离散分箱 + PAVA + 变更点推断管线，解决了 D/E/F/G/I 五项缺陷，但引入了以下新问题：

### P51-N1：Bootstrap 变更点 CI 覆盖率无理论保证

| 属性 | 内容 |
|------|------|
| 严重度 | 🟡 中等 |
| 涉及文件 | `core/vulnerability.py` `_changepoint_ci()` |
| 描述 | 变更点 Bootstrap CI 在大样本下渐近有效（Antoch & Hušková 2001），但有限样本（n < 1000）下实际覆盖率未知。当前 `n_boot=500` 为工程默认值，无理论推导。 |
| 缓解措施 | 用户可增大 `n_boot`（上限 2000）；未来可做 Monte Carlo 模拟校准实际覆盖率 |
| 风险 | 名义 95% CI 在小样本下可能偏窄或偏宽 |

### P51-N2：IMSE 选 J 无最优性理论保证

| 属性 | 内容 |
|------|------|
| 严重度 | 🟢 低等 |
| 涉及文件 | `core/vulnerability.py` binsglm 调用 |
| 描述 | IMSE 准则最小化积分均方误差，但在有限样本下不保证 J 的最优性。CCFF (2024b) 指出 IMSE 是合理的工程启发式，但未给出有限样本最优性证明。 |
| 缓解措施 | J 的选择在实践中「足够好」；可手动覆写 J；未来可做交叉验证选 J |
| 风险 | J 可能不是最优的（但通常不会严重偏离） |

### P51-N3：单调性断点回退丧失变更点推断成本优势

| 属性 | 内容 |
|------|------|
| 严重度 | 🟡 中等 |
| 涉及文件 | `core/vulnerability.py` `_diagnose_monotonicity()` |
| 描述 | 单调递减假设在策略断点处可检验（Wilson CI × 3σ）、可回退——但回退到独立检验 + Sidak 校正后，丧失了变更点推断的 O(1) 成本优势（J 次独立检验 vs 1 次变更点估计）。 |
| 缓解措施 | 仅当诊断到断点时触发回退；大多数场景单调性成立，变更点推断正常工作 |
| 风险 | 在策略切换密集的场景中，回退频率高，CI 宽度增大（Sidak 保守性） |

### P51-N4：binsglm 依赖项 C 扩展编译问题

| 属性 | 内容 |
|------|------|
| 严重度 | 🟢 低等 |
| 涉及文件 | `core/vulnerability.py` binsglm 导入 |
| 描述 | `binsglm` 包依赖 `numpy` C 扩展，在部分平台（如 ARM Windows、Alpine Linux）可能存在编译兼容性问题。 |
| 缓解措施 | 已实现自动回退——binsglm 失败时无缝降级到 `_logistic_ll_fit`（纯 Python IRLS 实现），GUI 状态栏显示回退警告 |
| 风险 | 回退后丧失分位数分箱优势（等样本量箱、IMSE 选 J），但不影响核心分析功能 |
