# 终极验证体系——分层独立参考实现与统计对比

> 状态：设计完成 · 2026-07-20
> 用途：上线前一次性验证——确保 GachaStat 引擎对每个游戏的核心卡池机制建模正确

---

## 一、动机

GachaStat 是一个通用抽卡模拟引擎。配置手册覆盖 19 款游戏，每款有独特的保底组合、副产物管线、限定行为。当前测试覆盖率 29.2%，集中在单元测试——没有端到端的「引擎产出 vs 游戏真实机制」对比。

**核心风险：引擎对某款游戏的机制理解本身就有偏差，但单元测试无法发现——因为测试和实现在同一套假设下。**

本方案通过编写**独立于 GachaStat 代码库的参考实现**，将引擎产出与独立实现产出做统计对比，不一致则阻塞上线。

## 三、S 层——独立参考实现规范

### 3.1 设计原则

| 约束 | 理由 |
|------|------|
| **硬编码游戏常量**——不从 TOML 读取 | TOML 解析本身可能含 bug——参考实现必须零依赖 GachaStat |
| **命令式循环**——不抽象 Behavior / Strategy / PityEngine | 抽象层就是 bug 来源——参考实现越「笨」越可信 |
| **单文件、单游戏** | 可独立审计、独立运行、独立调试 |
| **输出 `ReferenceResult`**——统一对比接口 | 所有 S 层参考实现共享同一套对比管线 |
| **200-400 行/款** | 足够精确复现核心循环，但不超过一人一小时内可完整审计的长度 |

## 四、对比管线——五项指标体系

### 4.1 为何不用 KS 检验

| KS 的问题 | 替代方案 |
|-----------|---------|
| 对中位数敏感、对尾部迟钝 | Anderson-Darling——对尾部权重高 4-5 倍 |
| N=100,000 时过分敏感 | Bootstrap CI——报告「差多少」而非「是否不同」 |
| 只判「不同」不判「哪里不同」 | 分层指标——位置/尾部/结构各自独立判定 |
| 对硬保底概率质量峰不敏感 | 精确二项检验——单点概率质量直接对比 |

### 4.2 五项指标

```
               ┌─────────────────────────────┐
               │   S 层对比指标体系           │
               └──────────────┬──────────────┘
                              │
     ┌────────────────────────┼────────────────────────┐
     │                        │                        │
┌────▼─────┐          ┌───────▼───────┐        ┌───────▼──────┐
│ 位置指标  │          │  尾部指标      │        │  结构指标     │
│ 均值·中位 │          │  95/99 分位   │        │  保底触发率   │
│ Bootstrap│          │  Anderson-    │        │  精确二项检验  │
│ CI 差值   │          │  Darling     │        │  + 分箱 χ²   │
└──────────┘          └───────────────┘        └──────────────┘
```

| # | 指标 | 方法 | 回答的问题 | 失败阈值 |
|:---:|------|------|-----------|---------|
| 1 | **均值差** | Bootstrap CI（10,000 resamples, BCa） | 「期望抽数差了几抽？」 | CI 不含 0 且 \|Δ\| > 0.5 抽 |
| 2 | **关键分位差** | Bootstrap CI for P50/P75/P90/P95/P99 | 「非酋体验差多少？」 | 任一关键分位 \|Δ\| > 1.0 抽 |
| 3 | **保底触发率** | 精确二项检验 (Exact Binomial Test) | 「硬保底触发概率一致吗？」 | p < 0.01 且 \|Δp\| > 0.1% |
| 4 | **软保底区间** | 分箱 χ²（逐抽分箱） | 「概率爬升斜率对吗？」 | p < 0.01 → 存疑 |
| 5 | **整体分布形状** | Anderson-Darling 双样本 | 「分布形状有实质差异吗？」 | p < 0.001 → 存疑（辅助参考） |

### 4.3 判定矩阵

对每款 S 层游戏，5 项指标各自判定，综合取最差：

| 指标 1-3 结果 | 指标 4-5 结果 | 综合判定 | 动作 |
|:---:|:---:|:---:|------|
| 全部通过 | — | ✅ **通过** | 无 |
| 任一项存疑 | — | ⚠️ **存疑** | 人工审查——可能是浮点精度或样本量问题 |
| 任一项失败 | — | ❌ **失败** | 阻塞上线——引擎或参考实现至少一方有 bug |

### 5.1 形态示例

```python
# tests/validation/differential/test_g16_nonreset.py

def test_g16_pity_counter_not_reset_on_ssr():
    """
    G16 幻塔：出金后保底计数器不重置。

    构造：第 79 抽 SSR → 第 80 抽应仍触发硬保底（出第 2 个 SSR）。
    对比：正常行为（如原神）第 79 抽出 SSR → 计数器归零 → 第 80 抽无保底。
    """
    config = build_huanta_config(ssr_at_79=True)
    result = run_gachastat_fixed_seed(config, seed=1, max_draws=80)

    assert result.ssr_at_draw(79),  "第 79 抽应出 SSR"
    assert result.ssr_at_draw(80),  "第 80 抽应仍然出 SSR——计数器未重置"
```

## 七、pytest 集成与运行策略

### 7.1 标记系统

```ini
# pytest.ini
[pytest]
markers =
    validation:  终极验证体系标记
    s_tier:      S 层独立参考实现
    a_tier:      A 层专项测试
    b_tier:      B 层快照回归
    slow:        慢速测试（>1s/用例）
    ci_quick:    CI 快速预检
```

### 7.2 运行分级

| 场景 | 命令 | n_sims | 预期耗时 | 触发 |
|------|------|:---:|:---:|------|
| **CI 预检** | `pytest -m validation_and_ci_quick` | 1,000 | ~5s | 每次 push（H9 前） |
| **PR 验证** | `pytest -m validation --n-sims 10000` | 10,000 | ~30s | PR 合并前 / 手动 |
| **上线前全量** | `pytest -m validation --n-sims-full` | 100,000 | ~3min | 手动触发，阻塞上线 |

### 7.3 CI 预检的降级策略

n_sims=1,000 时统计功效不足做正式对比。CI 预检仅做**烟雾检测**：
- 均值差不超过 10 抽（显著偏差可被少量样本捕获）
- 保底触发率不超过 2x 偏差
- 无异常崩溃或 NaN

正式对比仅在 `n_sims >= 10,000` 下执行。

## 九、风险与缓解

| 风险 | 概率 | 缓解 |
|------|:---:|------|
| 参考实现本身有 bug，两边同错 | 中 | 参考实现硬编码游戏常量、命令式循环——审计难度远低于引擎代码。S 层 5 款互相独立，不可能 5 款同时同向偏差 |
| Bootstrap CI 在 n_sims=100,000 时 trivial significance | 中 | 判定以效应量（Δ 抽数/Δp）为主，CI 仅提供区间估计 |
| 游戏版本更新后参考实现过时 | 低 | 参考实现标注版本号（如「5.0+」），与手册对齐。版本更新→同步更新参考实现 |
| 棋盘游戏（异环）无法验证 | 低 | 明确标记为搁置，不在上线阻塞范围内 |
