## 1. 任务是什么

分析页（`tools/poc_webview/layout_demo/` 这一套 WebUI 探针，同时约束真 GUI 的形态）的交互模型要重做。拆开是三个互相咬合的问题：

1. **参数住哪**：住在左栏，还是住在右栏各自的结果块里。
2. **运行入口收在哪**：现状是每个结果块一个「重新计算」、每个派发块一个「开始〈方法名〉」；用户要求「取消右侧的重跑，把运行分析统一收回左侧」。
3. **同一分析方法可否多实例**：即同一方法用不同参数出多份结果并排。

用户在讨论中途明说：「现在是交互逻辑重新设计的问题了，你可以不必要延续之前的方案，但是原理性与原则性的东西应该保持」。

### 起因

用户第一条诉求（原话）：

> 现在的点击左侧条目直接添加感觉还是怪怪的，能否改成点击只是选中，点击勾选才是添加

顺着这条追下去，发现真正的问题是「参数控件一次只显示一份，于是填 N 份要循环 N 次」，用户随即否掉了这个循环：

> 要求是要有更新也要有追加，还有一个重要的点是交互不能太繁琐，最好不要点击一项填一组参数点一个运行按钮，再点击一项填一组参数再点一次运行按钮，如何做得优雅一些，哪里有相似的模式参考就好了，但是生搬硬套也不行

### 调研里最有用的三条

1. **「多份」是两族正交机制，不要混为一谈**：**独立实例**（jamovi/JASP 的 Duplicate、Grafana 的 Duplicate）与**一维取多值**（jamovi/JASP 的 Split by、ggplot2 `facet_wrap`、Vega-Lite `facet`、Grafana repeat by variable、SPSS SPLIT FILE）。Grafana 的 repeat by variable 是「一维取多值」里最贴的单个现成样板。
2. **jamovi/JASP 的模型可以借鉴一半**：点方法 → 左区出现该方法的参数表单 → 右侧**追加**结果块；参数面板可折叠，**折叠后点对应结果块能重新打开它**。**但「改参数即时重算」抄不了**：它们的分析是毫秒级统计计算，我们的「运行」是跑蒙特卡洛（有 worker、有次数成本），改一个参数就自动重跑会变成灾难。所以运行仍必须是显式的用户动作。
3. **「默认共享还是默认独立」必须显式定，且主流默认是共享**：ggplot2 facet 默认 fixed、Vega-Lite facet 默认 shared、Tableau 默认 uniform axis range；Grafana 是反例。另加一条重要推论：**「统一分箱」与「允许逐份相对化」要分成两件事**，各面数据量级差很大时统一刻度会把小量级那份压成一条线（Tableau 教程里那位作者手工做相对化归一正是为此）。

### 调研给的三条附加设计约束

- **哪些参数允许取多值必须显式建模**。Grafana repeat 的前提是「参数必须是多值变量」，而且它只做字符串插值；我们的参数取值可能改变计算分支（命中集换一个集合 ≠ 换一个数），所以「参数的取值列表」要升格为一等公民，并逐参数声明能不能扫（分箱宽度天然可扫；命中集要先定义枚举域）。
- **跨方法的全局开关不能塞进方法参数表**。本项目有 `unit`（资源类 GDR 除以每抽成本）这类全局量，jamovi 模型里没有「全局参数」，Qt 面板是左栏顶部单独两组（`全局参数`／`单位参数`）。
- jamovi 的「参数面板可折叠、折叠后点结果块能重新打开」是一个可直接借的交互，它让左栏不必常驻占位。

## 5. 我提的主干方案（未获最终认可）

三条机制相加，demo 已按这个做出来（见 §8）：

**机制一：左栏三层**
```
左栏 300px                        右栏 = 结果
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ 间隔分析              3/7 项  │  │ 池化间隔分布                  │
│ ☑ ▾ 池化间隔分布              │  │ 分箱宽度5 · 参考线分位线 ▾    │←只读快照
│      命中集 ☑限定卡 ☑全部SSR  │  │ [图]                          │
│      分箱宽度 [5]             │  └──────────────────────────────┘
│ ☑ ▸ 累积分布 F(n)             │  ┌──────────────────────────────┐
├──────────────────────────────┤  │ 累积分布 F(n)                 │
│ [运行分析]        [清除结果]  │  │ 命中集=限定卡 ▾              │
└──────────────────────────────┘  │ [图]                          │
                                  └──────────────────────────────┘
```
方法清单 / 参数区（随选中项切换、可折叠） / 运行分析。**点方法行 = 只选中**（参数区切过去，不出结果）；**点勾选框 = 添加一份结果**。这一条同时满足「与 GUI 惯例一致」和「消灭逐项点运行的循环」。

**机制二：块头是只读参数快照**（用户在讨论中自己提的脑洞，原话）：

> 左侧参数区作为运行时只是指定参数，右侧结果区包含一个只读的参数展示区，右侧结果区提供参数-结果对应

块头那一行收起时写「这份结果实际用什么参数算的」，展开才变控件。它解开了四件事：① 「参数与图对应清晰」不再靠物理相邻，而是更强（物理相邻有个隐藏错配：参数改成 10、图还是旧的，你看到的是「新参数 + 旧图」；快照下不存在）；② 多实例天然落位，每份结果自带快照，不用给实例起编号；③ 左栏只写、右栏只读加结果，与 Qt 分工一致；④ 不违反「不在两处各列一遍」，那条管的是两个**选择器**谁说了算，只读回显不是第二个选择器。

**机制三：分面 + 复制一份**
- **分面**：把「取多个值」的参数（命中集、GDR 指标、事件模式）由单选改多选，勾 N 个 → 一块里 N 个面，**共享分箱与同一纵轴上限**。它同时做掉三件事：覆盖多实例的绝大部分需求；取代 Qt 的 GDR 穷举（42 个勾选框收成一个「指标取哪几个」）；兑现用户最早的「多子图高度可比、刻度对齐、图参数一致」约束（**共享其余参数是分面的定义**）。
- **复制一份**：块头一个按钮，以这一份的参数再加一份（jamovi/JASP/Grafana 的 Duplicate 做法）。多实例落在结果块上而不是左栏，于是左栏不必列实例列表，**用户明确担心的「左区长度」与「左右对应」两个问题一起消失**。

### 三笔成本（写方案时已摆给用户）

1. **参数出现两遍**（左栏可编辑 + 右栏只读）。这是换「左栏纯参数＋一次运行全部」付的代价。
2. **分面要有共享刻度才做得对**，也就是 §2 第 5 条那个 `SharedScale`。两件事是同一件，所以甲案不单独做。
3. **任意类型的并排面板在 Plotly 侧缺渲染器**（`_build_composite` 不存在）。直方图分面走 `ridge` 现成、叠加式分面走 `scatter` 现成；「N 个非直方图面板」要走 `composite`，要补渲染器。此成本**目前没有登记**。

## 6. 我怀疑「怪」的七个点（供接手者对照发问）

用户说「逻辑感觉怪怪的」但没指出具体位置。以下是我自己复盘出来的可疑处，按我认为的可疑度排序：

1. **勾选框管的是「多份」而不是「一份」**。勾上 = 加一份；**再点取消 = 删掉该方法全部份数**。复制了 3 份后误点一下，3 份全没。而「复制一份」在块头，于是同一个「数量的增减」被拆到左右两处，语义还不对称（左：方法级开关；右：实例级增删）。
2. **同一个按钮两种语义**。左栏底部「运行分析」在选中块时是**更新那一块**，在选中方法时是**新增一块**。用户无法从按钮本身预知后果。
3. **两个入口改同一份草稿**。块头展开改的与左栏参数区改的是同一份 `draft` 的两个视图。要么是同一份（那为什么两处都有），要么是两份（那同步规则是什么）；界面上看不出来，读者会当成两份。
4. **左栏高亮的是方法行，参数区配的是块**。选中块时左栏高亮它所属的方法行，可该方法行可能挂着 3 份块，从左边看不出「现在配的是哪一份」，只能读参数区标题那串摘要。
5. **摘要只列与默认值不同的项，全默认时写「默认参数」**。于是最常见的那份默认结果，块头读不到任何具体值，恰恰违背了这一行「这份结果实际用什么算的」的本意。
6. **分面与多实例的边界不可见**。同时差两维时无路可走（设计上倾向登记为不支持），但界面上没有任何提示。用户会先试分面（勾两个值），再想给其中一面单独改分箱宽度，才发现改不了。
7. **选中态触发面太大**。整块可点（含图本身），读图时随手点一下就把左栏参数区换掉了。
