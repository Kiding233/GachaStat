# P77 资源生命周期——限时货币强制兑换与清零

> 日期：2026-08-08 | 状态：设计中
> 触发：手册 §二十一 G6（限时货币到期转换）+ FGO 天井清零。2026-08-08 设计评审收敛：资源兑换与里程碑扩展（G18）分为两个独立计划（P77 / P78）；触发模型由「Banner 结束事件」改为**时间驱动**（真实机制是时间下架非抽空事件）；补充**策略可知性**（到期信息经 StrategyContext 注入策略）；记账语义定为「转换 = 源 consumed + 目标 gained」（对齐 P58 先例，GDR 口径自然隔离）；UI 适配纳入本期（**实施顺序 P78 先、P77 后**——P78 实现资源定义 Tab，P77 在其 lifecycle 占位区落地，不扩列）。同日晚第三次裁决：`on_expire` 仅两态（转换/清零，**无保留态**）；转换比例支持**精确整数对**（`from`/`to`，如 3 A 换 2 B），零头随源资源清零。
> 依赖：P61✅（时间窗口 + banner_end_times_sorted 检查点）、P60✅（state 基础设施）、P58✅（MilestoneEngine——本计划不消费其事件，仅触发时机与其并行）

## 一、问题

### 1.1 限时资源无生命周期（G6 + FGO 清零）

手册登记三款游戏 + FGO 存在「池结束 → 限定货币到期处理」机制，当前无法建模：

| 游戏 | 机制 | 到期行为 |
|------|------|---------|
| 幻塔 | 回火铸金（限定） | 卡池下架 → **等额转换**黑市铸金（常驻） |
| 蔚蓝档案 | 天井点数 | 卡池下架 → **转换**制造石碎片 |
| 赛马娘 | 天井点数 | 卡池下架 → **转换**四叶草 |
| FGO | 天井点数 | 卡池下架 → **清零**（不转任何常驻货币） |

**根因**：当前 `resource_defs: Dict[str, str]` 仅是「资源 id → 显示名」映射（[config_store.py:227](gacha_simulator/core/config_store.py#L227)），资源是**全局永驻**的一等公民，没有「到期时间」和「到期行为」两个属性。任何「限时货币/池专属货币」都无法表达。

**到期语义界定**：真实机制中「卡池结束」是**时间性下架**（卡池开放期结束），与玩家抽卡行为无关。模拟里 banner 的 `available_until`（秒）即此语义；玩家抽空池子（`pool_exhausted`/`max_draws` 耗尽）不应触发货币到期——故本计划以**时间触发**而非「Banner 结束事件」触发。

### 1.2 为什么不是 P61 lifecycle action / banner 结束事件

P61 `[[banner.lifecycle]]` 是「池的规则」：`condition → action`（`switch_to` / `exhaust_banner`），管池子可用性与切换。把资源转换塞进去变成「池结束 → 转换资源」，规则散落在每个 banner 配置里，同一资源被多池共用时需重复声明，且无法表达「到期清零」（无转换目标）。

更深一层：**P61 的 banner 结束并非单一事件**，而是两条独立路径——① lifecycle 规则（`_check_transitions`，事件驱动）；② ISSUE-001 时间窗口过期直接 `_exhaust()`（[gacha_service.py:375-379](gacha_simulator/service/gacha_service.py#L375-L379)，**不经过 lifecycle 规则**）。若把资源到期挂「Banner 结束事件」：
- 挂 lifecycle 事件 → 纯 `available_until` 关闭（无 lifecycle 规则的常见形态）不触发，资源永不过期；
- 挂 exhaust 事件 → 玩家抽空池子也触发到期，语义错。

**强制兑换的主体是资源，到期时刻本质是时间**。故本计划由资源持有 `expire_at`（或对齐某 banner 的 `available_until`），时间驱动——与 P63（溢出挂在卡上）、P65（标签挂在卡上）「数据自描述」范式同构，且复用 P61 现成的时间检查点。

## 二、目标

- 资源支持「到期时间 + 到期行为」——`expire_at`（绝对时间）/ `expire_with_banner`（对齐 banner 下架时刻）+ `on_expire`（转换/清零）
- 时间驱动触发，复用 P61 现有时间检查点，不新建事件系统
- **策略可知性**——到期信息经 `StrategyContext` 注入策略，策略可感知「某资源剩余 N 天到期、到期变什么」并据此决策
- **记账语义**——转换 = 源 `total_consumed` + 目标 `total_gained`（对齐 P58 milestone 资源并入 total_gained 先例，对账天然成立；GDR 分母固定为 draw_resource 与限定货币不相交，口径自然隔离）
- 覆盖游戏：幻塔/蔚蓝档案/赛马娘（G6）+ FGO（清零）
- 保持 `resource_defs: Dict[str, str]` 结构不动——不破坏 gdr.py 与 11 处 GUI 引用
- **UI 适配纳入本期**——P78 已实现「资源定义 Tab」（方案 X），本计划在其 lifecycle 占位区落地到期编辑（**实施顺序：P78 先、P77 后**）

## 三、方案

**设计决策（2026-08-08 二次评审修订）**：

1. 不修改 `resource_defs: Dict[str, str]`（波及 gdr.py 的 `for rid, rname in resource_defs.items()` + 11 处 GUI），**新增独立配置段** `resource_lifecycle`——只有声明了生命周期的资源才参与到期结算，其余资源行为完全不变。
2. **触发模型改为时间驱动**（原「Banner 结束事件触发」废弃）。到期时刻两个来源，互斥二选一：
   - `expire_at`：绝对到期时间（秒，TOML/UI 层以天书写，解析边界 `*DAY`，与 P61 一致）
   - `expire_with_banner`：快捷选项——对齐某 banner 的 `available_until`，覆盖「限时货币与卡池同步失效」的常见场景，免手写绝对秒数
3. **策略可知性**——`StrategyContext` 新增 `resource_expiry` 预览字段，由 `build_strategy_context()` 集中构造，与 `pending_transitions`/`future_resource_gains` 同一惯例。
4. **`on_expire` 仅两态（第三次裁决）**——`转换` / `清零`，**无「保留」态**，且**到期时间与 `on_expire` 必须成对出现**（声明了 `expire_at`/`expire_with_banner` 就必须有 `on_expire`）——「有到期时间但到期后什么都不做」的中间态无意义，与「无生命周期声明」重合，徒增配置歧义。`ctx.resource_expiry` 只承载「明确声明了到期动作」的资源（见 3.4）。
5. **转换比例支持精确整数对（第三次裁决）**——`on_expire = { convert_to, from: int, to: int }`，语义为「每 `from` 个源资源换 `to` 个目标资源」；可表达非等额比例（3 A 换 2 B）。整数对避免 `rate` 浮点乘法取整的语义含糊：余额 `balance` 可换 `(balance // from) * to` 个，**零头 `balance % from` 随源资源一并清零**（到期即作废，无找回）。

### 3.1 数据结构（新建 `core/resource_lifecycle.py`）

```python
@dataclass
class ResourceLifecycle:
    """限时资源生命周期——到期时刻 + 到期行为。"""
    resource_id: str                      # 作用对象（如 "tof_token_a"）
    expire_at: Optional[float] = None     # 绝对到期时间（秒）。与 expire_with_banner 互斥
    expire_with_banner: Optional[str] = None   # 快捷：对齐该 banner 的 available_until（秒）
    on_expire: Optional[dict] = None      # 转换 {convert_to, from, to} | 清零 {clear} | None 无生命周期声明

@dataclass
class ResourceLifecycleConfig:
    enabled: bool = True
    rules: List[ResourceLifecycle] = field(default_factory=list)

@dataclass
class ResourceExpiryPreview:
    """策略可读的资源到期信息——「这个资源还剩多久到期、到期变什么」。"""
    resource_id: str
    balance: float                # 当前余额（state.resources）
    remaining: int                # 剩余天数（ceil 向上取整，min 0）
    expire_at: float              # 解析后的到期时间（秒，expire_with_banner 已展开）
    on_expire: Optional[dict]     # 转换 {convert_to, from, to} | 清零 {clear} | None 无生命周期声明
    description: str              # 人类可读描述（对齐 TransitionPreview.description）
```

`ConfigStore` 新增字段：

```python
resource_lifecycle: ResourceLifecycleConfig = field(default_factory=ResourceLifecycleConfig)
```

**配置校验**（`config_toml.py` 解析期，显式报错而非静默漂移，对齐 ISSUE-004 惯例）：
- `expire_at` 与 `expire_with_banner` 二选一，同时/均不填 → ConfigError
- `expire_with_banner` 引用的 banner 必须存在且设置了 `available_until` → ConfigError
- 同一 `resource_id` 只允许一条 rule → ConfigError（一个资源一个生命周期）
- `on_expire` 二选一——`convert_to`（须含 `from`/`to` 正整数，`from > 0`）或 `clear`，同时出现/均缺 → ConfigError
- **到期时间与 `on_expire` 必须成对**——有 `expire_at`/`expire_with_banner` 而无 `on_expire` → ConfigError（无保留态，声明了到期就必须有动作）

### 3.1.5 TOML 结构定位

`[resources.lifecycle]` 是 `[resources]` 命名空间下的**第四个平级子表**，与 `[resources.defs]`（id → 显示名）、`[resources.initial]`（id → 初始数量）、`gain_rules`/`day_overrides` 平级，**不嵌套进 `defs`**（嵌套会把 `resource_defs: Dict[str, str]` 的值类型从 `str` 变 `dict`，破坏签名与全部只读消费者）。

### 3.2 TOML 配置

```toml
[resources.lifecycle]
enabled = true
rules = [
    # 幻塔——回火铸金到期转黑市铸金（等额，对齐卡池下架时刻）
    { resource_id = "tof_token_a", expire_with_banner = "banner_tof_weapon_a",
      on_expire = { convert_to = "tof_token_black", from = 1, to = 1 } },
    # FGO——天井点数到期清零（绝对时间，可表达兑换窗口晚于卡池下架）

      on_expire = { clear = true } },
    # 非等额精确比例示例——3 个源资源换 2 个目标资源（零头随源清零）

      on_expire = { convert_to = "uma_clover", from = 3, to = 2 } },

```

### 3.3 触发点（复用 P61 时间检查点，不新建事件系统）

`gacha_service.py` 构造 `resource_expiry_times_sorted`（`(resource_id, expire_time)` 按时间排序，`expire_with_banner` 在构造期解析为对应 banner 的 `available_until`），在**现有三个** `real_time >= bet` 时间检查块（等待期 [375](gacha_simulator/service/gacha_service.py#L375)、每抽后 [394](gacha_simulator/service/gacha_service.py#L394)、循环收尾 [406](gacha_simulator/service/gacha_service.py#L406)）同步检查 `real_time >= ret`，满足且未结算过 → 执行 `apply_resource_expiry()` 并从待结算集合移除（幂等，real_time 继续走不重复转换）。

```python
def apply_resource_expiry(self, rule: ResourceLifecycle, state: GachaState,
                          total_consumed: Dict, total_gained: Dict) -> None:
    """P77——到期时刻到达，执行资源到期结算。

    记账语义：转换 = 源 consumed + 目标 gained（对齐 P58 milestone 资源并入
    total_gained 先例）——对账恒等式（final = initial + gained - consumed）
    天然成立，无需新增结果字段或序列化版本号。
    """
    balance = state.resources.get(rule.resource_id, 0)
    if balance <= 0:
        return
    if rule.on_expire and 'convert_to' in rule.on_expire:
        f, t = rule.on_expire['from'], rule.on_expire['to']
        q, r = divmod(balance, f)                  # 完整兑换对 q，零头 r 作废
        amount = q * t
        state.gain(rule.on_expire['convert_to'], amount)
        state.spend(rule.resource_id, balance)     # 源全额扣减（含零头）
        total_consumed[rule.resource_id] = total_consumed.get(rule.resource_id, 0) + balance
        total_gained[rule.on_expire['convert_to']] = total_gained.get(rule.on_expire['convert_to'], 0) + amount
    elif rule.on_expire and rule.on_expire.get('clear'):
        state.spend(rule.resource_id, balance)
        total_consumed[rule.resource_id] = total_consumed.get(rule.resource_id, 0) + balance  # 清零 = 消耗
    # 配置校验已保证：on_expire 必为转换/清零之一，且到期时间与 on_expire 成对出现
```

**触发时机边界**：模拟里 `real_time` 仅在等待动作时推进（抽卡不推进时间）。因此到期只在等待时触发——与 P61 banner 时间关闭（ISSUE-001）同语义；策略从不等待的模拟在时间轴上不越到期点，属模拟边界而非缺陷。验收用例须通过含等待的策略覆盖。

### 3.4 策略可知性（2026-08-08 评审补充）

`StrategyContext` 新增字段（带空列表默认值，P69 阶段 2 契约——现有策略不经修改即可运行）：

```python
resource_expiry: List[ResourceExpiryPreview] = field(default_factory=list)
```

`build_strategy_context()` 集中构造：遍历 `resource_lifecycle.rules`，解析到期时间（`expire_with_banner` → 查该 banner `available_until`），结合 `state.resources` 余额与 `real_time` 计算 `remaining`，生成预览列表。`remaining` 为确定值（到期时间均来自配置的确定数值），无 `pending_transitions` 事件型那种 -1 不可预估态。

策略用法示例（`on_expire` 仅两态——转换/清零；无生命周期声明的资源不进 `resource_expiry`，策略无感知）：

```python
for exp in ctx.resource_expiry:
    if exp.balance > 0 and exp.remaining <= 5:
        # 5 天内到期转换/清零 → 决策「到期前花掉」/「等转换」/「放弃」
        pass
```

### 3.5 记账与对账口径（2026-08-08 评审修订）

**记账**：转换 = 源资源 `total_consumed` + 目标资源 `total_gained`（目标按完整兑换对计算，**零头随源作废**——只记源全额消耗，零头不折算进目标，不产生额外收益）；清零 = 源资源 `total_consumed`。对齐 P58 milestone 资源并入 `total_gained` 的先例（[gacha_service.py:416-422](gacha_simulator/service/gacha_service.py#L416-L422)）——`total_gained` 本就含非抽卡获得，转换到账并入与先例一致。

**对账**：`final_resources = initial_resources + total_gained - total_consumed` 天然成立（源和目标各平），无需新增结果字段、无需序列化版本号变更。

**GDR 隔离**：GDR 转化效率分母固定为 `draw_resource`（抽卡资源，[gdr.py:464](gacha_simulator/core/gdr.py#L464)），转换涉及的是限定货币（回火铸金/天井点数），**口径自然隔离**——GDR 结果不受转换影响（`final_resources` 反映转换后果，余额类统计不受影响）。若未来出现以限定货币为分母的 GDR 配置，需另行评估（配置约定，非代码守卫）。

**结算顺序**：转换结算**先于** `banner_end_resources` 快照（[gacha_service.py:375-381](gacha_simulator/service/gacha_service.py#L375-L381) 同检查块内）——快照语义是「banner 生命周期结束时的最终资源」，应含收尾动作结果。

### 3.6 UI 适配（纳入本期，2026-08-08 评审 + 顺序裁决修订）

**形态**：**落地在 P78 已实现的「资源定义 Tab」的 lifecycle 占位区**（实施顺序 P78 先、P77 后——P78 §3.3 方案 X）。在详情面板「资源生命周期」区域编辑，不新建表格、不扩列。

**控件**（沿用 QFormLayout/QTableWidget + cellWidget 模式，与 P78 select_voucher 区域同构）：
- 到期时间：三态选择——`永不过期`（空）/ `对齐卡池`（QComboBox 列出配置中存在 `available_until` 的 banner id）/ `绝对时间`（天数 QSpinBox，TOML/UI 以天书写，解析边界 `*DAY`）
- 到期行为：三态 `不转换` / `转换到…` / `清零`；选「转换到…」时激活目标资源 QComboBox（选项来自 `resource_defs` 键）+ 比例输入（**两个 QSpinBox：源数量 from / 目标数量 to**，表达「每 from 个换 to 个」，如 3 A 换 2 B）

**读写拆分**（与 P78 同构）：
- 读：`store.resource_lifecycle.rules` 按 resource_id 建索引回填对应资源详情（无 rule 的资源 = 永不过期 + 不转换）
- 写：扫描资源详情，非空到期资源生成 `rules` 列表；全空则省略 `[resources.lifecycle]` 段

**保存校验**（对齐 ISSUE-104 一次性警告模式）：`对齐卡池` 引用的 banner 存在且有 `available_until`；`转换到…` 目标资源已定义；行为选「转换」但目标为空 → 警告；比例输入 `from`/`to` 为正整数（`from >= 1`）；设了到期时间但行为为「不转换」→ 警告（到期与动作必须成对，无保留态）。

**零改动面**：6 处只读引用（plan_search/analysis/comparison/process/retreat/strategy/worst_impact 面板的 `populate_gdr_combo`）只消费 `resource_defs`，不变。

### 3.7 不建模

- 到期结算的 GDR/结果会计——已由 3.5 记账语义覆盖（转换入总账、口径自然隔离），不新增独立事件字段
- 转换明细的逐笔事件记录（如 `resource_conversions`）——记账方案下对账天然成立，无需独立归因字段；若未来需要转换审计明细再评估

## 五、风险

| 风险 | 缓解 |
|------|------|
| 资源转换精度（非等额比例 3:2 时余额零头） | 完整兑换对 `q, r = divmod(balance, from)`，目标得 `q * to`，零头随源作废（到期即作废，无找回）；`from`/`to` 正整数校验 |
| 零头作废的语义是否符合预期 | 到期作废是核心语义——零头不可兑换即作废，不折算回任何资源；文档 + 验收用例明确 |
| `apply_resource_expiry` 在并行模拟中状态隔离 | 只在 `_run_compact` 的 per-sim state 上调用——不共享跨模拟状态 |
| 转换/清零入总账影响 GDR 分母 | 口径自然隔离——GDR 分母固定 `draw_resource`，与限定货币不相交；以限定货币为分母的 GDR 配置为罕见场景，文档约定不守卫 |
| 触发时机边界（real_time 仅等待时推进） | 与 P61 banner 时间关闭同语义，属模拟边界；验收用例用含等待策略覆盖 |
| `expire_with_banner` 引用的 banner 无 `available_until` | 配置期显式校验报错（ConfigError），不静默漂移 |
| 同一资源被多条 rule 声明 | 配置期拒绝（一个资源一个生命周期）；结算幂等（触发后移出待结算集合） |
| 到期时余额为 0 | `apply_resource_expiry` 空转跳过 |
| GUI 落地依赖 P78 已实现的资源定义 Tab | 实施顺序固定 P78 先、P77 后；生命周期区域在 P78 Tab 占位区内落地，不扩列、不新建表格 |

## 六、验收标准

- [ ] `[resources.lifecycle]` 段解析正确——`expire_at`/`expire_with_banner` 互斥、引用存在、`resource_id` 唯一、`on_expire` 两态互斥（转换含 from/to 正整数）、到期时间与 `on_expire` 成对，五类校验显式报错
- [ ] `expire_at` 绝对时间触发——模拟等待越过到期点 → `on_expire` 执行一次（转换/清零）
- [ ] `expire_with_banner` 对齐——到期时间 = 该 banner 的 `available_until`；banner 提前被抽空不影响到期（时间语义）
- [ ] 转换语义正确——等额 `from=1, to=1` 全量转目标；非等额 `from=3, to=2` 按完整对 `divmod` 换算，**零头随源作废**（源全额扣减，目标只得 `q*to`）；`clear` 清零
- [ ] **记账**——转换 = 源 `total_consumed` + 目标 `total_gained`（目标按完整对，零头不折算）；清零 = 源 `total_consumed`；对账恒等式 `final = initial + gained - consumed` 成立
- [ ] **GDR 隔离**——`draw_resource` 为分母的 GDR 在配置/不配置生命周期时结果一致
- [ ] **策略可知性**——`ctx.resource_expiry` 含每个到期资源的余额/剩余天数/到期行为；无生命周期声明的资源**不在** `resource_expiry` 中
- [ ] **GUI round-trip**——资源定义 Tab 的 lifecycle 区域设置生命周期（含非等额比例）→ 保存 → 重载 → 回填一致；现有配置（全为永不过期）保存后不生成 `[resources.lifecycle]` 段
- [ ] 无生命周期声明的资源行为完全不变（`resource_defs` 结构不动，gdr.py 零改动）
- [ ] G6 幻塔/蔚蓝/赛马娘 + FGO 清零 TOML 配置 → 含等待模拟 → 验证转换/清零
- [ ] 余额为 0 的资源不触发任何操作（空转跳过）
- [ ] 零头作废不产生负余额——`balance < from` 时源全额扣减、目标零入账
- [ ] 结算幂等——real_time 越过到期点后继续推进不重复转换
- [ ] pytest 全量通过
