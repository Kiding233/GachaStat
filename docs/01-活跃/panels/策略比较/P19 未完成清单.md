## 效应量专项设计（2026-06-12 讨论）

> 触发：实际使用中 1000+ 模拟量级下 p 值几乎必然显著，统计显著 ≠ 实际有意义。
> 定位：**增强解释**——保留现有 p 值体系，额外汇报效应量，由用户判断差异大小。
> 约束：不引入新依赖（scipy + numpy 已足够），复用 BootstrapEngine 计算 CI。

### 推荐指标集

**连续型 GDR（平均抽数、平均资源消耗等）：**

| 指标 | 公式 / 实现 | 说明 |
|------|------------|------|
| **Hedges' g** | `(mean_a - mean_b) / s_pooled`，小样本校正因子 | 过 N>1000 时 ≈ Cohen's d，方法论更严谨 |
| **CLES**（共通语言效应量） | `P(X_a > X_b)` = `np.mean(samples_a > samples_b)` | 最直观——「策略 A 在 53% 模拟中优于 B」，非统计用户秒懂 |
| **效应量 95% CI** | Bootstrap BCa（复用 `BootstrapEngine`） | 汇报不确定范围 |

**二项型 GDR（获得目标卡概率等）：**

| 指标 | 公式 / 实现 | 说明 |
|------|------------|------|
| **风险差（RD）** | `p_a - p_b` | 「策略 A 成功率高 3.2 个百分点」——比 OR 直观 |
| **NNT 类比** | `1 / (p_a - p_b)` | 「需多抽多少次才能多获一张目标卡」——对玩家极有意义 |
| **RD 95% CI** | Wilson 得分法（复用 `wilson_ci()`）或 Bootstrap BCa | 汇报不确定范围 |

**明确不纳入（及理由）：**

| 放弃项 | 理由 |
|--------|------|
| 优势比 (OR) | 解释门槛高，非统计用户易误读为风险比 |
| η²/ω² | 多组比较场景有用，当前以成对比较为主，属 Phase 3+ |
| Cohen 的小/中/大标签（0.2/0.5/0.8） | 社会/行为科学惯例，抽卡场景未必适用——只报数值 + CI，不贴标签 |

### 与现有架构的关系

- **CLES**：纯 NumPy 一行代码，零依赖
- **Hedges' g**：可手写（公式简单）或用 `pingouin.compute_effsize`（设计文档已提及）
- **Bootstrap CI**：直接复用 `BootstrapEngine`，无需新模块
- **Wilson CI**：已在 `process_analysis.py` 实现，直接调用

### 输出形式

以 **n×n 效应量矩阵表**（类 L3 p 值矩阵）为主，辅以 ECDF 叠加图上的 CLES 标注。不另建热力图 Tab——直接扩展 L1 描述统计表或 L3 p 值矩阵，在同一视图中呈现 p 值 + 效应量 + 方向。

### 重启条件

核心 L1-L4 功能稳定 + 用户在实际使用中确认「p 值过度敏感」构成解释障碍后，择机推进。
