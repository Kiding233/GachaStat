# 随机目标卡生成 — 设计文档

> 状态：待审核 | 日期：2026-06-16 | 关联计划：—

## 一、需求摘要

新增「按比例随机生成目标卡」功能。启用后每次模拟独立从 SSR 候选池中随机抽取 a% 的卡作为目标，考察策略在任意目标卡组合下的表现。

核心规则：
- 范围：限定 SSR（6 张）或全部 SSR（12 张），用户可选
- 比例 a%：5%-100%，步长 5%
- 每张随机目标卡需求量固定为 1
- 手动配置的目标卡作为「固定底牌」，随机抽取时**自动排除手动卡**，保证合并后总量 = ceil(a% × 候选池)
- 每次模拟独立重新抽取（`seed + sim_index` 保证确定性）
- 输出：与现有分析面板完全兼容——成功率、GDR 分布、热力图等均正确反映随机目标下的策略表现

## 二、信息流对比

### 当前

```
TOML → ConfigStore
         → target_specs = {card_id: quantity}   (一批共享)
              │
         run_batch_parallel(env, target_specs)
              ├─ 构建 1 个 TargetCardSet           (批次级单例)
              ├─ 构建 1 个 WorkerLocalExtractor    (进程级单例)
              └─ N 轮模拟共用同一套 target_set + extractor
```

### 新

```
TOML → ConfigStore
         ├─ target_cards (手动)
         ├─ random_target_enabled / pct / scope
              │
         create_provider(store) → TargetCardProvider
              │
         run_batch_parallel(env, provider)
              ├─ _wk_init(env, provider)            (provider 可 pickle)
              └─ 每轮 _wk_run_single:
                   ① provider.resolve(seed) → 随机 TargetCardSet
                   ② _run_single(env, target_set, seed)
                   ③ 新建 WorkerLocalExtractor(ts)  ← 用本轮目标造尺子
                   ④ extractor.process(compact)     ← 写 target_specs 入 agg
```

## 三、核心领域模型（`core/target_card.py`）

新增三个类和一个工厂函数，放在现有 `TargetCardSet` 之后。

### `TargetCardProvider`（协议基类）

```python
class TargetCardProvider:
    def resolve(self, seed: int) -> TargetCardSet:
        raise NotImplementedError
```

### `FixedProvider`

```python
class FixedProvider(TargetCardProvider):
    def __init__(self, targets: TargetCardSet):
        self._targets = targets
    def resolve(self, seed: int) -> TargetCardSet:
        return self._targets
```

现有行为的零开销包装。`targets` 由 `ConfigStore.target_cards` 构建。

### `RandomSampleProvider`

```python
class RandomSampleProvider(TargetCardProvider):
    def __init__(self, candidate_pool, manual_ids, pct, pool_lookup):
        # 所有字段为内置类型 → 可 pickle → 可传入 worker
        self._candidate_pool = list(candidate_pool)
        self._manual_ids = manual_ids
        self._target_count = max(1, ceil(len(candidate_pool) * pct / 100))
        self._pool_lookup = dict(pool_lookup)

    def resolve(self, seed: int) -> TargetCardSet:
        rng = random.Random(seed)
        needed = max(0, self._target_count - len(self._manual_ids))
        available = [cid for cid in self._candidate_pool
                     if cid not in self._manual_ids]
        picked = rng.sample(available, min(needed, len(available)))
        # 手动卡 + 随机卡 → TargetCardSet，每张 quantity=1
```

关键行为：`manual_ids` 从候选池排除 → 合并后目标数 = max(|手动|, ceil(pct% × |候选池|)) → 不重合。

### 签名变更

```diff
     env: SimulationEnv,
-    target_specs: Dict[str, int],
+    provider: TargetCardProvider,

 )
```

### 多进程路径

`_wk_init` 接收 provider 替代 target_specs：

```python
def _wk_init(env: SimulationEnv, provider: TargetCardProvider):
    global _wk_env, _wk_provider
    _wk_env = env
    _wk_provider = provider
    # 不再构建 _wk_target_set / _wk_extractor
```

`_wk_run_single` 每轮 resolve + 新建 extractor：

```python
def _wk_run_single(args):
    seed, initial_resources = args
    target_set = _wk_provider.resolve(seed)

    ts = {t.card_id: t.quantity_needed for t in target_set.targets}
    extractor = WorkerLocalExtractor(
        pool_end_times=_wk_env.pool_end_times,
        target_ids=set(ts.keys()),
        ssr_ids=_wk_env.ssr_ids,
        target_specs=ts,
        ...
    )
    compact = _run_single(_wk_env, target_set, seed, initial_resources)
    extraction = extractor.process(compact)
    ...
```

### 单进程 + 降级路径

同模式——循环内 `resolve + 新建 extractor`。

## 七、GDR 兼容（`core/streaming.py` + `gui/analysis_panel.py`）

### 问题

17 个 GDR 中 12 个强依赖 `target_specs`。当前 AnalysisPanel 用同一份 `target_specs` 计算全部 aggregate 的 GDR，随机模式下每轮目标不同 → 需要逐条计算。

### 方案

**步骤 1**：`WorkerLocalExtractor.process()` 在返回的 extraction_packet 中写入：

```python
'target_specs': dict(self._target_specs)
```

**步骤 2**：合并后的 `aggregate_data[i]` 自然携带 `target_specs`。

**步骤 3**：`AnalysisWorker._run_impl` 逐条创建 GDR calculator：

```python
for agg in aggregate_data:
    ts = agg.get('target_specs', ctx.target_specs)  # 兼容旧数据
    checker = make_gdr_calculator(self._store, ts, gdr_key, ...)
    values.append(checker.compute_gdr(agg))
```

### 性能

1000 次模拟 × 17 GDR = 17000 次 checker 创建，约 5ms → 可忽略。

## 十、风险矩阵

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| extractor 每轮新建 → 性能 | 极低 | 10μs/次 vs 模拟 10-100ms/次 |
| GDR 逐条计算 → 分析面板延迟 | 极低 | 5ms 额外开销 |
| Windows spawn pickle | 低 | Provider 全内置类型，已验证可 pickle |
| 旧 aggregate 无 target_specs | 低 | `agg.get('target_specs', ctx.target_specs)` 兜底 |
| seed 可复现性 | 极低 | `random.Random(seed)` 局部实例 |
| 手动/随机目标重复 | 无 | 候选池排除手动卡 |
| 向后兼容（现有行为） | 无 | `random_target_enabled=False` 默认关闭 |
