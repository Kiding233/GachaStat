# P77 资源生命周期与里程碑序列扩展——强制兑换与交替奖励

> 日期：2026-08-08 | 状态：设计中
> 触发：手册 §二十一 G6（限时货币到期转换）/ G18（终末地武器池交替循环）+ 里程碑引擎能力边界分析（2026-08-08 三轮设计评审收敛）
> 依赖：P58✅（MilestoneEngine）、P61✅（事件总线 + Banner 生命周期）、P63✅（溢出管道）、P60✅（state 基础设施）

## 一、问题

### 1.1 限时资源无生命周期（G6 + FGO 清零）

手册登记三款游戏 + FGO 存在「池结束 → 限定货币到期处理」机制，当前无法建模：

| 游戏 | 机制 | 到期行为 |
|------|------|---------|
| 幻塔 | 回火铸金（限定） | 卡池结束 → **等额转换**黑市铸金（常驻） |
| 蔚蓝档案 | 天井点数 | 卡池结束 → **转换**制造石碎片 |
| 赛马娘 | 天井点数 | 卡池结束 → **转换**四叶草 |
| FGO | 天井点数 | 卡池结束 → **清零**（不转任何常驻货币） |

**根因**：当前 `resource_defs: Dict[str, str]` 仅是「资源 id → 显示名」映射（[config_store.py:227](gacha_simulator/core/config_store.py#L227)），资源是**全局永驻**的一等公民，没有「作用域」（绑定哪个 banner）和「到期行为」两个属性。任何「限时货币/池专属货币」都无法表达。

### 1.2 里程碑引擎缺序列与事件能力（G18）

终末地武器池交替循环（手册 §16.4）：

```
80 抽大保底（必出当期 UP，1 次）→ 之后每 80 抽一个节点：
100 → 补充武库箱（自选非 UP 6★）
180 → 当期 UP 武器
260 → 武库箱
340 → UP 武器
…   （无限交替，A/B 循环）
```

当前 [MilestoneEngine](gacha_simulator/core/milestone.py) 只支持：
- `at=N` 单次触发（一次性）
- `every=N` 周期触发（**同奖励**重复）

**缺失能力**：
1. **交替奖励序列**——`every=N` 触发时奖励 A/B 循环切换，无法表达「武库箱 ↔ UP」交替
2. **事件后启动计数**——循环从「大保底触发」后才开始，而非模拟开始
3. **起始偏移**——首节点在事件后第 20 抽（100 = 80 大保底 + 20），即周期序列的相位偏移

## 二、目标

- `ResourceDef` 或等效机制支持「作用域 + 到期行为」——`scope`（绑定 banner）+ `on_expire`（转换/清零）
- Banner 结束事件触发资源到期结算——复用 P61 事件总线，不新建事件系统
- `MilestoneDef` 支持 `alternate_rewards` / `offset` / `start_after`——覆盖 G18 交替循环
- 覆盖游戏：终末地（G18）、幻塔/蔚蓝档案/赛马娘（G6）、FGO（清零）
- 保持 `resource_defs: Dict[str, str]` 结构不动——不破坏 gdr.py 与 6 处 GUI 引用

## 三、方案

### 阶段 1（R1）：里程碑序列与事件启动扩展

**新增位置**：[core/milestone.py](gacha_simulator/core/milestone.py) + [config_store.py](gacha_simulator/core/config_store.py) 的 `MilestoneDef`

```python
@dataclass
class MilestoneDef:
    name: str
    threshold: int = 40
    repeat: bool = False
    max_triggers: int = 0
    bonus_reward: dict = field(default_factory=dict)
    banner: str = ""
    # ── P77 新增（全部带默认值，向后兼容）──
    alternate_rewards: List[dict] = field(default_factory=list)  # 交替奖励序列（空=原行为）
    offset: int = 0            # 首节点相位偏移（0=从 threshold 起）
    start_after: str = ""      # 事件后启动计数（空=模拟开始即计数）
```

**引擎逻辑（MilestoneEngine）**：

```python
def __init__(self, defs, seed=42):
    # ... 原有状态 ...
    self._alt_index: Dict[str, int] = {}        # 交替奖励当前索引
    self._started: Dict[str, bool] = {}         # start_after 事件是否已触发

def on_event(self, event_type: str, **data):
    """接收 notifier 事件——start_after 事件触发后激活计数。"""
    for name, md in self._defs.items():
        if md.start_after and not self._started[name] and event_type == md.start_after:
            self._started[name] = True

def after_draw(self, banner_id, pool_id):
    # 触发判定前置守卫：
    for name, md in self._defs.items():
        if md.start_after and not self._started[name]:
            continue                            # 事件未触发——不计数
        c = self._counters.get(name, 0) + 1
        self._counters[name] = c
        if c < md.threshold + md.offset:        # offset 推后首节点
            continue
        # 触发——交替序列取奖励
        if md.alternate_rewards:
            reward = md.alternate_rewards[self._alt_index.get(name, 0) % len(md.alternate_rewards)]
            self._alt_index[name] = self._alt_index.get(name, 0) + 1
            bonus = self._resolve_bonus_from(reward)   # 从交替项解析
        else:
            bonus = self._resolve_bonus(md)
        # ... 原有 repeat / max_triggers 生命周期管理 ...
```

**关键时序**：`start_after` 事件由 `on_event()` 接收（gacha_service 在模拟循环中转发现成事件），计数器在事件前冻结、事件后从 0 累加。

### 阶段 2（R2）：资源生命周期——scope + on_expire

**设计决策**：不修改 `resource_defs: Dict[str, str]`（波及 gdr.py 的 `for rid, rname in resource_defs.items()` + 6 处 GUI），**新增独立配置段** `resource_lifecycle`——只有声明了生命周期的资源才参与到期结算，其余资源行为完全不变。

**新增位置**：`config_store.py` + `config_toml.py` + `gacha_service.py`（或 banner 生命周期事件点）

```python
@dataclass
class ResourceLifecycle:
    """限时资源生命周期——scope 绑定 banner，到期执行 on_expire。"""
    resource_id: str            # 作用对象（如 "tof_token_a"）
    scope: str = ""             # 关联 banner id（空 = 不触发）
    on_expire: Optional[dict] = None   # {convert_to: str, rate: float} 转换 | {clear: true} 清零 | None 保留

@dataclass
class ResourceLifecycleConfig:
    enabled: bool = True
    rules: List[ResourceLifecycle] = field(default_factory=list)
```

**TOML 配置**：

```toml
[resources.lifecycle]
enabled = true
rules = [
    # 幻塔——回火铸金到期转黑市铸金（等额）
    { resource_id = "tof_token_a", scope = "banner_tof_weapon_a",
      on_expire = { convert_to = "tof_token_black", rate = 1.0 } },
    # FGO——天井点数到期清零
    { resource_id = "fgo_spark_points", scope = "banner_fgo_limited",
      on_expire = { clear = true } },
]
```

**触发点**：`gacha_service.py` 在 Banner 生命周期事件（P61 `pool_exhausted` 等）后调用 `apply_resource_expiry(banner_id, state)`——遍历 `resource_lifecycle.rules`，匹配 `scope == banner_id` 的资源，执行 `on_expire`：

```python
def apply_resource_expiry(self, banner_id: str, state: GachaState) -> None:
    """P77——Banner 结束事件触发资源到期结算。"""
    for rule in self.resource_lifecycle.rules:
        if rule.scope and rule.scope != banner_id:
            continue
        balance = state.resources.get(rule.resource_id, 0)
        if balance <= 0:
            continue
        if rule.on_expire and 'convert_to' in rule.on_expire:
            rate = rule.on_expire.get('rate', 1.0)
            state.gain(rule.on_expire['convert_to'], balance * rate)
            state.spend(rule.resource_id, balance)      # 扣减源资源
        elif rule.on_expire and rule.on_expire.get('clear'):
            state.spend(rule.resource_id, balance)      # 清零
        # 无 on_expire → 保留
```

**不建模**：到期结算的 GDR/结果会计——资源金额已在总账 `resources` 中，转换是「同账户不同科目」的调账，不产生新收益；仅需在 `bonus_events` 或事件日志记录一条转换元数据（审计用）。

## 五、风险

| 风险 | 缓解 |
|------|------|
| `start_after` 事件源不明确（哪些事件可触发） | MVP 仅支持 P61 已 emit 的事件类型（`after_draw` + `pity_triggered` 标志）；如需 `pool_end` 事件在阶段 2 一并 emit |
| `offset` 与 `threshold` 语义混淆 | 明确 `offset` 是相位偏移（首节点 = threshold + offset），不改 `threshold` 语义；文档示例覆盖 |
| 交替序列长度与周期不匹配（2 项交替 vs 3 抽周期） | 索引模长度——`% len(alternate_rewards)` 自然循环，不要求整除 |
| 资源转换精度（rate=0.5 时余额奇数） | 转换金额四舍五入到整数；`rate` 仅支持正小数 |
| `apply_resource_expiry` 在并行模拟中状态隔离 | 只在 `_run_single` 的 per-sim state 上调用——不共享跨模拟状态 |
| 到期转换是否算「新增资源收益」（GDR 影响） | 已决策不算——调账而非收益，不参与 GDR 计算 |
| GUI 无资源生命周期编辑入口 | MVP 仅 TOML 手写；GUI 编辑入口作为后续增强（若需求明确再加） |
