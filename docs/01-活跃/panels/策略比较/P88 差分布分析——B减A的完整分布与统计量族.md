## 一、问题

### 1.1 现有对比分析缺一层

对比分析面板（`gui/comparison_analysis_panel.py`）现在是四层：

| 层 | 内容 | 产出形态 |
|---|---|---|
| L1 | `DescriptiveStats` 描述统计 + PMF/ECDF 叠加 | 每数据集一行标量 + 分布图 |
| L2 | DD Bootstrap 随机占优（FSD/SSD/TSD，PySDTest Donald-Hsu 2016） | n×n 二元显著标记矩阵 |
| L3 | 假设检验（KS/MWU/ttest + Holm/BH 校正） | n×n p 值矩阵 |
| L4 | 双 GDR 帕累托前沿 | 散点 + 前沿连线 |

缺的是**成对差异的完整分布**。现有各层都只给点或二元判定：

- L1 只给单数据集的边际汇总，两个数据集的差只体现在「均值差」这一个数上
- L2 给「是否随机占优」的二元结论 + p 值，不给「差多少、多大概率」
- L3 给 p 值，但 p 值回答的是「能否拒绝无差异」，不是「差异有多大、朝哪边」

具体缺什么，用三个现有面板答不出的问句说明：

- 「B 比 A 多拿至少 1 张目标卡的概率是多少？」
- 「两个策略的结果在多大比例的模拟里完全一样？」
- 「B 相对 A 的平均增益是多少、平均损失是多少、比值多少？」

这三个问句背后的量，L2 的 FSD 检验在数学上隐含（Strassen 定理：A 一阶随机占优 B 等价于存在某耦合使 A ≤ B 几乎必然），但从未被显式报出。L3 的 Mann-Whitney 统计量 `U/(n_A·n_B)` 恰好是 `P(B > A)` 的估计，也同样未被报出。

### 1.3 范围界定：只做卷积版

D = B − A 的分布有两种语义：

| 版本 | 构造 | 语义 | 本计划 |
|---|---|---|---|
| 配对版 | 同随机数下 `d_i = b_i − a_i` | 同一运气下换策略（弱化反事实） | **不做** |
| 卷积版 | 两批独立样本的差 `F_B * F_{−A}` | 重开一局换策略（含运气差异） | **做** |

不做配对版的**实测依据**（非判断，是查证结果）：

1. `service/batch_simulator.py` 并行路径用 `imap_unordered`，`aggregate_data` 按完成顺序排列，与 seed 顺序无关
2. `core/streaming.py` 的 `extract_aggregate` 产出的记录**无 seed 字段**，事后无法回溯排序
3. `core/pool.py` 用 `random.random()` 顺序消费随机数，两条轨迹仅在动作序列完全一致的前期共用随机数流，一旦分叉即错位

即「同种子索引配对」当前物理上做不到，需先补 seed 溯源基础设施。配对版留作后续增量（见 §三.6）。

卷积版的额外优势：均值层面零信息损失（`E[D] = E[B] − E[A]` 是期望线性性的恒等式，配对与否均成立），且与现有数据管线零冲突（并行路径产出的样本天然独立）。

## 二、目标

1. **给定两个数据集与一个 GDR，产出 D = B − A 的完整经验分布**，精确（不是近似），且成本与样本量解耦
2. **产出一族差分布统计量**：中心、三段概率、正负期望分解、离散度，各带置信区间
3. **呈现层落在对比分析面板**，默认视图为 D 的 PMF，累积视图为 CDF
4. **与现有 L3 交叉自洽**：`P(D>0)` 应与 MWU 统计量归一化值一致，不一致即 bug

## 三、方案

### 3.1 核心算法：唯一值压缩 + 唯一值对枚举（设计定稿）

**不用 `np.convolve`，不用等距直方图。** 实测依据见 §3.2。

```
uA, cA = np.unique(a, return_counts=True)      # 唯一值 + 频数
uB, cB = np.unique(b, return_counts=True)
d = (uB[None, :] - uA[:, None]).ravel()        # |uA|·|uB| 个差值
w = (cB[None, :] * cA[:, None]).ravel()        # 对应权重
# 按差值聚合：np.unique(d, return_inverse=True) + np.add.at(c, inv, w)
# 概率 = c / c.sum()
```

成本 O(|u_A|·|u_B|)，**与 n 无关**。实测 |u| 在 25 上下，即约 600 次运算；输出支撑最多 600 余点，符合项目 O(1) 内存口径。

保护分支：若 |u_A|·|u_B| 超过阈值（建议 1e6），退回 ECDF 采样或 FFT。按实测此分支不会触发。

### 3.2 精确性实证（不依赖判断，已跑数）

把 6 个 GDR 的样本对半分成 A、B 两组（独立样本，符合卷积语义），压缩路径与暴力枚举 O(n_A·n_B) 逐点对照：

| GDR | nA/nB | \|uA\|/\|uB\| | 暴力对数 | 压缩对数 | D 支撑 | 最大差值偏差 | 概率最大偏差 | 概率和 |
|---|---|---|---|---|---|---|---|---|
| resource_remaining | 200/200 | 24/23 | 40000 | 552 | 204 | 0 | 0 | 1.000000000000 |
| non_pity_draws | 200/200 | 24/24 | 40000 | 576 | 204 | 0 | 0 | 1.000000000000 |
| resource_efficiency | 200/200 | 27/25 | 40000 | 675 | 669 | 0 | 0 | 1.000000000000 |
| target_achievement | 200/200 | 3/3 | 40000 | 9 | 7 | 0 | 0 | 1.000000000000 |
| resource_per_card | 200/200 | 27/25 | 40000 | 675 | 470 | 0 | 0 | 1.000000000000 |
| weighted_satisfaction | 200/200 | 3/3 | 40000 | 9 | 5 | 0 | 0 | 1.000000000000 |

`dmax = 0`、`pmax_diff = 0`，是逐位相同而非接近。

**为何不用 `np.convolve`（实测反例）：**

| GDR | 暴力支撑 | np.convolve 输出长度 | 一致 |
|---|---|---|---|
| resource_remaining | 204 | 40481 | 否 |
| non_pity_draws | 204 | 258 | 否 |
| pity_draws | 5 | 5 | 是 |
| all_targets | 3 | 3 | 是 |

原因：`np.convolve` 要求格距为 1 的稠密数组。资源类 GDR 格距 160（单抽成本），值域 13760，输出 40481 个桶而真实支撑仅 204 个，多出的是零概率填充。格距越大浪费越狠。

### 3.3 GDR 取值形态实测（n=300，决定实现分支）

| 类型 | GDR | 实测特征 |
|---|---|---|
| 整数格点 | resource_remaining, resource_consumed, non_pity_draws, pity_draws, target_card_draws, weighted_satisfaction, total_card_value, all_targets, extra_target | 格距 160（资源类）或 1（计数类） |
| 有理格点（分母固定） | target_achievement, target_collection, per_pool_draw_rate（格距 1/6）、resource_per_card（格距 80/3） | 乘固定分母即整数 |
| 不等距连续 | **resource_efficiency**（值域 1e-4，最小间距 2e-7，35 个不同值）、weapon_character_ratio | **无公共格距**，乘任何因子都无法整除 |

第三类证明「先放大成整数再卷积」走不通：`resource_efficiency = achieved/consumed`，consumed 每次不同（49920 到 63680，160 的倍数），分母变动导致无公共格距。而压缩路径对三类**统一处理**，这是它优于等距直方图的根本原因。

实测 distinct/n 比值：最高 0.117（resource_efficiency），最低 0.003。n 增大时 |u| 的上限由「值域 ÷ 格距」决定，不由 n 决定。

### 3.4 统计量族（设计定稿）

| 类别 | 统计量 | 说明 |
|---|---|---|
| 中心 | `E[D]`、中位数、各分位数 | `E[D] = E[B] − E[A]` 恒等式；**差值的分位数 ≠ 分位数之差**，实现须写死用前者 |
| 三段概率 | `P(D=0)`、`P(D>0)`（=CLES）、`P(D>δ)`、`P(D<−δ)`、`P(\|D\|≤δ)` | `P(D=0)` 是抽卡场景主力项，不可省 |
| 正负分解 | `E[D⁺] = E[max(D,0)]`、`E[D⁻] = E[max(−D,0)]`、比值 | 恒等式 `E[D] = E[D⁺] − E[D⁻]`；`E[D⁻]` 是下侧部分矩 LPM(1)；比值即盈亏比 |
| 离散 | Var、标准差、IQR | IQR 对厚尾比 std 稳健 |

**δ 的性质**：用户显式输入的可选参数，不在默认路径上，整组统计量挂在 `P(D>x)` 曲线后面按需取。因此不构成 P19 第 5 项（Almost Stochastic Dominance）被暂缓的同一问题（那项要做默认路径且无自然取值）。建议默认值从 GDR 语义导出（如「多 1 张目标卡」），UI 可调并显示对应的绝对量。

**统一形式（可选）**：`Ω(θ) = E[(D−θ)⁺] / E[(θ−D)⁺]`（Omega 比率，θ 即 δ）。该函数与分布函数一一对应，即完整刻画差分布；三段概率、正负期望比、分位数都是它的取样点。可作为「一条曲线替代一堆标量」的呈现选项。

### 3.5 精度：两样本 bootstrap（设计定稿）

**必须避开的坑**：`P(D>0) = (1/(n_A·n_B)) ΣΣ 1[b_j > a_i]` 表面是 n_A·n_B 个伯努利样本，但这些指示变量严重不独立（共用同一批 a 和 b），**有效样本量在 `min(n_A, n_B)` 量级**。直接套二项或 Wilson CI 会把方差低估几个数量级，结论虚假精确。

正确做法：**bootstrap 重抽 A、B 两批样本**（各抽各的，保持独立性），每次重算统计量，取分位数区间。

| 量 | 方法 | 可复用 |
|---|---|---|
| `P(D>δ)` 等比例量 | 两样本重抽 | 需新写包装（`BootstrapEngine.bootstrap_probability` 吃单序列，不能直接喂 |u_A|·|u_B| 个差值） |
| `E[D]`、`E[D⁺]`、`E[D⁻]` | `BootstrapEngine.bootstrap_mean` | 需两样本重抽包装 |
| 分位数 | `BootstrapEngine.bootstrap_quantile` | 同上 |
| 厚尾诊断 | `BootstrapEngine.detect_heavy_tail` | 直接可用，用于决定是否上 BCa |

### 3.6 三个实现细节（必须写死）

1. **差值相等的浮点容差聚类**。`resource_efficiency` 实测 675 个唯一值对产生 669 个不同差值（6 对碰撞）。数学上相等的差值在浮点下可能不等（不同运算路径差 1ulp），会把本该合并的桶拆开。差值聚合时做一次容差聚类（排序后按相对容差 1e-12 扫描合并）。本次未发生，但不可依赖。

2. **退化检测**。实测当前配置下 `ssr_collection`、`extra_target`、`weapon_character_ratio` 的 distinct = 1（恒为 0），`draw_conversion_efficiency` 恒为 1。这些 GDR 的差分布退化为单点 {0}，UI 须显式提示「该指标在当前配置下无变异」，不得画一条垂直线。可复用 `core/distribution.py` 的 `_count_distinct() < 20` 判据。

3. **方向约定**。`resource_consumed`（`core/gdr.py:397`）与 `resource_per_card`（`core/gdr.py:431`）是 `lower_is_better = True`，其上 `D = B − A` 为负才是 B 好。沿用现有 `lower_is_better` 标志翻成「越高越好」再算，否则用户在正负号上读反。

### 3.7 呈现层设计（阶段 2，形态待定）

- **默认视图：D 的 PMF 柱状图**。x 轴按实际支撑摆放（去重排序后直接作柱 x 坐标），宽度取相邻支撑间距中位数。理由：D 是单分布无多曲线遮挡问题；实测支撑高度离散（target_achievement 的 D 只有 5~7 个取值），柱状比阶梯好读；`P(D=0)` 原子直接可见；δ 三段着色在柱状上天然（按区间给柱子染色）。
- **累积视图：CDF `F_D(x)`**，不用生存函数。理由：与 L1 的 ECDF、L2 的积分 CDF 方向一致，同一面板内不应出现方向反转。`P(D>x)` 的读数用标注或 hover 补。
- **Y 轴用概率质量，不用密度**。L1 现用 `histnorm='probability density'`（连续模式），那对格点数据是错的，柱子高度会变成 1/格距 的量纲，格距 160 与格距 1 的两个 GDR 之间无法比较。
- **自适应**：支撑小（约 ≤50）用 PMF，支撑大（resource_efficiency 实测 669）用 CDF。参考 `core/gdr_binning.py` 的 `bar_mode` 判据。
- **二项型 GDR 走 RD/NNT 分支**：取值 0/1 的 GDR（如 `all_targets`）差分布只有 −1/0/+1 三个原子，全部统计量退化，`P(D=1)` 即风险差 RD。这类直接报 RD + NNT 更清楚（P19 §效应量专项设计已有此设计）。
