# P41 目标卡实例权重架构改造——可行性分析

> 日期：2026-06-12 | 状态：分析中
> 来源：用户需求——同名目标卡 ≥2 张时支持按实例（副本）区分权重和加入/删除顺序
> 涉及层：config → core → service → gui（全栈）

---

## 1. 目标

**现状：** 目标卡系统以 `card_id` 为键合并同名卡。`target_specs: Dict[str, int]`（`{card_id: 需求数量}`）。所有权重（GDR 的三类 + 方案搜索的加入/删除顺序）都按 `card_id` 索引 → 同一张卡的多个副本共享完全相同的权重。

**目标：** 当目标卡要求 ≥2 张同名卡时，每个副本（实例）可以有独立的权重和独立的加入/删除顺序。架构上支持未来任意新增权重类型，不再需要改数据结构。

## 2. 核心数据结构变更

### 2.1 新增 `TargetInstance`

```python
from typing import Union, Dict, List, Any, Callable

WeightValue = Union[float, 'ExpressionWeight']


@dataclass
class TargetInstance:
    """一张目标卡的一个逻辑行。quantity≥1，实例消耗按顺序。"""
    card_id: str
    pool_ids: List[str]
    quantity: int = 1
    weights: Dict[str, WeightValue] = field(default_factory=dict)
    # 键：desire_weight / miss_cost_weight / card_value / add_order / remove_order
    # 值：float（所有实例共享）或 ExpressionWeight（动态求值）
```

### 2.2 示例

```python
target_instances = [
    # 同名卡 ×2，不同权重 → 两行，每行 quantity=1
    TargetInstance("limited_ssr_1", ["pool_c1"], quantity=1,
        weights={"desire_weight": 2.0, "miss_cost_weight": 3.0, "add_order": 2.0}),
    TargetInstance("limited_ssr_1", ["pool_c1"], quantity=1,
        weights={"desire_weight": 0.5, "miss_cost_weight": 0.8, "add_order": 0.3}),

    # 动态表达式：有了 A 之后 desire 降为 0.1
    TargetInstance("limited_ssr_2", ["pool_c2"], quantity=1,
        weights={"desire_weight": ExpressionWeight(
            "0.1 if acquired.get('limited_ssr_1',0)>0 else 2.0"),
            "add_order": 1.0}),

    # 按 instance_index 递减（quantity=3 一行搞定）
    TargetInstance("limited_ssr_3", ["pool_c3"], quantity=3,
        weights={"desire_weight": ExpressionWeight("2.0 / (instance_index + 1)")}),
]
```

### 2.5 权重系统设计（仅两层）

`InstanceWeight` 不单独存在——`instance_index` 已在 `WeightEvalContext` 中，表达式可以直接用：
- `$[2.0, 0.5][instance_index] if instance_index < 2 else 1.0$` 等价于 `InstanceWeight({0: 2.0, 1: 0.5})`
- `$2.0 / (instance_index + 1)$` 更灵活——不限于离散值

因此类型层次只有两层：

```python
WeightValue = Union[float, 'ExpressionWeight']
# float  = 静态值，覆盖 90% 用例。所有实例共享同一值
# ExpressionWeight = 任意 Python 表达式，覆盖动态/跨卡/参数化/按实例索引


class ExpressionWeight:
    """可序列化的权重表达式——编译为受限 callable。"""
    expression: str

    def compile(self) -> Callable[['WeightEvalContext'], float]:
        code = compile(self.expression, '<weight_expr>', 'eval')
        def evaluator(ctx: WeightEvalContext) -> float:
            return eval(code, {'__builtins__': {}}, ctx.to_namespace())
        return evaluator
```

方案搜索的边界也因此更干净：

```python
def validate_search_weight(spec: WeightValue, key_name: str) -> float:
    """add_order / remove_order：float 通过，ExpressionWeight 拒绝。"""
    if isinstance(spec, (int, float)):
        return float(spec)
    raise SearchWeightError(
        f"{key_name} 不接受表达式: {spec.expression}。"
        f"同名卡不同排序权重请用多行实例（每行 quantity=1 + 不同 float）。"
    )
```

无 `is_static()`、无 `InstanceWeight`、无中间地带。

#### 2.5.2 求值上下文

所有的参数都通过 `WeightEvalContext` 暴露。**用户表达式可以引用其中任意字段——不做限制。**

```python
@dataclass
class WeightEvalContext:
    # ── 实例身份 ──
    card_id: str                          # 当前卡 ID
    instance_index: int                   # 该同名卡中的序号 (0-based)

    # ── 模拟状态 ──
    acquired: Dict[str, int]              # {card_id: 已抽到累计数量}
    draw_number: int                      # 当前总抽数 (1-based)
    simulation_day: int                   # 当前模拟日
    active_pool_id: str                   # 当前活动池
    resources: Dict[str, float]           # 当前剩余资源

    # ── 用户扩展 ──
    extra: Dict[str, Any]                 # 用户自定义参数，自由注入

    def to_namespace(self) -> Dict[str, Any]:
        return {
            'card_id': self.card_id,
            'instance_index': self.instance_index,
            'acquired': self.acquired,
            'draw_number': self.draw_number,
            'simulation_day': self.simulation_day,
            'active_pool_id': self.active_pool_id,
            'resources': self.resources,
            'extra': self.extra,
        }
```

#### 2.5.3 实例消耗语义（顺序模型）

抽到第 k 张该卡 → `instance_index = k` → 权重求值。

```
card_A ×2: desire_weight = $[2.0, 0.5][instance_index] if instance_index < 2 else 1.0$
  抽到 0 张 → 全部缺失
  抽到 1 张 → instance_index=0 → desire=2.0   ✓
  抽到 2 张 → instance_index=1 → desire=0.5   ✓

更简洁的等价写法：$2.0 / (instance_index + 1)$
```

**`instance_index` 的推导机制：**

当前设计：GDR 事后计算时从 `card_counts`（CompactResult）出发，维护局部 `instance_counter: Dict[str, int]` 递减计数器——每次消耗一个实例时自增，模拟「消耗到第几个」。这是**两本账**——`card_counts` 和 `instance_counter` 存同一信息的不同切面。

**P58 就绪后的简化（双重效应）：**

1. **instance_index 推导简化：** `state.acquired[card_id]` 既是「已有几张」的答案，也是「下一张是第几张」的答案——`instance_index = state.acquired.get(card_id, 0)`（抽前值）。消灭局部递减计数器，一份数据两种读法。运行时（策略/流式分析）直接读取，事后（GDR）同样适用。见 P58 §4.2。

2. **WeightEvalContext.acquired 来源统一：** 没有 P58A 时，`acquired` 有两个来源——事后 GDR 从 `compact.card_counts` 读，运行时流式分析从 `SimulationStats.acquired_counts` 读（两本账，可能不一致）。P58A 之后，两处都读 `state.acquired`——单一真相源。见 P58 §4.2「对 P41 的简化效应」。

#### 2.5.4 方案搜索的边界

排序键（`add_order`/`remove_order`）必须在模拟前确定全序。只接受 `float`，`ExpressionWeight` 一律拒绝——用户如需同名卡不同排序权重，用多行（每行 `quantity=1` + 不同 `float`）。见 §6.1。

## 4. 配置格式变更

### 4.1 新格式：`config.toml` `[[targets]]` 节扩展

P53 已将全部配置统一到 `config.toml`。P41 在现有 `[[targets]]` 节基础上内联权重列，废弃独立的 `[[weights]]` 节。

# 权重值语法：

### 4.2 字段定义

| 字段 | 类型 | 默认值 | 说明 | UI 编辑入口 |
|------|------|--------|------|-----------|
| `card_id` | str | — | 必填 | 目标卡 Tab |
| `quantity` | int | 1 | 该条目代表的目标卡副本数 | 目标卡 Tab |
| `pool_ids` | `List[str]` | — | 该卡可出现的池子 | 目标卡 Tab |
| `desire_weight` | WeightValue | 1.0 | 抽取意愿（→ GDR satisfaction） | 目标卡 Tab |
| `miss_cost_weight` | WeightValue | 1.0 | 错失代价（→ GDR 惩罚） | 目标卡 Tab |
| `card_value` | WeightValue | 1.0 | 卡牌价值（→ GDR total_card_value） | 目标卡 Tab |
| `add_order` | float | 1.0 | 前进法加入优先级（高→先加入） | **方案搜索面板** |
| `remove_order` | float | 1.0 | 后退法移除优先级（低→先移除） | **方案搜索面板** |

`add_order` / `remove_order` 仅接受 `float`（拒绝表达式），消费者唯一（方案搜索），编辑入口在方案搜索面板。
目标卡 Tab 不显示这两列——其职责收敛为「想要哪些卡 + 抽到了值多少分」。

### 4.3 表达式语法

- `"$...$"` 包裹的是 Python 表达式（TOML 中为字符串值），求值时命名空间 = `WeightEvalContext.to_namespace()` 的所有字段
- 可用变量：`instance_index`, `acquired`, `draw_number`, `simulation_day`, `active_pool_id`, `resources`, `extra`
- 安全性：`eval()` 关闭 `__builtins__`，只能做纯计算，不能调 `open`/`import` 等
- `add_order`/`remove_order` 禁用表达式（方案搜索需要静态全序）
- 预编译校验：`ExpressionWeight` 构造时即 `compile()`——语法错误在加载配置时暴露，对齐 P55 的「配置时校验」哲学

### 4.4 扩展性

新增权重列 = 在 `[[targets]]` 中加一个可选字段 + 在 `TargetInstance.weights` 键名中注册即可。未知字段忽略（向前兼容）。

### 4.5 `[[weights]]` 节废弃

`config.toml` 中独立的 `[[weights]]` 节废止——内容合并入 `[[targets]]` 的内联权重字段。加载时若 `[[weights]]` 存在且 `[[targets]]` 条目不包含权重字段 → 触发一次性自动迁移，将权重填入对应 `[[targets]]` 条目并删除 `[[weights]]` 节。

## 5. GDR 计算改造（核心算法层）

### 5.1 当前问题

```python
# _gdr_weighted_satisfaction (gdr.py:392-406)
for card_id, qty in target_specs.items():
    got = min(card_counts.get(card_id, 0), qty)
    satisfaction += got * desire_weights.get(card_id, 1.0)  # 所有副本同一权重
```

### 5.2 改造方案

三步管道：`ExpressionWeight → compile() → _resolve_weight(spec, ctx) → float`

```python
def _gdr_weighted_satisfaction_v2(compact, target_instances, **kwargs):
    card_counts = dict(compact.get('card_counts', {}))  # 副本
    satisfaction = 0.0
    instance_counter: Dict[str, int] = {}               # 追踪同名卡已消耗实例数

    for inst in target_instances:
        cid = inst.card_id
        got = card_counts.get(cid, 0)

        for i in range(inst.quantity):                   # 每个逻辑实例逐一消耗
            idx = instance_counter.get(cid, 0)
            ctx = WeightEvalContext(
                card_id=cid,
                instance_index=idx,
                acquired=compact.get('card_counts', {}),  # 原始 counts（非递减副本）
                draw_number=compact.get('total_draws', 0),
                simulation_day=compact.get('final_day', 0),
                active_pool_id='',                        # GDR 事后计算，无当前池
                resources=compact.get('final_resources', {}),
                extra=kwargs.get('extra', {}),
            )

            if got > 0:
                got -= 1
                instance_counter[cid] = idx + 1
                desire_spec = inst.weights.get('desire_weight', 1.0)
                satisfaction += _resolve_weight(desire_spec, ctx)
            else:
                miss_spec = inst.weights.get('miss_cost_weight', 1.0)
                satisfaction -= _resolve_weight(miss_spec, ctx)

    return satisfaction


def _resolve_weight(spec: WeightValue, ctx: WeightEvalContext) -> float:
    """统一求值入口。float → 直接返回，ExpressionWeight → compile + eval。"""
    if isinstance(spec, (int, float)):
        return float(spec)
    # 编译缓存（compiled_fn 可挂在 spec 实例上，只编译一次）
    if not hasattr(spec, '_compiled'):
        spec._compiled = spec.compile()
    return spec._compiled(ctx)
```

### 5.3 无权重函数简化为遍历 quantity

```python
def _gdr_target_achievement_v2(compact, target_instances, **kwargs):
    card_counts = compact.get('card_counts', {})
    total = sum(inst.quantity for inst in target_instances)
    got = dict(card_counts)
    achieved = 0
    for inst in target_instances:
        c = got.get(inst.card_id, 0)
        allocated = min(c, inst.quantity)
        got[inst.card_id] = c - allocated
        achieved += allocated
    return achieved / total if total else 0.0
```

## 6. 方案搜索改造

核心原则：**数据的消费者拥有数据的编辑权。** `add_order` / `remove_order` 的唯一消费者是方案搜索——编辑界面迁入方案搜索面板。目标卡 Tab 只保留 GDR 评估权重（desire / miss_cost / card_value）。

### 6.1 静态约束

方案搜索的排序键在模拟前确定全序，不接受依赖运行时状态的表达式。

```python
def validate_search_weight(spec: WeightValue, key_name: str) -> float:
    """add_order / remove_order 只接受静态 float。"""
    if isinstance(spec, (int, float)):
        return float(spec)
    raise SearchWeightError(
        f"{key_name} 不接受表达式: {spec.expression}。"
        f"同名卡不同排序权重请用多行实例（每行 quantity=1 + 不同 float）。"
    )
```

### 6.2 从 TargetInstance 提取排序键

```python
def get_sorted_instances(instances: List[TargetInstance], key: str, reverse: bool
                         ) -> List[Tuple[float, int, TargetInstance]]:
    """返回按权重排序的 (score, instance_index, TargetInstance) 列表。"""
    scored = []
    for inst in instances:
        spec = inst.weights.get(key, 1.0)
        for i in range(inst.quantity):
            score = validate_search_weight(spec, key)  # float 通过，表达式拒绝
            scored.append((score, i, inst))
    scored.sort(key=lambda x: x[0], reverse=reverse)
    return scored
```

### 6.3 PlanSearchEngine 改造

- `_get_sorted_card_ids()` → `_get_sorted_instances()`
- 排序键：权重值 float，同名卡通过 `instance_index` 区分
- 后退法：低 `remove_order` 优先移除；前进法：高 `add_order` 优先加入
- `ExpressionWeight` → 构建时校验拒绝，不等到运行时崩溃

实例的增删属于**目标卡 Tab**（card_id / qty / pool_ids 全在那）。方案搜索面板不提供新增/删除按钮——当用户在目标卡 Tab 增删实例后，方案搜索面板重新从 ConfigStore 读取实例列表，自动刷新表格。

## 7. 流式分析改造

### 7.1 `WorkerLocalExtractor._check_success()`

```python
# 旧：检查 {card_id: quantity}
for cid, qty in self._target_specs.items():
    if cumulative_cards.get(cid, 0) < qty:
        return False

# 新：检查实例列表
def _check_success(self, cumulative_cards):
    remaining = dict(cumulative_cards)
    for inst in self._target_instances:
        if remaining.get(inst.card_id, 0) < 1:
            return False
        remaining[inst.card_id] -= 1
    return True
```

## 10. 风险与边界情况

| 风险 | 等级 | 缓解 |
|------|------|------|
| `target_specs: Dict[str, int]` 签名遍布 30 个文件 | 高 | 渐进迁移：先加 `target_instances` 参数，`target_specs` 标记 deprecated 并存一版 |
| 实例消耗顺序 | 低 | **已确定：顺序消耗模型（§2.5.3）** |
| GDR 权重递减逻辑——`card_counts` 副本线程安全 | 低 | 局部副本，GDR 只读 |
| 表达式 `eval()` 安全——配置文件中注入恶意代码 | 低 | `eval()` 关闭 `__builtins__`，只暴露纯计算命名空间；本地桌面应用，配置为用户自己编写 |
| 表达式求值性能——每次 GDR 计算都 eval | 中 | `compile()` 一次后缓存 `_compiled`，后续调 callable 零开销 |
| ExpressionWeight 序列化——字符串表达式的可移植性 | 低 | 表达式只引用 `WeightEvalContext` 字段名，不绑定外部变量；序列化为纯字符串 |
| 配置面板 UX——静态/表达式两种模式 | 中 | 数值输入框（静态）+ 表达式输入框（`$...$` 语法高亮） |
| 向后兼容——旧 `[[weights]]` 节无法自动迁移 | 高 | 检测旧格式 → 自动迁移对话框 |
| 测试 break | 中 | 先更新 fixture 工厂函数，再逐测试适配 |

## 12. 判定

**可行。** 核心设计极其简单——仅两层：

1. **`float`** — 写一个数，所有实例共享。覆盖 90%+ 用例。同名卡不同权重 = 多行不同 float
2. **`ExpressionWeight`** — `$python_expr$`，访问 `WeightEvalContext` 全部字段（`instance_index`、`acquired`、`draw_number`、`simulation_day` 等），不做限制。实例索引、跨卡依赖、按日期、按抽数……全部由表达式覆盖
3. **方案搜索边界** — `validate_search_weight()`：float 通过，表达式拒绝。规则单一，无例外

`InstanceWeight` 被刻意排除——`instance_index` 已在上下文中，表达式 `$2.0/(instance_index+1)$` 比 `{0:2.0,1:1.0,2:0.67}` 更灵活且不引入新类型。

建议先做 Phase A+B 原型：定义 `ExpressionWeight` → `TargetInstance` → 4 行配置（含表达式）→ 验证 `_resolve_weight` 管道贯通。
