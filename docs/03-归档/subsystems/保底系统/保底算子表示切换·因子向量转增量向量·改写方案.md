## 0. 判据

### 0.1 成本账（决定性的）

2026-10-08 实测：

| 项 | 状态 |
|---|---|
| `core/pity_modifier.py` / `pity_primitives.py` / `pity_tracker.py` | **均不存在** |
| 代码内 `def factor` / `_apply_factor` | **零命中** |
| `core/pity.py` | 仍是旧的 `_redistribute_scope`（6 处） |
| TOML 配置 | 不含表示信息（表示是实现细节） |

**S1 尚未开工，因子向量接口一行代码都没写。** 故切换的**实现成本、测试成本、
数据迁移成本均为零**，只有文档改写成本。反之若推迟到 S8 落地后再换，成本包含
已实现代码与已写验收装置的改写。

### 0.2 收益

1. **表达力严格更强**。常数因子等价于增量（`m` 为常数时 `δ = p(m−1)`，§2.4 已证），反之不成立。
   差的那部分正是「把质量搬到零概率结果上」。
2. **§3.9.5 的一批边界特判消失**（见 §3）。现在绕 `assign` 目标值为 0 写的「因子取无穷」
   「按口径 3 直接写入绝对值」，在增量形式下是 `δ = −p_c`，没有特殊情形。
3. **少一层转写**。§2.1 的 `δ = t(u_A − u_Q)` 与 §4.1 的丁案公式都是增量形式，
   换过去后推演公式与实现同形，不再需要「由绝对量反推因子」的中介。

### 0.3 代价

1. **J4 降级**：非负性约束从类型级（`m ≥ 0`，与 `p` 无关）变为值依赖（`p + δ ≥ 0`）。
   对转移族退化为单个标量 `t ≤ p(Q)`，§3.9.4 已写该前置条件。
2. **§3.1.5.5 的可交换性判据重写**：现写「逐元素比较两种顺序下的因子乘积」，
   改为比较增量。概念不变，文字要重来。

### 0.4 明确不解决的问题

切换**不解决** `p(A) = 0`。穷举（`.recycle_bin/probe_pA0_reach.py`）显示该退化只在
「夺 UP / 保 UP」对撞的配置下可达，真实机制不需要它。故切换后**仍须**在 §3.4.1 与
§3.1.5.6 写明「目标组无概率且无货可取时不转移」。

## 1. 接口对照

### 1.1 Modifier 基类

| | 现状（因子） | 切换后（增量） |
|---|---|---|
| 方法名 | `factor(view, dist, ctx)` | `delta(view, dist, ctx)` |
| 返回值 | `Optional[Dict[str, float]]`，值为因子 `m` | `Optional[Dict[str, float]]`，值为增量 `δ` |
| 缺省 | 未列出的卡 `m = 1` | 未列出的卡 `δ = 0` |
| 恒等元 | `None` | `None`（不变） |
| 签名 | 三参数定稿（§3.1.2） | **三参数不变**（只换方法名与值的语义） |
| `rebind` / `state_keys` | 见 §3.9.2 | **逐字不变** |

### 1.2 框架归一化

```
现状：   p′_c = m_c · p_c / Σ(m ⊙ p)
切换后： p′_c = (p_c + δ_c) / Σ(p + δ)
```

```python
def _apply_delta(dist, d):
    out = {c: dist[c] + d.get(c, 0.0) for c in dist}
    total = sum(out.values())
    return dist if total <= 0 else {c: v / total for c, v in out.items()}
```

骨架调用点由 `mod.factor(...)` 改为 `mod.delta(...)`，其余（`self._view_for(mod)` 的遍历纪律、
`None` 短路）**逐字不变**。

### 1.3 助手函数

| | 现状 | 切换后 |
|---|---|---|
| 名 | `transfer_factors` | `transfer_delta` |
| 签名 | `(dist, A, Q, amount)` | `(dist, A, Q, amount, shape='current')` |
| 返回 | 因子向量 | 增量向量 |
| A 内 | 每卡 `× (p(A)+amount)/p(A)`（常数因子，保持当前比例） | `+ amount · u_A(c)`，`u_A` 由 `shape` 定 |
| Q 内 | 每卡 `× (p(Q)−amount)/p(Q)` | `− amount · p_c / p(Q)`（**恒为当前形状**） |
| 配平 | `⟨m,p⟩ ≡ 1` | `Σδ = 0` |

`shape` 取值 `'current'`（`u_A = p_c/p(A)`）或 `'declared'`（`u_A = w_c/w(A)`）。
按三案推演 §8.3 / §8.4 的实测，**当前 7 个形态全部取 `'current'`**。

**`'declared'` 只在增量形式下可用**：因子形式下 A 内有零概率卡会让因子取无穷，
这是切换收益 1 的由来；但按 §0.4，它当前没有用户。

## 2. 七个机制形态

**在 `shape = 'current'` 下，两版是同一个算子**（§2.4 已证：`δ = p(m−1)` 与常数因子等价），
故 7 个形态的行为**逐点不变**。切换只改记账方式，不改结果。

示例（`RotatingModifier`，A = featured，Q = scope − featured，`amount = p(Q)`）：

```python
# 现状
return transfer_factors(dist, A, Q, sum(dist[c] for c in Q))

# 切换后
return transfer_delta(dist, A, Q, sum(dist[c] for c in Q))     # shape 默认 current
```

## 3. §3.9.5 边界条目的逐条处置

| # | 情形 | 现状处置 | 切换后 | 变化 |
|---|---|---|---|---|
| 1 | `T == 0`（目标组当前概率为 0） | `share` 跳过目标因子、源侧仍写；`assign` 返 `None` | `current` 下 `u_A` 未定义 → **统一返 `None`**；`declared` 下按声明分配 | **简化**：两分支合一 |
| 2 | `P == 0`（U 内全零） | 两者返 `None` | `p(Q) = 0` → 无货可取 → 返 `None` | 不变 |
| 3 | `P − T == 0`（目标占满 U） | 只给目标加因子，源侧写 0 因子 | `δ_A = +amount·u_A`、`δ_Q = −amount·p_c/p(Q)` 自然涵盖 | 写法简化 |
| 4 | 目标集为空 | 返 `None`（三处守卫） | 不变 | 不变 |
| 5 | scope 键缺失 | `.get(scope, ())`，空集 → `None` | 不变 | 不变 |
| 6 | `⟨m,p⟩ ≠ 1`（U 外更高稀有度被缩放） | `_apply_factor` 的归一化不是恒等，会缩放 U 外的卡（实测 0.009 → 0.008919） | **消失**：转移族恒有 `Σδ = 0`，故 `Σ(p+δ) = 1`，归一化退化为恒等 | **消除** |
| 7 | `T ⊄ U` | 构造期 `ConfigError` | 不变 | 不变 |
| 8 | 归一化后总量 ≤ 0 | 返原分布 | `_apply_delta` 同 | 不变 |

**条目 6 的连带收益**：M1（槽位级）与 M2（S8 卡级）之间关于 `Σp` 的口径分歧
（ISSUE-011 / ISSUE-903：M1 期望 `Σp = 1 + Σp(被 F 豁免的更高稀有度槽位)`，
S8 期望 `Σp = 1`，两个里程碑的期望值相反）**随之一并消失**，因为增量形式下
`Σ(p+δ) ≡ 1` 对转移族恒成立，两个里程碑取同一式。

## 6. 风险与未决

1. **M1 不受影响**：M1（S1–S7）各 Modifier 实现 `apply` 并返回**分布**（§3.9.2 的两期分工），
   与表示无关。切换只影响 S8 及其后。
2. **与旧类的等价性（M1 口径）不受影响**：同上。
3. **命名撞车（需裁决）**：`delta` 与 `PityDef.deltas`（软保底的 RLE 段表）同名易混。
   备选名：`adjust` / `increment` / `shift`。
4. **`shape` 参数是否入签名（需裁决）**：7 个形态当前全取 `'current'`。
   写入则将来改动小，不写则签名更干净。
5. **未被本次切换触及**：§3.14.5 的悬空引用（两处指向不存在的小节，因 2026-10-06 的
   条件外置改判删节后未更新引用）与「方案 C 是否已作废」的判定，是独立问题。

## 8. 裁决结果（2026-10-08，用户裁决）

| 项 | 裁决 |
|---|---|
| 是否切换 | **换**（因子向量 → 增量向量） |
| 助手函数命名 | **`transfer_linear`**（原 `transfer_factors`） |
| `shape` 是否入签名 | **入签名**：`transfer_linear(dist, A, Q, amount, shape='current')` |

**命名的依据**：`transfer_linear` 返回的 `δ = t(u_A − u_Q)` 对 `t` 是**线性**的，故 `linear`
描述的是该函数自身的数学性质；同时它与被替换的 `transfer_factors`（乘性）形成对照。
一处已知的措辞瑕疵：框架施加的 `p ↦ p + δ` 本身是**仿射**（线性加平移）而非严格线性，
但该步由框架做、不在本函数内，故不影响命名。

**执行按 §7 的顺序推进**：接口与边界 → §3.1.5 全节 → 验收层与任务层 → 独立审查。
