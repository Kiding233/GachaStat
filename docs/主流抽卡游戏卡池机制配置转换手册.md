## 〇、约定

### 描述约定

| 术语 | 含义 |
|------|------|
| **UP** | 概率提升（Rate Up），出对应稀有度时有更高概率获得特定卡牌 |
| **硬保底 (hard pity)** | 达到指定抽数 100% 出对应稀有度 |
| **软保底 (soft pity)** | 达到指定抽数区间后概率逐抽爬升 |
| **天井/井 (spark)** | 累计 N 抽后可兑换指定卡牌 |
| **大保底 (guarantee)** | 上一次出对应稀有度但非 UP 后，下一次必定 UP |
| **定轨 (epitomized/targeted)** | 在 UP 卡中选定一张作为目标，歪后累计进度至必出 |
| **命定值 (fate point)** | 定轨系统中累积的进度计数 |
| **50/50 / 75/25** | 出对应稀有度时 UP 的概率 |
| **十连保底** | 每 10 抽必出 ≥4★（或等价） |

### 配置映射约定

软件中每条 `[[pity]]` 对应一种保底行为，`[[pool]]` 对应一个卡池实例。兑换池用 `is_exchange = true` 标识。附属池 + 特殊资源建模旁路机制。

**兑换池刷新原则：** 商品随周期变化的兑换池（如每月刷新、每期限兑 N 次）——**每个周期为一个独立池实例**，而非单个池子 + `max_exchanges` 配额。原因：不同周期的商品可能不同，独立实例避免污染。周期内的「限 N 次」由池内 rewards 的总可兑换量自然表达。

### 限定行为与池子组成

不同游戏的「卡池结束后卡片去向」差异显著——这决定后续池子的 offrate 概率空间。**不在所有游戏上套统一分类。** 每个游戏据实描述。

统一建模方式：池子显式声明其 `rewards`（所有可出卡）+ 卡片元数据声明 `available_in`（可出现在哪些池子）。不推导。

```toml
[[card]]
id = "limited_ssr_a"
rarity = "ssr"
available_in = ["banner_2026_01", "standard_roster"]   # 显式声明
# 或更简单的：直接用池子的 rewards 列表显式枚举。哪个池子有这张卡，就写进去。
```

#### 溢出 / 满突破后分解

当一张卡达到最大突破次数后，再次获得该卡时产出与未满时**不同**——通常更多商店货币。通用于大量游戏：

```
Reward.bonus 根据 acquired_count vs max_copies 分档:
  未满 → bonus_regular（如 10 星辉）
  已满 → bonus_overflow（如 25 星辉）
```

不建新基建——`Reward` 已有 `bonus` 字段，加按 `acquired_count` 的条件分档即可。

### 1.2 资源体系

#### 限定行为

- **5★ 限定**：仅在 debut 池或复刻池中出现。**不进常驻池。不作为其他限定池的 offrate（歪）。** 歪出的 5★ 永远是标准常驻 5★（迪卢克/琴/莫娜等）。
- **5★ 常驻**：始终在常驻池中，且是所有限定角色池的 offrate 来源。
- **4★ 限定**：debut 池结束后**立刻**进入常驻 offrate 集——后续所有池子（常驻+限定）均可歪出。
- **武器池**：5★ 限定武器同角色规则——不进常驻、不可歪。offrate 来源为该池的另一把 UP 武器 + 常驻武器。**定轨仅作用于当前池的 UP 武器对。**
- **联动角色/武器**（如埃洛伊）：真限定——不进常驻、不可歪、不复刻。

### 1.5 副产物管线

抽卡 → 获得 Reward → `bonus` 字段产出 `starglitter` / `stardust`：

```toml
[[card]]
id = "standard_5_star_duplicate"
# ... 抽到此卡时触发 bonus → 产出星辉
```

副产物资源注入 `starglitter_shop` / `stardust_shop` 兑换池。兑换池产出纠缠之缘→流入限时池。形成闭环。

## 二、崩坏：星穹铁道 (Honkai: Star Rail)

> 版本：3.x | 开发商：HoYoverse | 资料可信度：高

### 2.1 副产物管线

同原神结构——星芒=星辉、余烬=星尘。兑换比例完全一致：5 星芒=1 专票，75 余烬=1 专票（月限 5）。月卡：30 元=300 古老梦华+90 星琼/日×30=3000 星琼/月。≈18.75 抽/月。

### 2.2 卡池清单
| 角色活动跃迁-2 | 限时UP(同期) | 角色池保底组 | 星轨通票 |
| 光锥活动跃迁 | 限时UP | 光锥池保底组 | 星轨通票 |
| 常驻跃迁 | 常驻 | 常驻保底组 | 星轨通票(普票) |

| 重复 SR（6星后） | 1 | 1 |

核心反馈：**限定货币不继承 → 常驻货币继承。** 不在限定池抽满 120 铸金 = 浪费（转常驻后无法换限定武器）。

### 5.3 核心特点

- **双轨道保底**：抽数保底（跨池继承）+ 兑换货币保底（不继承，卡池结束转常驻货币）
- **提前出金不重置 80 抽保底** 🔵：这是幻塔最独特的机制——即使第 79 抽出了 SSR，第 80 抽仍然必出 SSR（保底计数器独立于出金事件）。等价于每 80 抽一个额外的「白送」保底金。**所有其他游戏出金后均重置计数器，唯幻塔不重置。**
- **歪后铸金补偿**：保底歪了常驻 SSR 时额外获得 10 回火铸金。实际约 **100–110 抽**即可凑够 120 铸金，而非字面 120 抽。
- **隐藏连歪机制**：连歪 2 次 → 下次必中；连中 2 次 → 下次必歪。跨池继承
- **多 UP 池共享保底计数**：可「切池垫刀」——在 A 池垫 79 抽 → 切 B 池出保底金

### 7.2 核心特点

```toml

[[pity]]
type = "hard"
name = "bh3_expansion_hard"
scope = "ssr"
threshold = 100
pools = ["bh3_expansion_all"]    # 所有扩充补给共享此组 → 继承

# 精准补给——50抽UP保护不继承
[[pity]]
type = "hard"
name = "bh3_precision_a_up"
scope = "ssr"
target_featured = true
threshold = 50
pools = ["bh3_precision_a"]      # 仅绑定 A 池 → 不继承到 B 池
```

| **计数器1**（小保底） | 80 抽 | 80 抽必出 6★，50% 为当期 UP | ✅ 继承 | 无限 |
| **计数器2**（大保底） | 120 抽 | 同池内 120 抽必出当期 UP | ❌ **不继承** | 每池 1 次 |
| **计数器3**（信物） | 240 抽 | 获得首个 UP 后，240 抽必出信物 | ❌ **不继承** | 每池 1 次 |

**6★基础概率：0.8%。** 软保底从第 65 抽起每抽 +5%，第 80 抽 100%。

**关键风险结构：** 80 抽可跨池垫刀；一旦进入 80-120 区间，必须在池结束前完成 120 抽，否则大保底清零。不存在「垫 40 抽观望」的中间态。

### 16.2 特殊福利机制

| 福利 | 触发 | 效果 |
|------|------|------|
| **30 抽加急招募** | 限定池累计 30 抽 | 送 1 次十连——**不计入任何保底计数器**。该十连自带保底：必出 ≥5★ |
| **60 抽寻访档案** | 限定池累计 60 抽 | 获得 10 张**下期限定池专用券**——计入下期保底 |
| **120 抽（1.2 辉光庆典）** | 庆典限定池 120 抽 | 送**六星自选券**（四选一）——不同于常规池的 120 大保底 |

> ⚠️ 里程碑奖励**随版本变化**——1.2 辉光庆典的 30/60/120 奖励与常规限定池不同。配置时需按卡池版本区分。

**60 抽档案的建模含义：** 它创造了非线性激励——第 59→60 抽的边际价值突然跃升。玩家倾向于「垫到 60 抽」即使当前池不打算继续追。对方案搜索而言，这是一个**跨期投资决策节点**。

### 16.3 副产物管线

终末地的商店资源分两条线——**每期限定** 和 **常驻通用**：

| 产出来源 | 信物(每期) | 信物(常驻) | 武器配额 |
|------|:---:|:---:|:---:|
| 4★ 重复（满潜后） | 可换 5 抽/期 | — | 20 |
| 5★ 重复（满潜后） | — | 可换不限量限定券 | 200 |
| 6★ 重复（满潜后） | — | 可换不限量限定券 | 2000 |

| 兑换 | 消耗 | 限制 |
|------|------|------|
| 限定单抽券 ×1 | 4★信物(每期) | 每期限 5 抽 |
| 限定单抽券 ×1 | 5★/6★信物(常驻) | 无限制 |
| 武器十连 ×1 | 1980 武器配额 | 无限制 |

> **每期商店建模原则：** 「每期限 N 次」不应建模为单个兑换池 + `max_exchanges` 配额——因为每期刷新的商品**可能不同**。应建模为**每期独立的兑换池实例**（`endfield_period_shop_001` / `_002` / …）。每池各自配置 rewards，自然的每池可兑换总量即等于该期限额。这样不同期的不同商品（如 1.0 换券 vs 1.2 换券+自选箱）不会互相污染。

**武器配额：** 抽角色池直接产出武器池货币。~5 次角色池十连 → 1 次武器池十连。这是已知最强的跨池绑定——角色池和武器池无法独立规划。

**每期免费抽构成：** 签到 5 抽 + 商店 5 抽(4★信物) + 30 抽送 10 连 + 60 抽送下期 10 连。每池实际投入 40 抽即可拿满免费额度。

### 16.4 武器池

> ⚠️ **数据溯源：** 旧调研报告（2026-05，二测数据）称小保底为 30 抽，正式版已改为 40 抽。以下均为独立核实后的公测数据。

| 项目 | 数值 |
|------|:---:|
| 6★基础概率 | 4% |
| UP 率（6★内） | **25%**（75% 歪常驻） |

| 大保底 | **80 抽**（8 次十连）必出当期 UP——仅 1 次，不继承 |

#### 限定行为

终末地的限定行为与米家游戏**根本不同**——限定 6★ 不进常驻，但作为 offrate 出现在 **debut 池 + 后续 2 期** 限定池中。之后移除，等复刻重开。常驻 6★ 始终在常驻池和所有限定池的 offrate 中。这创造了「缓冲窗口」——前 2 期错过仍有概率歪出，2 期后绝版。

配置建模：每张限定卡附带 `offrate_window = 2`。池子构造时自动纳入仍处于窗口期内的往期限定。

## 十七、火影忍者手游 (Naruto Mobile)

### 17.1 碎片即资源

火影的「高招」不是传统抽整卡——每抽产出的是**忍者碎片**。S 忍需 100 片，A 忍需 40 片。这恰好是兑换池模型：

```

  → 产出 naruto_fragment_sasuke × 1-5（概率分布）
  → 100 片 → exchange pool → 兑换 S 忍
```

**不超出已有基建。** 碎片是 `resource`，兑换是 `is_exchange` 池。

### 17.2 保底机制

> ⚠️ **建模警告（见 G20）：** 以下用 `hard` 保底建模碎片产出是**近似**——`hard` 触发时**替换**正常抽卡结果（吞掉本该出的卡/装备）。实际游戏中，碎片保底只保证产出**不低于**某个最小值，不替换同抽中的其他产出。精确建模需 `pity.mode = "bonus"`（追加语义）。

| 保底 | 规则 | 建模（当前近似） |
|------|------|------|
| 十连保底 | 每次十连必出 ≥1 片 S/A 碎片 | `hard(scope="sr", threshold=10)` ⚠️ 替换语义——会吞正常产出 |
| S 碎小保底 | 每 10 抽必出 1 片 S 碎 | 同上 |
| S 碎大保底 | 50 抽一组 5 片 S 碎 | `hard(scope="ssr_fragment", threshold=50)` ⚠️ 替换语义 |
| A 碎保底 | 40-50 抽一组 4 片 A 碎 | 同上 |

### 17.3 首付机制

新高招忍者上线首周——一次性的碎片奖励事件：

| 忍者 | 首付抽数 | V0 返还 | V15 返还 |
|------|:---:|:---:|:---:|
| 高招 S | 100 抽 | 25 片 | 38 片 |
| 高招 A | 50 抽 | 10 片 | 15 片 |

建模：`on_draw_n(100)` 事件 → 注入 `naruto_fragment_X += 25`（按 VIP 参数）。

### 18.2 核心特点

**保底池 vs 命运池（赌狗池）——同一个 UP 角色的两条赛道：**

| | 保底池（蓝底） | 命运池（红底） |
|---|:---:|:---:|

| 期望抽数 | ~52 | ~52 |
| UP 率 | 100% | 100% |

同一角色两个池子——平民选保底池(确定性高)、氪佬选命运池(冲高星级)。

### 18.3 保底继承：「同名继承制」

战双的继承规则比崩坏 3 更简单——**同池子类型间完全继承，不同类型完全不通：**

| 池类型 | 继承至 |
|--------|--------|
| 主题活动保底 | 下一个主题活动保底 |
| 命运主题活动 | 下一个命运主题活动 |
| 降临狙击 | 下一个降临狙击 |
| 武器池 | 下一个武器池 |
| 联动池 | **完全独立——不继承任何池也不被继承** |

### 18.4 校准系统（定轨等价物）

降临狙击池（轮换复刻）和武器池——歪后触发校准：

```
选定 A → 出 A（70%）  → 校准归零
        → 出 B 或 C   → 校准激活 = 下次必 A
```

这等价于 `rotating(loss_increment=50)` ——但起始胜率是 70% 而非 50%。武器池起始胜率 80%。

### 20.2 棋盘对建模的根本挑战

> ⚠️ **架构级需求：** 棋盘不是「在现有概率模型上调参」。它需要**一个新的底层抽象**。

现有 PityEngine 管道假设：`before_draw → 调整概率分布 → pool.draw() → after_draw → 更新计数器`。概率由 PityBehavior 逐抽调整，从同一个分布中抽样。

棋盘的工作方式不同：
- **概率不是分布参数，而是棋盘布局。** 每个格子有独立的奖励——欧皇区格子的 S 概率远高于非酋区
- **双态不是调参，是换棋盘。** 基准棋盘 → 第 70 抽切换至变格棋盘——物理上换了另一套格子分布
- **掷骰引入了额外随机层。** 两次 90 抽保底但棋盘不同的玩家，路径完全不同——这创造了逐格状态的 Martingale 而非 i.i.d. 抽样

**需要的底层支持：** 一个 `BoardState` 抽象——表示「当前棋盘布局 + 当前位置 + 切换条件」，替代或嵌入现有的「概率分布→抽样」管道。这不是 P55/P56 的 scope，属于更底层的基础设施。

### 17.5 配置转换

#### 限定角色池——棋盘双态

棋盘模式的核心难点：**概率不是连续爬升，而是一个离散的状态切换（70 抽 → 1% → 19.5%）。** 这不是 `soft_additive` 的线性累加，而是一个**双态 Markov 切换**——状态取决于「距上次 SSR 的抽数」。

需要用一个特殊的 soft 变体来表示这个离散跳变：

```toml
# 方法一：用 soft_interval 近似——start=70, end=90, func=step
[[pity]]
type = "soft_interval"
name = "yihuan_chess_soft"
scope = "ssr"
start = 70
end = 90
func = "step"                  # ← 离散跳变：70 抽前 1%，70 抽后直接跳至 19.5%
pools = ["yihuan_limited_char"]

[[pity]]
type = "hard"
name = "yihuan_chess_hard"
scope = "ssr"
threshold = 90
pools = ["yihuan_limited_char"]

# 注：不歪——不需要 rotating。出金即当期UP。
```

**方法一的问题：** `soft_interval` 的 `func=step` 目前尚未实现（P55 仅定义 `linear/exp/step`，`step` 为预留值）。且双态切换的精确逻辑（70 抽整点跳变 vs 渐进？69→70 抽是否立即切换？）需确认。

**方法二（更精确）：** 用两个 `hard` 保底模拟双态——

```toml
# 基准态：1% 概率（SSR 总出率由池子 base_prob 控制）
# 变格态：70 抽起，SSR 概率跳至 19.5%

[[pity]]
type = "soft_additive"
name = "yihuan_variant"
scope = "ssr"
start = 70
increment = 18.5            # 一次跳变——从 1% → 19.5%
pools = ["yihuan_limited_char"]
# 但 soft_additive 是逐抽累加 18.5，不是一次性跳变
```

都不完美。**精确建模需要新增 `soft_step` type 或扩展 `soft_interval` 的 `func=step` 实现。**

### 17.6 功能缺口

> ⚠️ **底层结构需求：** 异环的棋盘机制不是「在现有概率模型上调参」可以覆盖的。它需要**一个新的底层抽象**——一个「双态 Markov 切换」的概率模型，而不是传统的「从分布中抽样 + 保底修正」。现有 PityEngine 管道（`before_draw→draw→after_draw`）假设概率由 PityBehavior 逐抽调整——但棋盘的双态切换需要知悉「整个计数周期内的 SSR 出货事件」，并且概率跳变是**离散的一次性状态切换**而非逐抽累加。

| 缺口 | 说明 | 优先级 |
|------|------|--------|
| **棋盘双态 Markov 切换** | 需要 `SoftStepBehavior` 或引擎层支持「达到计数器阈值→离散切换至另一概率分布」。现有 `soft_interval(func=step)` 仅为预留值 | 🔴 **架构** |
| 保底双黄（发售后赠送） → 见 **G20** | 90 抽后额外赠送——需 `pity.mode = "bonus"` 追加语义，在正常产出之上注入额外卡 | 🔴 高 |
| 武器池仅十连 | `pool.batch_size_min=10`——需池子支持最小十连约束 | 🟡 中 |
| 变格概率跳变的精确切换点 | 第 70 抽结束时切换 vs 第 71 抽开始时切换？ | 🟡 中 |
