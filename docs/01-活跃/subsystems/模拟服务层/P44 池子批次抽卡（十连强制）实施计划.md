# P44 池子批次抽卡（十连强制）实施计划

> 日期：2026-06-13 | 状态：设计中
> 依赖：无（独立可执行）

**Goal:** 支持池子级配置 `batch_size`（默认 1），当 `batch_size > 1` 时策略检查 N 发可负担性、服务层原子预检查 + 逐发抽取（保底逐发更新、多资源优先级自动切换）。

**Architecture:** 池子驱动——`batch_size` 是 `Pool` 的静态属性。策略返回普通 `DrawAction`，通过 `ctx.state.can_afford_batch()` 检查 N 发可负担性。服务层预检查 → `for i in range(batch_size)` 逐发 `spend()` + `draw()`。不改 `DrawAction` 接口、不改收集器/统计/保底引擎接口。

**Tech Stack:** Python 3.10+, pytest, 现有项目基础设施

---

## 设计摘要

### 数据流

```
schedule.txt 第 9 列 (可选, batch_size, 默认 1)
        │
        ▼
PoolConfig.batch_size  ──→  PoolEntry.batch_size  ──→  Pool.batch_size
                                                             │
        ┌────────────────────────────────────────────────────┤
        ▼                                                    ▼
StrategyContext                                    GachaService.run_simulation()
(pool.batch_size 可读)                             (读取 pool.batch_size)
        │                                                    │
        ▼                                                    ▼
策略调用                                          if not can_afford_batch(cost, batch_size):
  can_afford_batch(cost, batch_size)                   continue   # 静默跳过
        │                                                    │
        ├─ True  → 返回 DrawAction(pool_id)                  ├─ for i in range(batch_size):
        └─ False → 跳过该池子                                │      spent = state.spend(cost)  # 逐发扣费
                                                             │      pity.before_draw()
                                                             │      reward = pool.draw()
                                                             │      pity.after_draw()
                                                             │      collector.on_draw(spent=...)
                                                             └─ 下一轮迭代
```

### 向后兼容性

| 场景 | batch_size | can_afford_batch | 服务层 | 策略 |
|------|-----------|-----------------|--------|------|
| 现有配置无第 9 列 | 1 (默认) | 退化到 `can_afford` | `range(1)` → 单发 | 无感知 |
| 新建十连池 | 10 | 模拟 10 次独立费用选择 | `range(10)` → 逐发 | 检查 10 发可负担性 |
| 未来 N 连池 | N | 模拟 N 次 | `range(N)` → 逐发 | 检查 N 发可负担性 |

- 不改任何现有 `.txt` 配置文件
- 不改 `DrawAction` 接口
- 不改收集器 / 统计 / 保底引擎接口

```python
# core/state.py GachaState 类中新增

def _choose_option_from(self, cost, resources: dict) -> Optional[CostOption]:
    """从给定资源快照中选择最优 cost option（不修改真实资源）。"""
    if isinstance(cost, dict):
        if all(resources.get(r, 0) >= a for r, a in cost.items()):
            return cost
        return None
    if isinstance(cost, list):
        for option in cost:
            if all(resources.get(r, 0) >= a for r, a in option.items()):
                return option
        return None
    return None

def can_afford_batch(self, cost, batch_size: int = 1) -> bool:
    """
    模拟 batch_size 次独立抽卡的费用选择。

    每次独立选择最优 cost option，资源快照逐次递减。
    支持 free_draw:1 > draw_resource:160 等 OR 优先级资源自动切换。

    batch_size=1 退化到 can_afford()。
    """
    if batch_size <= 1:
        return self.can_afford(cost)
    remaining = dict(self.resources)
    for _ in range(batch_size):
        option = self._choose_option_from(cost, remaining)
        if option is None:
            return False
        for res, amt in option.items():
            remaining[res] -= amt
    return True
```

```python
class TestGachaServiceBatchDraw:
    def test_batch_draw_executes_n_draws(self):
        """batch_size=10 的池子一次 DrawAction 执行 10 发。"""
        from gacha_simulator.core.pool import Pool, Reward
        from gacha_simulator.core.state import GachaState
        from gacha_simulator.core.action import DrawAction
        from gacha_simulator.core.strategy import Strategy, StrategyContext
        from gacha_simulator.core.stop_condition import StopCondition
        from gacha_simulator.service.gacha_service import GachaService

        # 构造 batch_size=3 的简单池子
        pool = Pool(
            id='test_batch', name='batch池', cost=[{'coin': 10}],
            rewards=[(Reward(id='card_a', name='A'), 1.0)],
            batch_size=3,
        )
        state = GachaState(resources={'coin': 100})

        # 策略：固定返回该池子
        class FixedDraw(Strategy):
            def select_action(self, ctx):
                return DrawAction(pool_id='test_batch')

        # 停止条件：抽 1 次动作后就停（但 1 次动作 = 3 发）
        stop_hit = []
        class OneActionStop(StopCondition):
            def check(self, state, pools, stats):
                if stats.total_draws >= 3:
                    stop_hit.append(True)
                    return True
                return False

        service = GachaService(
            pools={'test_batch': pool},
            pools_list=[pool],
            strategy=FixedDraw(),
            stop_condition=OneActionStop(),
            pity_engine=None,
            resource_gain=None,
            schedule_manager=None,
            target_cards=None,
            card_defs=[],
            ssr_ids=set(),
            session_id='test',
        )
        result = service.run_simulation(state, max_iterations=100)
        # 1 次 DrawAction → 3 发
        assert result.total_draws == 3
        # 资源消耗 3 × 10 = 30
        assert result.total_consumed.get('coin', 0) == 30

            batch_size=10,
```

```python
        spent = state.spend(pool.cost)
```

### 已知行为（设计决策，非缺陷）

| 场景 | 行为 | 理由 |
|------|------|------|
| 批次中途获得目标卡 | 剩余发照常执行 | 批次原子性——与「付不起就不抽」对称，付得起就抽完 |
| 批次中途池子过期 | 剩余发照常执行 | 与单抽行为一致——池子可用性仅在迭代开始时检查 |
| 批次中途资源耗尽 | 不应发生——`can_afford_batch` 已预检查 | 若因奖励扣费导致不够后续发也是预期内（极少见） |
| 策略缓存了保底概率 | 批次第 2 发不使用缓存 | `before_draw()` 逐发调用获取新鲜概率 |
