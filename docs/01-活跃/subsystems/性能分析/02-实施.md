## 2. 适配器契约

```python
class Adapter(Protocol):
    name: str                 # 路径标识，写入每条 RunResult
    is_user_path: bool        # inline 为 False，其余为 True
    def available(self) -> bool: ...        # 本环境能否跑（无 PyQt6 则不报错，跳过）
    def run(self, plan: Plan) -> RunResult: ...
```

**职责**（详见 `01-理论.md` §3 驱动复用约束）：

1. 建起这条路径的运行环境
2. 把 `Plan` 翻译成这条路径的输入
3. 在**正确的进程与线程边界**上挂计时器与剖析器
4. 以这条路径自己的方式等待结束
5. 归一成同一个 `RunResult`

**禁止**：新写驱动。只能修复或包装已有入口。

**面板分发段：已于 2026-09-17 结案，结论为「可独立测量」**（2026-09-22 订正——此处原写「已知未验证项……初版覆盖面定到 `SimulationThread` 结束」，该表述已被 `P83 §3.10` 的结案推翻）。根因是**探针自身用了 `QApplication([])` 传空 argv**，与执行环境无关；改用 `QApplication(sys.argv)` 后 `gui-qt` 路径**全程**可驱动，含面板构造与分发执行。适配器的切分点为**两条 `on_simulation_finished` 之间**，不照抄 `scripts/profile_gui.py` 的 B6 自建实例序列（见 `01-理论.md` §9.2 与 `P83 §3.10`）。

## 3. Plan（测量规格）

> ⚠ **本节以 `P83 §6.0` 的 `1b` 行为唯一真值源**（2026-09-22 同步，`1a-2`）。`1b` 交付 `Plan` + `PlanGrid` + `validate()` + 因子展开 + **`to_dict()` / `from_dict()`**（`plan.json` 的唯一读取器，AUDIT-BREAK-1）。下方为摘要，字段口径与拒绝规则以 `P83 §3.4` / §3.8 D8 / §3.9 T2 为准。

```python
@dataclass(frozen=True)
class Plan:
    # —— 模拟规格 ——
    config_path: str
    strategy_key: str
    strategy_params: dict
    n: int
    workers: int
    seed: int
    chunksize: int | None = None      # None = 交给 run_batch_parallel 自算
    # —— 三轴 ——
    subject: str = 'simulation'       # simulation | startup（P83 §3.3）
    path: str = 'cli'
    grain: str = 'stage'              # batch | stage | function（single 本期未实现，validate 拒绝）
    # —— 测量政策 ——
    repeats: int = 3                  # 取中位数；建基线时强制 >=3
    collector: bool = False           # 本次 plan 是否带流式收集器（如实申报，非运行期开关）
    py_spy: bool = False
    # —— 阶段 6 的四个触发字段（P83 §3.8 D1；写入 env 由 1e-2 承接）——
    profile_enabled: bool = False
    profile_dir: str = ''
    profile_skip: int = 2
    profile_count: int = 50
    note: str = ''

@dataclass(frozen=True)
class PlanGrid:
    base: Plan
    factors: dict[str, list]          # n / workers / chunksize / strategy_key / config / seed
    def expand(self) -> list[Plan]: ...   # 笛卡尔积，去重
```

**`collector` 的默认值是 `False` 而非 `True`（fail-safe）**：四条路径中 `cli` / `gui-qt` / `webui` 的实际申报值均为 `False`，只有 `inline` 为 `True`。若默认 `True`，适配器漏填时会静默落入规则 4 的 1600 上限而非规则 1 的 1000——**上限被放宽**，与「如实申报」的契约方向相反；默认 `False` 则漏填时落入更严的规则 1，最坏是多拒一条 `n > 1000` 的 plan（可被 T3 的申报值断言立刻暴露）。

**`validate()` 的拒绝规则**（构造期，各条数值见 `P83 §3.4`）：规则 1（`collector=False` 且 `n > 1000`）/ 规则 4（`collector=True` 时 `n ≤ 1600`）/ 规则 5（内存阈值，内存查询须可注入）/ §3.8 D8（`profile_count > 500`）/ §3.8 D2.1（`grain='function'` 且 `workers <= 1`）/ `grain='single'`（本期未实现）/ `subject='startup'` 落到本期无落点的路径或档位（`3e`）；`subject='startup'` 时规则 1 与规则 4 **不适用**（`n` / `workers` 被忽略），规则 5 与 D8 仍适用。

**`startup` 的语义落点（`3e`，2026-09-22 实施）：** 被忽略的字段在代码里是常量 `STARTUP_IGNORED_FIELDS = ('n', 'workers', 'chunksize', 'strategy_key', 'seed')`（**唯一真值源**，`validate()` 的分支、`memory_requirement_gb()` 与 `Plan.ignored_fields()` 全读它），有落点的路径是 `STARTUP_PATHS = ('gui-qt',)`。**「被忽略」不等于「可以声明」**：`subject` 在三轴模型里与 `path` / `grain` 正交，故 `startup × cli` 在字段层面可构造，而本期只有 `3f-1` 认领了 `startup × gui-qt`（`cli` / `webui` 的启动测量被 §3.11 明写为**两个独立增量**、不在本计划内）。放行该组合的实际后果不是「少测一段」，而是入口薄壳按 `plan.path` 派发到 `CliAdapter` 并**照常产出一条带 `subject='startup'` 的记录**——报告会把一次普通模拟说成启动测量。故按 `grain='single'` 的同一处置（§3.3）在 `validate()` 内拒绝：路径不在 `STARTUP_PATHS` 内、`grain='function'`（`function` 档的落点是围绕单次 `_run_single` 的开闭窗口，冷启动进程内无 worker 池亦无该调用点）、`profile_enabled=True`（§3.8 D1 的四字段注入通道落在 `run_batch_parallel` 的 worker 路径上，`main.py` 的冷子进程不经过它）三者均拒。

**`PlanGrid.expand()` 同受该语义约束（`3e`）：** `startup` 下扫被忽略的字段会在入口处拒绝——展开出的各格读数必然相同，但每格都要真起一次冷进程（真实窗口 + 约 8 秒），扫描看起来生效、实际只是把同一次测量重复 N 遍。

**规则 5 在 `startup` 下按 `gui-qt` 特例计（`3e`）：** 内存下限 = `max(2.0, 1 × 0.75) + 0.5 = 2.5 GB`，与 plan 里填的 `workers` 无关（那五项被忽略）。两条特例在代码里合并为一个谓词 `gui_like = subject == 'startup' or path == 'gui-qt'`。

## 4. RunResult（记录）

> ⚠ **本节字段表以 P83 `1c` 为唯一真值源**（2026-09-21 定死，AUDIT-BREAK-2 / AUDIT-BREAK-4）。
> 下表已按真值源逐项同步；后续若有分歧，**一律以 P83 `1c` 为准**。

```python
@dataclass
class RunResult:
    run_id: str
    timestamp: str
    path: str
    is_user_path: bool
    fingerprint: EnvFingerprint       # 见下方 EnvFingerprint
    plan: Plan                        # 完整规格，保证可复现
    repeats: int                      # 实跑次数；建基线强制 >= 3
    wall_median: float
    wall_samples: list[float]         # 各次原始值，用于判断方差
    repeats_downgraded: bool          # 预估墙钟超 30s 时降为 1，置 True
    stages: dict[str, float]
    single: SingleStats | None        # 预留：grain='single' 本期未实现（P83 §3.3），恒为 None
    functions: list[FuncStat] | None  # (name, ncalls, tottime, cumtime)
    resources: ResourceStats          # 序列化字节数、RSS 峰值
    return_compact: bool              # 可比性维度：False 时三元组首分量为 None，字节数跨路径不可比
    samples_meta: SamplesMeta | None  # py-spy: duration / samples / errors / profiles（profiles 由 4b 于 2026-09-22 补入）
    not_comparable: bool = False      # function 档为 True，被基线比值排除（P83 §3.8 D6）
    warnings: list[str]               # 含「本路径不可得」等标注

@dataclass
class EnvFingerprint:
    cpu: str
    cores: int
    os: str
    python: str
    code_version: str                 # 代码版本
    qt_qpa_platform: str              # 本次 QT_QPA_PLATFORM 取值（P83 §3.11，供基线比对照出平台口径）
```

**两条硬约束（P83 AUDIT-BREAK-2 / AUDIT-BREAK-4）：**

- **`repeats` 缺失是硬失败而非降级**——`1f` 的门禁读 `repeats` 判「建基线须 ≥ 3」，字段为 `None` 时与 `3` 比较即抛 `TypeError`。故 `1f` 的比值比对与登记门禁一律按「**字段缺失或 `None` → 按不可比处理并记 `warnings`，不得直接比较**」实现，由 T1 断言。
- **`return_compact` 与 `qt_qpa_platform` 是可比性维度而非普通读数**——报告在跨路径对比处据此标注可比范围，**不得把两个不同 `return_compact` 取值的字节数直接相比**。

## 8. 阶段 6 的接口约束（P83 §3.8 摘要）

阶段 6 是**全平台唯一改动模拟热路径默认行为**的地方（2026-09-22 订正：原写「唯一触碰被测量代码的地方」，按 `P83 §3.2`「约束 B 的范围修订」与 §8.2 收窄口径，另有**四处默认关闭的产品侧可选通道**与一行实验期临时改动，见 `P83 §四` / §8.2），三条约束不可回退：

1. **`SimulationEnv` 新增 4 字段**：`profile_enabled` / `profile_dir` / `profile_skip` / `profile_count`，全部带默认值以保持跨进程 pickle 兼容（照既有 `return_compact` / `n_heatmap_bins` 的模式）
2. **采样窗口在 `_wk_run_single` 内开闭**，不在 `_wk_init` 里做进程级 enable。依据是 `multiprocessing.pool.Pool.__exit__` 走 `self.terminate()`（本机 Python 3.12.5 源码核验），worker 被强杀、`atexit` 不执行
3. **剖面结果走文件**（`dump_stats` + 父进程 `pstats.Stats.add()` 合并），不动 `CompactResult`、不动 `_RESULT_VERSION`、不改 `_wk_run_single` 的三元组 arity（其 docstring 有 ⚠ 明确契约，父进程有 `len(result) == 3` 守卫）

失败一律软降级，绝不因剖析失败导致模拟失败。

## 10. gui-qt 覆盖率（P83 §3.10 摘要）

**覆盖完整 GUI 路径**，含面板构造与分发执行。根因已查明：此前探针失败是因为用 `QApplication([])` 传空 argv（WebEngine 初始化随之失败，进程以 `0xC0000409` 终止）；改用 `QApplication(sys.argv)` 后全部正常。

## 13. 默认路径的副作用登记（2026-09-22 实测）

本计划对产品**默认路径**的改动应当是零，唯一例外是 §8.2 标注的 `6b`（阶段 6，改动模拟热路径）。此处登记一处**非热路径但确有的**默认路径副作用，以及一处默认路径**行为放宽**。

### 13.1 `--strategy` 的 choices 动态化（`1e-3`）

**副作用：每次 CLI 启动多一次插件目录扫描与插件模块导入。** 原因：`choices` 由 `STRATEGY_REGISTRY` 动态生成，而插件键只在 `load_plugin_strategies()` 之后才存在，故该函数必须前置到 parser 构造之前——**它在 `parse_args()` 之前**，因此**每次 CLI 启动都会执行**，包括那些最终报错退出的调用。

**实测（2026-09-22，本机）：**

| 测项 | 中位数 |
|---|---|
| `load_plugin_strategies()` 同进程热态 | **0.7 ms**（插件目录下 1 个 `.py`） |
| 冷态「import 注册表」 | 220.6 ms |
| 冷态「import 注册表 + 插件扫描」 | 213.5 ms |
| 冷态差值 | **−7.2 ms（负值即噪声——净增量低于测量分辨率）** |
| CLI 端到端 `--help` | 294 ms |
| CLI 端到端 `--version` | 300 ms |

**结论：在当前插件数（1 个）下，该开销低于测量分辨率**——冷态差值落在噪声内，端到端两条路径无可辨差异。**但开销随插件数线性上升**（每多一个插件多一次 `exec_module` 与其未缓存的 import），故此处记下测法备用：插件数显著增加后应重测本表。

**行为放宽（属放宽而非收紧，须如实登记）：** `[strategy].key` 为插件键的配置，在 CLI 上**首次可解析**；`no_draw` 也首次进入 `--strategy` 的合法取值（它一直已注册，只是没进原来的字面量 `choices` 列表）。

### 13.2 禁用项的语义降级（`1e-3`）

「禁用」从「不作为合法取值被 argparse 接受」（`invalid choice`，退出码 2）降级为「**被接受后由 `load_toml` 之后的显式校验拒绝**」（同样退出码 2，但错误信息由本步给出，含被禁用的 key 与 `[plugins].disabled` 出处）。

降级原因：生成 `choices` 时**禁用集合尚不可知**——`[plugins].disabled` 不是 `load_toml` 施加的（`load_toml` 只构建 `store`，全函数体不调用 `_build_plugins`），且 parser 构造还在 `load_toml` 之前。两条路可选，本实现取**推荐方案（只读重读文件）**：cli 自行用 `tomllib` 重读 `args.config`，取 `data['plugins']['disabled']` 做只读比对，**不调用 `_build_plugins`**——后者会把 `STRATEGY_REGISTRY` 里对应条目的 `meta.disabled` 置 `True`（全局注册表副作用），而这条 CLI 进程紧接着就要跑模拟，污染注册表会改变 `create_strategy()` 的守卫行为与后续 `--strategy` 语义。该纪律有专门用例守护（`tests/benchmarks/test_cli_strategy_choices.py::TestReadIsReallyReadOnly`）。

备选方案（两阶段 parser：`parse_known_args` 取 `-c/--config` → `load_toml` → 构造带最终 `choices` 的 parser → `parse_args`）保留于此以备复核：它可保持前一种语义，但代价是 `main()` 的 parser 构造被拆成两段，且报错退化为 argparse 自身的 `invalid choice`、仍须自行补齐出处信息。
