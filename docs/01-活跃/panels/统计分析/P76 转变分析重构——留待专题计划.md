# P76 转变分析重构——留待专题计划

> 日期：2026-08-07 | 状态：占位（设计待启动）| 优先级：中
> 触发：P72 计划审查（P38 工作流）D1 裁决——转变分析暂缓，留待本专题完善后加回
> 背景：P72 审查暴露转变分析多项缺陷（per_pool_target 两路径无效、N3 键错配、吸收态限制、演进路径未定），P72 本次只修键错配 bug，转变分析整体留待本专题

---

## 一、问题（P72 审查暴露，2026-08-07）

转变分析（banner 序列 + 累计窗口成败 + 转变矩阵）存在以下缺陷，均不在 P72 本次修复范围：

1. **per_pool_target 判据两路径下均无有效判定**（P72 ISSUE-101，详见 P72 §5.1 附注）：
   - 主路径（streaming 预计算 `transition_flags`）：完全不查询 success_criteria 下拉，per_pool_target 是静默 no-op
   - 回退路径（旧数据集加载）：走 single_pool 分支，N3 键错配恒判失败
   - 两路径均未产生有效判定，用户切换判据只是假变化（combo 变动触发重算但输出不变）
2. **N3 键错配**（P72 §2.3/§5）：banner 键 `pool_ids_ordered` 查全限定表恒空，影响转变分析 single_pool scope 与每池成功率「第k池单池」scope
3. **累计窗口吸收态**（P72 §1.5）：累计达成后 AB/BA 恒 0，转变矩阵退化为单调爬升，测不出活动间转运/翻车
4. **演进路径未定**（P72 §6）：A'（banner 局部窗口，真转变）vs B（pool 级阶段转变，缺 pool 开放区间数据，暂不采纳）

## 二、目标（占位）

- 转变分析成为有效分析：success_criteria 判据真正生效、转变矩阵测出真转变
- 吸收态限制解决（A' 局部窗口）或明确标注为已知限制
- 与 P72 已完成的键空间修复平滑衔接

## 三、方案（占位——设计待启动）

- 演进路径 A'（banner 局部窗口）可行性细化：判据改为局部化（如「该活动期间出了目标卡/SSR」）
- per_pool_target 判据有效化（streaming 提取器尊重所选判据）或移除
- N3 修复落点（与 P72 §5.1 原候选衔接：banner 化 / 保留 pool 级 / 移除）
- 与 P71 维度 3（成败口径 draw-only/含累抽得/全获得）的耦合裁决
- **未触达识别的数据层根治**（2026-08-07 P72 D5 登记）：P72 已裁「语义 A（继承态）」——未触达 banner 快照 = sim 终点继承态（语义合理非 bug），P72 消费端只做展示口径（2d-1），不做识别。本计划重构窗口逻辑时优先评估数据层根治：改回退循环（streaming.py L365-381）让未触达 banner 显式标记「未触达」，或快照补 sim 终点时间字段（当前仅并行路径含 `pool_end_time`、单线程路径缺），使所有消费端自动受益。
