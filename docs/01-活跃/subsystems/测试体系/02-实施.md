## 2. 测试模式

### 文件组织约定

- 每个源文件对应一个测试文件：`gacha_simulator/core/xxx.py` → `tests/core/test_xxx.py`
- 测试文件命名：`test_<模块名>.py`
- 测试函数命名：`test_<功能描述>`
- 测试类命名：`Test<功能分组>`（仅在需要共享 fixture 时使用）

### 工厂函数模式

```python
# 延续现有模式：模块级工厂函数，不污染 conftest
def _make_state(resources=None):
    return GachaState(resources=resources or {'draw_resource': 1000})

def _make_ctx(state, pools, **kwargs):
    return StrategyContext(state=state, current_pools=pools, ...)
```

### AAA 模式

```python
def test_smart_strategy_selects_exchange_first():
    # Arrange —— 构造输入
    state = GachaState(resources={'draw_resource': 100, 'exchange_currency': 50})
    strategy = create_strategy('smart', {})

    # Act —— 执行被测函数
    action = strategy.select_action(ctx)

    # Assert —— 断言输出
    assert isinstance(action, ExchangeAction)
```

### 参数化

```python
# 同逻辑不同输入——参数化
@pytest.mark.parametrize('strategy_key', ['smart', 'pool_quota', 'pity_reserve',
    'stop_on_target', 'target_hunting', 'fixed_count', 'draw_target'])
def test_all_strategies_return_valid_action(strategy_key):
    ...

@pytest.mark.parametrize('gdr_key', UNIFIED_GDR_REGISTRY.keys())
def test_all_gdr_compute_returns_finite(gdr_key):
    ...
```

### Mock 策略

几乎不用 mock。代码链路为 `输入 → 计算 → 输出`，无外部 IO。例外：
- `streaming.py` 的多进程路径可能用 `multiprocessing` 测试技巧
- 时间依赖场景可用 `freezegun`（仅在必要时引入）

## 3. 每模块测试覆盖清单

每个目标模块的测试按四类场景分配：

| 类别 | 占比 | 示例 |
|------|------|------|
| Happy path | 40% | 正常输入 → 期望输出 |
| 边界条件 | 30% | 零抽卡、空目标、资源刚好够/不够 |
| 异常输入 | 15% | 不存在的池子 ID、负数资源 |
| 回归锚点 | 15% | 针对已知 bug（注释引用 `fix:` commit hash） |
