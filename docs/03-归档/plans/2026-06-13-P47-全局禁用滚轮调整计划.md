# P47 全局禁用滚轮调整

> 日期：2026-06-13 | 状态：已实施  <!-- REVIEW-R1-FIX: ISSUE-001 -->
> 触发：用户在配置面板等 ScrollArea 中滚动时，鼠标经过 QComboBox / QSpinBox / QDoubleSpinBox 会意外切换选项/修改数值。需求：全局禁用这三类控件的滚轮调整，同时将滚轮事件转发给外层 ScrollArea 保持页面正常滚动。

## 一、问题

### 1.1 现状

项目 GUI（PyQt6）10 个 Tab 中，6 个活跃面板包含 QComboBox / QSpinBox / QDoubleSpinBox 控件。用户在 QScrollArea 中滚动页面时，鼠标一旦经过这些控件，滚轮事件被控件捕获——导致下拉选项切换或数值 ±1——而非滚动页面。这是 Qt 默认行为，属于 UX 反模式。

## 二、目标

1. **全局统一**：QComboBox / QAbstractSpinBox（含 QSpinBox、QDoubleSpinBox、QDateEdit/QTimeEdit/QDateTimeEdit 等所有子类）在任何面板中均不响应滚轮 <!-- REVIEW-R1-FIX: ISSUE-001 -->
2. **页面正常滚动**：滚轮事件转发给外层 QScrollArea，用户无感知，不存在死区
3. **下拉列表不受影响**：ComboBox 弹出下拉列表后，列表内滚轮正常选单
4. **零面板代码修改**：不在任何面板中逐个替换控件或安装过滤器
5. **自动覆盖未来**：后续新增面板/控件无需任何额外操作

## 三、方案

### 核心技术：QApplication 全局事件过滤器 + 祖先转发

在 `QApplication` 上安装单个事件过滤器，拦截所有发给 QComboBox / QAbstractSpinBox（含 QSpinBox、QDoubleSpinBox、QDateEdit/QTimeEdit/QDateTimeEdit 等子类）的滚轮事件，将其转发给最近的 QAbstractScrollArea 祖先，同时返回 `true` 阻止原目标处理。 <!-- REVIEW-R1-FIX: ISSUE-001 -->

**事件链路：**

```
鼠标在 ComboBox 上滚动
  → QApplication.notify()
  → GlobalWheelBlocker.eventFilter(obj=ComboBox, event=Wheel)
      ├─ isinstance 命中 ✓
      ├─ 沿 parent 链向上查找 QAbstractScrollArea
      │   ComboBox → QFrame → ... → QScrollArea.viewport() ← 找到
      ├─ sendEvent(viewport, event)  → 页面正常滚动 ✅
      └─ return True                 → ComboBox 不收到事件 ✅
```

### 阶段 A：核心实现（主变更）

**A1. 新建 `gacha_simulator/gui/wheel_blocker.py`**（~23 行）<!-- REVIEW-R1-FIX: ISSUE-004 ~20→~23，viewport() None 判空 +2 行 -->

```python
"""全局滚轮过滤器——QComboBox/QAbstractSpinBox 不响应滚轮， <!-- REVIEW-R1-FIX: ISSUE-001 -->
将事件转发给外层 ScrollArea 保持页面正常滚动。"""

from PyQt6.QtCore import QObject, QEvent, QCoreApplication
from PyQt6.QtWidgets import (
    QComboBox, QAbstractSpinBox, QAbstractScrollArea,
)


class GlobalWheelBlocker(QObject):
    def eventFilter(self, obj, event):
        if event.type() != QEvent.Type.Wheel:
            return super().eventFilter(obj, event)
        if not isinstance(obj, (QComboBox, QAbstractSpinBox)):
            return super().eventFilter(obj, event)

        # 查找最近的可滚动祖先，转发事件
        parent = obj.parent()
        while parent is not None:
            if isinstance(parent, QAbstractScrollArea):
                vp = parent.viewport()                     # <!-- REVIEW-R1-FIX: ISSUE-004 防御 viewport() 为 None——widget 析构过程中可能短暂返回 None -->
                if vp is not None:
                    QCoreApplication.sendEvent(vp, event)
                break
            parent = parent.parent()

        return True  # 阻止目标控件自己处理
```

## 五、风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| `sendEvent` 导致递归（ScrollArea 滚动后事件再次经过过滤器） | 低 | 中 | `sendEvent` 发送到 `viewport()`（QWidget），`isinstance` 检查不命中 ScrollArea 视口——直接放行，不递归 |
| 某处 QComboBox 不在 ScrollArea 内，`while parent` 循环走到根窗口仍找不到 | 低 | 低 | `parent` 最终为 `None`，循环安全退出；`return True` 仍正确阻止控件响应 |
| `viewport()` 返回 None（widget 析构过程中短暂为 None）<!-- REVIEW-R1-FIX: ISSUE-004 --> | 极低 | 低 | `eventFilter` 中 `vp = parent.viewport()` 后判空 `if vp is not None`，None 时跳过 `sendEvent`，`return True` 仍正确阻止控件响应 |
| PyQt6 版本差异导致 `QAbstractScrollArea` 检测行为变化 | 极低 | 低 | `QAbstractScrollArea` 是 Qt 4 以来的稳定基类，PyQt6 完整封装 |
| 键盘 ↑↓ 键在 ComboBox/SpinBox 上是否受影响 | — | — | 不受影响——全局过滤器只拦截 `QEvent.Type.Wheel`，键盘事件直接放行 |
