# P49 配置文件读写格式一致性修复计划

> 日期：2026-06-14 | 状态：规划中 | 优先级：🔴 P0 — 数据完整性
> 来源：配置面板（`config_panel.py`）+ 配置IO（`config_io.py`）审计
> 涉及层：core（`config_io.py`、`pool_config.py`）→ gui（`config_panel.py`）
> 触发：GUI 保存操作导致 schedule.txt 卡池绑定 + pools/*.txt 分布文件双重数据损坏

---

## 1. 问题总览

配置系统有 **两条独立的数据损坏路径**，均通过 GUI「保存配置」（`Ctrl+S`）触发：

| 编号 | 损坏目标 | 根因 | 严重度 |
|------|---------|------|--------|
| D1 | `pools/*.txt` 分布文件 | `_save_distributions()` 写入扁平格式，`parse_distribution_file()` 只能解析嵌套括号格式 | 🔴 致命 |
| D2 | `schedule.txt` 中 SSR/SR/R bindings | `apply_to_store()` 从 GUI 表格重建 bindings 时仅保留 `type` 字段 | 🔴 致命 |

**10 个配置文件中 8 个往返一致**（resources.txt、cards.txt、targets.txt、pity.txt、gains.txt、initial_resources.txt、weights.txt、day_overrides）——仅 `pools/*.txt` 和 GUI 路径下的 `schedule.txt` 受影响。

此外发现 3 个次要缺陷。

---

## 2. D1：分布文件格式损坏（详细分析）

### 2.1 数据流

```
嵌套格式文件 ──parse_distribution_file()──► PoolDistEntry[] ──_save_distributions()──► 扁平格式文件
      ✅ 可正确解析                                                                    ❌ 无法再次解析
```

### 2.2 原始格式（嵌套括号语法，如 `pools/character_pool.txt`）

```
[1]:0.004
[1]=[featured,offrate]
[featured]:0.5
[offrate]:0.5
[featured]=ssr
[offrate]=ssr_alt
[2]:0.051
[2]=sr
[3]:0.945
[3]=r
```

### 2.3 `parse_distribution_file()` 支持的格式

仅支持三种正则模式：
- `^\[key\]\s*=\s*\[list\]$` — 嵌套分组定义
- `^\[key\]\s*:\s*[0-9.]+$` — 概率定义
- `^\[key\]\s*=\s*.+$` — 卡牌ID/绑定定义

所有不匹配的行被**静默忽略**。

### 2.4 `_save_distributions()` 输出的格式（`config_io.py:549-575`）

```
# Distribution for pool_c1

limited_ssr_1 | 0.2000 | ssr | featured
standard_ssr_1 | 0.2000 | ssr
sr_1 | 5.1000 | sr
r_1 | 94.5000 | r
```

这是展开后的 `PoolDistEntry` 列表逐条写入的**竖线分隔扁平格式**。

### 2.5 实测验证

```python
# 扁平格式输入 → parse_distribution_file 输出
>>> parse_distribution_file(flat_file, bindings)
[]   # ← 0 条 rewards，全部静默丢失
```

### 2.6 受影响的范围

- **所有池子的分布文件**（`pools/character_pool.txt`、`pools/weapon_pool.txt` 等）
- **`_no_card` 条目**（空抽仅资源）同样丢失
- **exchange_card 池子**：因 `_load_schedule` 通过 `exchange_card_id` 字段直接构造分布（不读文件），故不受分布文件损坏影响。但文件本身仍会被覆盖为扁平格式。
- **CLI 路径**：CLI 仅调 `load_store_from_directory`，不调 `save_store_to_directory`，不受影响。

### 2.7 边界情况：分布文件不存在

当 `pools/*.txt` 缺失但 `schedule.txt` 引用它时，`_load_schedule` 产生 `distribution=[]`（空列表），**无任何警告**。池子被创建但没有任何可抽卡牌。

## 3. D2：schedule.txt bindings 丢失（详细分析）

### 3.1 数据流

```
schedule.txt ──_load_schedule()──► PoolEntry.bindings ──refresh_from_store()──► GUI表格
  ssr=card;sr=...                   完整保留               仅提取 type 字段
                                                                     │
                                              apply_to_store() ◄──────┘
                                              仅写回 type → bindings={'type':'角色'}
```

### 3.2 关键代码路径

**① 加载时**（`_load_schedule`，`config_io.py:162`）：
```python
bindings=dict(pc.bindings),
# → {'ssr': 'limited_ssr_1', 'ssr_alt': 'standard_ssr_1,...', 'sr': 'sr_1,...', 'r': 'r_1,...'}
```

**② GUI 刷新时**（`_refresh_from_store_impl`，`config_panel.py:2989`）：
```python
pool_type = p.bindings.get('type', '角色') if p.bindings else '角色'
# → 只取了 type，SSR/SR/R 全部丢弃
```

**③ GUI 保存时**（`apply_to_store`，`config_panel.py:2873-2875`）：
```python
bindings = {}
if pool_type:
    bindings['type'] = pool_type
# → 只写了 type，SSR/SR/R 永久丢失
```

### 3.3 实测验证

```
[加载后]   bindings: {'ssr': 'limited_ssr_1', 'ssr_alt': 'standard_ssr_1', 'sr': 'sr_1', 'r': 'r_1'}
[GUI保存后] bindings: {'type': '角色'}
[重新加载]  保底引擎无法识别 SSR/SR 卡
```

### 3.4 影响

- **保底引擎**：`_get_ssr_ids_from_bindings` / `_get_sr_ids_from_bindings` 返回空集合，保底软/硬递增失去目标
- **稀有度判定**：所有卡牌被判定为 `r`（因为不在 ssr_ids/sr_ids 中）
- **featured 判定**：所有卡牌均非 featured

### 3.5 注意：直接 `save_store_to_directory` 不受影响

如果 bindings 在 ConfigStore 中是完整的，直接调用 `save_store_to_directory`（未经 GUI apply_to_store）可以正确保存。损坏仅发生在 GUI 路径中 `apply_to_store()` 覆盖 bindings 后。

## 4. 次要缺陷

### 4.1 死代码（`config_panel.py:2258-2259`）

```python
[{'resource_id': rid, 'amount': amt}
                             for rid, amt in store.initial_resources.items() if amt > 0]
```

列表推导式创建后未赋值给任何变量，功能已被下方 `resource_defs`（line 2281-2283）和 `initial_resources`（line 2320-2321）覆盖。

### 4.2 分布编辑对话框列号判断错误（`config_panel.py:919`）

```python
def _edit_pool_distribution(self, row, col):
    if col != 8:   # ← 应为 col != 9
        return
```

池子表格列布局：0=启用, 1=ID, 2=名称, 3=类型, 4=开始, 5=持续, 6=消耗, 7=批次大小, **8=备注**, **9=分布编辑**。当前代码双击备注列会误触发分布编辑对话框，而双击分布编辑列不会触发。

### 4.3 `_load_targets` 中 quantity 合并语义（`config_io.py:373`）

```python
existing.quantity = max(existing.quantity, quantity)  # 取 max 而非 sum
```

同名卡多行时取最大值而非累加。若用户意图为"各行独立需求数量"，应使用 `sum`。需确认语义或添加文档说明。

## 6. 推荐修复方案

### 6.1 修复 D1：给 `parse_distribution_file` 增加扁平格式 fallback

**方案：** 在 `parse_distribution_file` 末尾增加扁平格式解析逻辑。当 `top_keys` 为空（即文件不含任何嵌套语法）时，尝试按竖线分隔扁平格式解析。

**文件：** [pool_config.py](gacha_simulator/core/pool_config.py) `parse_distribution_file()`

**逻辑：**
```python
# 在现有解析逻辑后，若 all_leaves 为空，尝试扁平格式 fallback
if not all_leaves:
    for line in raw_lines:
        parts = line.split('|')
        if len(parts) >= 3:
            card_id = parts[0].strip()
            try:
                prob = float(parts[1].strip()) / 100.0  # 百分比→概率
            except ValueError:
                continue
            rarity = parts[2].strip().lower()
            # 解析可选字段：featured / resources / ft / nth / xs
            ...
            all_leaves.append((card_id, prob))
```

**优点：**
- 向后兼容——旧的嵌套格式仍可解析
- 不需要反向推导分组结构（`PoolDistEntry` 已丢失嵌套信息）
- 改动集中在 `pool_config.py` 一个文件

**风险：** 若文件同时包含嵌套语法和扁平行（混合格式），fallback 不会触发。当前 `_save_distributions` 总是写入纯扁平格式，故不存在混合场景。

### 6.2 修复 D2：保存 bindings 完整信息

**方案 A（推荐）：** 在 `ConfigPanel` 中新增 `_pool_bindings` 字典，独立存储除类型外的完整 bindings。

**文件：** [config_panel.py](gacha_simulator/gui/config_panel.py)

**改动：**
1. `_refresh_from_store_impl()`：从 `p.bindings` 提取完整 bindings，存入 `_pool_bindings[pool_id]`（过滤掉 `type` 键）
2. `apply_to_store()`：合并 `_pool_bindings[pool_id]` + `{'type': pool_type}` 作为完整 bindings
3. `get_config()` / `set_config()`：同步处理 `_pool_bindings`

**方案 B（备选）：** 在池子 GUI 表格中增加隐藏列存储原始 bindings 字符串。

**方案 A 更简洁**——不改变表格列布局，仅在内存中保留 bindings 数据。

### 6.3 修复次要缺陷
