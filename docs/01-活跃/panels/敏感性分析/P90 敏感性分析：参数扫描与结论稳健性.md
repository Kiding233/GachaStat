### 1.3 可扫描参数是四类，成本差两到三个数量级

| 类 | 改什么 | 是否重跑 | 单点成本 | 归属 |
|---|---|---|---|---|
| 口径参数 | 从同一批样本里算什么 | 否 | O(n)，毫秒级 | 复算侧（P86） |
| 策略参数 | `strategy_params` | 是 | N × M 次模拟 | 派发侧（P87） |
| 机制参数 | 池子／保底／里程碑／资源 | 是 | N × M 次模拟 | 派发侧（P87） |
| 精度参数 | 用多精的方法测 | 否（重算分析） | O(n) 或 O(n log n) | 复算侧（P86） |

完整清单与判据见 `01-理论.md` §2。**分界线是「模拟器读不读它」，不是「参数写在哪个文件里」**：`[[weights]]` 写在 config.toml 却只有 GDR 计算读它，属口径参数；`[[targets]]` 同时被策略与 GDR 读，改「追哪张」是机制参数、改「测哪张」是口径参数。

### 1.4 主诉求是「结论是否成立」，现有面板答不出

现有面板给出的都是**单点结论**：对比分析比较给定数据集、统计分析描述当前数据集、方案搜索沿资源维度搜索（单维度特例）。答不出三个问题：这个结论有多稳、哪个参数最要紧、结论在哪里翻转。

项目另有一类独家需求：手册 §二十一 的 **U1–U15 全是「官方未公布、社区假设」的机制参数**（U7 异环两套机制二选一、U8 UP 率 25% vs 75%、U13 战双 T∈[80,100] 分布）。处置方式是「两种互斥取值各跑一遍，看结论是否翻转」，翻转则升级为必须查证，不翻转则可标注「结论对 U8 不敏感」。

## 二、目标

1. **给定数据集（复算侧）或配置（派发侧）与一个参数维度的扫描规格，产出 N 个扫描点上的统计量族与置信区间**
2. **产出翻转区间与裕度**，而非单个翻转点（依据见 `01-理论.md` §三）
3. **产出「说不准地带」**，即结论既不能判定成立也不能判定不成立的参数区间
4. **区分信号与噪声**：结论的成立／翻转判定必须建立在正确量化的不确定性之上，不得只看点估计
5. **产出形态与 P86 一致**：`sections` 列表（图表优先），机器消费者可从稳定 metric key 无损取出数值
6. **两侧共用同一结果对象**，使「口径参数 × 机制参数」将来可组合（第一版不做二维）

## 三、方案

### 3.1 分类框架：判据是「模拟器读不读它」

见 §1.3 与 `01-理论.md` §2.3。四类不是一个分类学练习，它同时是**架构归属线**（复算侧走 P86 的 `AnalysisRunner`，派发侧走 P87 的变换器）与**能否先做**的答案。

### 3.2 分层与调用关系

```
前端（P74 分析页「敏感性分析」专题）
    ↓
P90 敏感性分析        ← 与 GUI / WebUI 平级，是 AnalysisRunner 的第三个调用方
    ├── 复算侧：循环调 AnalysisRunner.run(dataset_ids, method, params_v)
    └── 派发侧：P87 变换器生成 N 个 sub 配置 → 运行器派发 → 分析侧读结果
    ↓
P86 AnalysisRunner  /  P87 变换器·运行器·汇合器
```

**不新增「分析调用分析」机制。** 敏感性分析**不进** P86 的分析项注册表。理由三条：

1. **语义不匹配**：注册表项签名是 `fn(ctx, params) -> List[Section]`，含义是「一个数据集 → 一组 sections」；敏感性是「跨 N 次调用的聚合」，天然产出 N 个结果。
2. **循环风险**：进注册表就会出现「注册表项调用注册表」（它可能包到自己），需额外守卫。
3. **收益不成立**：进注册表唯一的好处是自动生成表单，而它的表单形态本就不同（要选内部参数、扫描范围、关注的统计量）。

P86 §3.6 已否决过一次同类过度抽象（把分析抽象成「度量 × 分组 × 视图」的笛卡尔积），理由记在案：「强行表达会造出表达力不足的 DSL」。把扫描塞进普通分析项属同一类风险。

**P86 侧需配合两条（都很小，不要求改框架）：**

- **稳定标识必须跨参数值稳定**。`SummarySection.items` 的 metric key 不得把参数值编进 key（不能是 `target_achievement@threshold=0.95`），否则 N 个扫描点对不上同一个量，「跨点追踪」退化为拼字符串。
- **扫描面从 `AnalysisSpec.params` 派生**。P86 §3.6 精化一已把每个分析项的参数声明为 `ParamDescriptor` 列表，`FloatParam` / `IntParam` 可数值扫描，其余可枚举。敏感性分析**不自行维护**「能扫什么」的清单。

**一个已评估的替代（记录以免后人重走）**：让敏感性分析绕开 P86，直接在 `core/` 上调 `gdr.py` / `bootstrap.py` / `comparison_analyzer.py`。否决，理由是那会造出分析编排的第三份实现，正是 P86 §1.2 记录的问题（`_unique_count` 两侧行为已不同：GUI 版取前 5000 采样见第 3 个不同值即早退，WebUI 版是全量 `len(set())`）。

### 3.3 扫描规格的三种模式

「区间 + 步长」不足以覆盖。三种模式都由 `ParamDescriptor` 的类型天然派生：

| 模式 | 触发类型 | 产出形态 | 例 |
|---|---|---|---|
| **数值栅格** | `FloatParam` / `IntParam` | **曲线**（同一统计量的 N 个取值） | GDR 阈值、权重系数、`pity_reserve.pity_threshold_pct`、池子 cost |
| **离散枚举** | `BoolParam` / `StrParam` / `StringListParam` / `PoolIntMapParam` | **对比**（N 个不同口径，不是曲线） | 哪个 GDR 指标、`stop_on_target` 的布尔、`draw_target` 的卡列表 |
| **互斥分支** | 二者的特例：枚举只有两个取值 | **对比** | U8 异环 UP 率 25% vs 75% |

**依据**：8 个内置策略中 6 个有参数，能用数值栅格表达的只有 2 个（`fixed_count.count`、`pity_reserve.pity_threshold_pct`），其余 4 个是布尔／字符串／字符串列表／映射。这不是可选项，是这一类里三分之二的形态。

**注意**：枚举模式下「翻转点」概念退化。数值扫描有 θ 轴、翻转点有意义；枚举比对没有轴，问题变成「两个口径是否显著不同」。两者的结论对象形态不同，实现时不得混为一谈（见 `01-理论.md` §七.2）。

### 3.4 参数面三源

| 类 | 扫描面来源 | 状态 |
|---|---|---|
| 口径 | `AnalysisSpec.params` | P86 设计中 |
| 策略 | `StrategyMeta.params` | P69 已落地 |
| 机制 | **白名单**（本计划定义） | 待建 |
| 精度 | 与口径同类，但旋钮不在分析项的 `params` 里（bootstrap B、EVT 阈值、搜索参数），需单独登记 | 待建 |

**机制参数用白名单，不做通用路径寻址。** 理由：机制参数字段既多又活在数组里（`store.banner.banners[i].pools[j].cost`、`store.pity.pities[i].threshold`、`store.milestone.milestones[i].threshold`），通用寻址意味着用户能扫任意字段，包括那些一改就违反配置校验的（如改 `PityDef.scope` 会触发 `ConfigError`），错误路径太多。而**真正值得扫的字段很少**。

白名单的形态：`ParamDescriptor` 列表（与口径／策略对外一致）＋ 一个「apply 到 ConfigStore」的函数。落点与清单内容见 §七 待决项 B。

**apply 的方式**：反射改 dataclass（按 `id` / `name` 找索引后赋值）。不走「改 TOML dict 层再重新解析」，因为那要重跑一遍 `load_toml`，连带 `_check_pity_format` 等校验全部重来，成本高且副作用多。

### 3.5 结果对象

**图表优先。** 沿用 P86 的 `AnalysisResult.sections: List[Section]`，不另造对象。在「图表优先」下，需要装的东西全部塌缩为图的元素：

| 要装的东西 | 形态 |
|---|---|
| 曲线（数值扫描） | `ChartSection`，折线图 |
| 对比（枚举扫描） | `ChartSection`，条形图 |
| 各点 CI | **同一张图上的误差带** |
| 翻转区间 | **同一张图上的 `ChartAnnotation(vline)`**（两端各一条）或 `ShadedRegion`（说不准地带） |
| 机器消费的数字 | `SummarySection` 的 items（翻转区间端点、裕度、各点估计与 CI），带稳定 metric key |

即：**一到两个 `ChartSection` 加一个 `SummarySection`**。翻转点与 CI 是图的元素，不是与曲线并列的兄弟对象。

**`ScatterTrace` 加 `fill` 属「画什么」而非「画成什么样」**，故放数据类而不放 `layout_hints`（后者是渲染细节的自由字典，`core/gdr_binning.py:53` 即该用法）。

### 3.6 翻转点定位

**均匀采样 + 细化**：

1. 在 `[start, end]` 上按步长采样，得 N 点，读出形状与翻转所在的**夹逼区间**
2. 在夹逼区间内二分，把翻转位置精确到容差

**不做纯二分**：它假设单调性，给不出形状，且遇跳变会失效（P26 Q2 的几何锚定效应即「中点恰好击中硬保底跳跃点」导致收敛到错误侧）。
**第一版不做自适应采样**：实现复杂、结果不可预期，且采样点依赖运行时观测，与可复现目标冲突。

**步长必须小于机制的最小特征尺度**，否则整段跳过跳变。本项目机制里跳变是常态：P26 核验报告实测 `p(r)` 是三级阶梯函数、第三跳跃达 35.0×SE；硬保底跳跃点；手册 G4 异环棋盘双态 1%→19.5%。

### 3.7 统计核心：判定，不是汇总

如果本功能只是「跑 N 次 + 把图排在一起」，用户完全可以手动跑 N 次并排看，功能不成立。价值在于「并排看」答不出「结论翻转了没有」。所以核心运算有三项：

**1. 区分信号与噪声。** 两侧性质不同（`01-理论.md` §二）：

- 复算侧样本固定，`ŝ(θ_i) − ŝ(θ_j)` 不含抽样噪声，**差异即信号**；各点完全配对。
- 派发侧每点独立抽样，差异 = 信号 + 抽样噪声 + 分析噪声；**不配对**（依据：并行路径用 `imap_unordered`，`aggregate_data` 按完成顺序排列与 seed 顺序无关，记录无 seed 字段）。

因此**两侧不能用同一套判据**。具体取哪套见 §七 待决项 A。

**2. 翻转点的不确定性。** 输出是**翻转区间**而非点：从「结论确定成立端」到「确定不成立端」之间是「说不准地带」，宽度量级约为 `CI 半宽 / |ds/dθ|`。只报单个翻转点是虚假精确，与 P88 §3.5 判定的那类错误同源（那里实测朴素二项 CI 低估方差 39 到 131 倍）。

**3. 形状判定。** 单调 / 非单调（非单调说明内部有极值点，是不同结论，且翻转点是集合而非单点）；有无跳变（跳变点与翻转点是两回事）。

**多重比较必须处理**：N 个扫描点各自做判定会累积第一类错误，按每点独立口径报「显著」会使实际错误率远高于名义水平。

**种子账本（前置纪律）**：扫描时参数变、种子不变，且种子账本从扫描规格一路贯穿到分析层。现状是硬编码散落：`analysis_panel.py:2337` `random_seed=42`、`comparison_analysis_panel.py:30` `rng_seed=42`、`comparison_service.py:108` `rng_seed=42+order`、`analysis_service.py:619` `default_rng(42)`、`vulnerability.py:280` `seed=None`（同数据集重跑结果会变）、`analysis_panel.py:775` `np.random.choice` 无种子。**不修这条，扫描结果的抖动无法归因，会把噪声读成敏感性。**

### 3.8 阶段 0：ChartSpec 扩展（无依赖，可独立提前执行）

| 项 | 内容 |
|---|---|
| 文件 | `visualization/chart_spec.py` |
| 改动 | `ScatterTrace` 加 `y_lower` / `y_upper` / `fill_color` 三字段（缺省 `None`，向后兼容） |
| 文件 | `visualization/plotly_charts.py` |
| 改动 | `_build_scatter`（`:322`）的 `for tr in d.traces:` 循环内，画线前先画带 |
| 实现 | `fill='toself'`：`x = concat([tr.x, tr.x[::-1]])`、`y = concat([tr.y_upper, tr.y_lower[::-1]])`、`line=dict(width=0)`、`showlegend=False`、`hoverinfo='skip'` |

**为什么给上下界而不给误差半宽**：CI 常常不对称。项目里用的就是不对称那套（`analysis_panel.py:2361` 的 `bootstrap_mean(vals, use_bca=True)`，BCa 正是做偏差与偏度校正的）。

**为什么挂在 trace 上而非 `ScatterData`**：多轨迹模式下每条轨迹各带各的带子。

**为什么用 `toself` 而非 `tonexty`**：`tonexty` 的语义是「填到列表中下一条 y 轨迹」，依赖顺序，且是 Plotly 私有；ECharts 无此原语（POC renderer `tools/poc_webview/ui_compare/src/panels/workbench/specToECharts.js` 用堆叠 area 画带子）。IR 只表达意图，两个渲染器各自实现。

**为什么本项目已有先例**：`gui/comparison_analysis_panel.py:802-810` 就是这么画的（但它走的是 `ChartWebView.set_charts` 的逃生口子，直接传裸 `go.Figure`，不经 IR）。

**不用改的**：webui 序列化走 `webui/analysis_service.py:36` 的 `_spec_to_dict`（`dataclasses.asdict` ＋ 递归 `_clean`），新增字段自动跟随；四处副本（analysis / comparison / vuln / worst_impact）都不用动。

**归口说明**：ChartSpec 属「图表引擎」子系统，该子系统状态为「已完成(P11)，**无关联主题计划**」（`模块状态矩阵.md:37`、`subsystems/图表引擎/00-档案.md:4`），故没有现成承接方。本计划自带此任务，并标注可独立提前执行。

**P74 连带项**：POC 的 ECharts renderer `specToECharts.js` 的 `case 'scatter':`（`:406`）需同步实现堆叠 area，登记为 P74 实施时的连带项。

## 六、验收标准

**阶段 0**

- [ ] `ScatterTrace` 有 `y_lower` / `y_upper` / `fill_color` 三字段，缺省 `None`，旧用例不受影响

- [ ] 旧有带填充的图（`comparison_analysis_panel`）不受影响（它走逃生口子，不经 IR）

**阶段 1（复算侧）**

- [ ] 给定数据集 ＋ 一个口径参数 ＋ 数值栅格规格，产出曲线 ＋ 误差带 ＋ 翻转区间 ＋ `SummarySection`

**阶段 2（派发侧）**

- [ ] 给定配置 ＋ 一个策略参数或机制参数 ＋ 扫描规格，生成一个批次，N 个数据集落工作区

- [ ] 机制参数白名单外的字段不出现在可扫清单中

- [ ] 复算侧与派发侧各用与其统计性质相符的判据（待决项 A 落地）

## 七、待决项

**A. 「区分信号与噪声」的具体判据未定（🔴 阻塞阶段 3）**

决定「结论成立／翻转」的判定逻辑。候选与其性质见 `01-理论.md` §五：

| 候选 | 复算侧 | 派发侧 | 主要问题 |
|---|---|---|---|
| 各点 CI 是否重叠 | 可用但不必要 | 可用 | 「CI 重叠」与「差异不显著」不等价 |
| 配对检验 | **可用** | **不可用** | 只在复算侧有效 |
| 两样本检验 | 可用但浪费配对 | 可用 | 多重比较 |
| 趋势检验 | 可用 | 可用 | 验的是单调趋势，不是翻转 |
| 只报 CI 不判定 | 可用 | 可用 | 把负担推给用户，与主诉求相悖 |

**B. 机制参数白名单的字段清单与各字段范围**

范围待定。已识别的候选：池子 `cost` / `rewards[].probability` / `batch_size`、`PityDef.threshold` / `soft_start` / `soft_end` / `cr_base_rate`、`MilestoneDef.threshold`、初始资源。落点（新文件 vs 现有文件）也待定。

**C. 派发侧批次的树视图呈现**

接口层 P87 §3.11 F 已定（批次标识 ＋ 「组是查询而非实体」）；呈现属 P74 前端。本计划只需确认 `derivation` 携带参数分配信息是否足够，不需要定前端形态。

**D. 「说不准地带」的呈现方式**

画成图上的带状（`ShadedRegion` 只支持 x 方向区间，恰好够用）？还是只在 `SummarySection` 报区间端点？见 `01-理论.md` §七.1。

**E. 枚举模式下结论对象的形态**

数值扫描有 θ 轴、翻转点有意义；枚举比对没有轴，「翻转」退化为「两个口径是否显著不同」。两者的结论对象是否分开，见 `01-理论.md` §七.2。

**F. 多翻转点的呈报**

非单调时翻转点是集合，裕度取最近者，但「存在多个翻转点」这件事本身是否要提示。

**G. 精度参数的登记面**

精度参数旋钮（bootstrap B、EVT 阈值、搜索 `num_simulations` / `precision_draws`、`n_heatmap_bins`）不在任何 `AnalysisSpec.params` 里，需要单独登记。范围与落点待定。
