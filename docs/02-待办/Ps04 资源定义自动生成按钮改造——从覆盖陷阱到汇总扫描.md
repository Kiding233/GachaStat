# Ps04 资源定义「自动生成」按钮改造——从覆盖陷阱到汇总扫描

> 日期：2026-08-25 | 状态：已实施（独立审查见 §六，实施与验证见 §八）
> 触发：用户反馈——「自动生成」按钮当前功能无意义
> 性质：功能性改进（P78 遗留收尾），修改面集中（config_panel.py 单文件 + 相关测试），核心改动约 20 行

## 一、问题定位

### 现状（三个调用点，关键区分）

`_auto_generate_resource_defs`（`config_panel.py:5791`）当前实现为：

```python
def _auto_generate_resource_defs(self):
    defs = [
        {'resource_id': 'draw_resource', 'display_name': '抽卡资源', 'initial_amount': 0},
        {'resource_id': 'exchange_currency', 'display_name': '兑换货币', 'initial_amount': 0},
    ]
    self.set_resource_defs(defs)
```

它被**三个调用点**引用，语义各不相同：

| 调用点 | 位置 | 语义 | 点击时会怎样 |
|--------|------|------|------------|
| 按钮点击 | `_setup_resource_def_tab` L3899 | 手动触发 | **覆盖**成 2 个固定资源 |
| `_set_defaults()` | L5097（`__init__` L544 调用） | 新面板初始化兜底 | 写入 2 个默认资源 |
| L6285 分支 | `_refresh_from_store_impl` 空 store 兜底 | 空配置加载 | 写入 2 个默认资源 |

### 缺陷：按钮的「覆盖」语义是误操作陷阱

点「自动生成」会调用 `set_resource_defs`，**整体覆盖**当前资源定义为 2 个固定资源。若用户已在卡池配置了 `voucher1` 等其它资源，一点按钮这些定义就被冲掉（尽管 select_voucher/milestone 可能还在，但显示层定义瞬间丢失）。

### 需保留的部分：函数本体与两个兜底调用点不能删

- `_set_defaults`（L544 → L5097）与 L6285 兜底是**新面板 / 空配置加载**的合理默认来源。ISSUE-124「全空资源定义兜底预期」（P78 文档 L454 验收清单项）约定「资源定义 Tab 删除全部资源 → 保存 → 重载后，左列表出现默认 `draw_resource`/`exchange_currency`」。
- **独立审查发现（缺陷 A）**：ISSUE-124 这一行为当前**仅是文档验收清单项，`tests/` 中并无对应 pytest 自动化断言**（`exchange_currency` 在 GUI 测试中零出现；`test_p58_milestone.py` 是纯数据层/引擎层测试，不触 GUI 兜底）。因此改造会保留该语义（兜底分支完整继承），但**当前无自动化测试保护**。本计划补一条 pytest 断言以真正锚定该语义（见 §五）。

## 二、改动方案

### 方案：把按钮语义从「覆盖」改造为「汇总扫描 + 只补不覆盖」

核心：`_auto_generate_resource_defs` 改为「保留空兜底分支 + 汇总扫描所有配置源，用 `_ensure_resource_registered` 只补不覆盖」。

```python
def _auto_generate_resource_defs(self):
    """从全配置汇总缺失资源，只补不覆盖（替代原硬编码覆盖式）。

    两个用途兼容：
      ① 兜底（_set_defaults / 空 store 加载）——全空时给 2 个默认资源（ISSUE-124 验收语义）
      ② 按钮点击——扫描卡池 cost/rewards + 里程碑奖励 + 自选券 voucher id，
         只补不覆盖，堵死原「点击覆盖成 2 个固定款」误操作陷阱。
    """
    # 兜底：全空时也给两个默认（保持 ISSUE-124 文档验收项），但**不 return**——
    # 加默认后继续扫描，让「汇总扫描」真正覆盖所有配置源（缺陷 B 修正）。
    if not self.resource_defs:
        defs = [
            {'resource_id': 'draw_resource', 'display_name': '抽卡资源', 'initial_amount': 0},
            {'resource_id': 'exchange_currency', 'display_name': '兑换货币', 'initial_amount': 0},
        ]
        self.set_resource_defs(defs)

    # 汇总扫描：卡池 cost/rewards（复用 _register_resources_from_pools）
    # 守卫用 getattr ——若 _banner_defs 从未初始化，直接访问会抛 AttributeError（缺陷 C 修正）
    if getattr(self, '_banner_defs', []):
        self._register_resources_from_pools()
    # 里程碑奖励（bonus_reward + alternate_rewards 同构）
    for md in getattr(self, '_milestone_defs', []):
        for rid in md.get('bonus_reward', {}).get('resources', {}):
            self._ensure_resource_registered(rid)
        for alt in md.get('alternate_rewards', []) or []:
            if isinstance(alt, dict):
                for rid in alt.get('resources', {}):
                    self._ensure_resource_registered(rid)
    # 自选券 voucher id
    for sv in getattr(self, '_select_vouchers', []):
        self._ensure_resource_registered(sv.get('voucher', ''))
```

### 方案要点说明（供审查聚焦）

1. **兜底分支不 `return`，加默认后继续扫描**：全空时给 2 个默认并**继续往下扫**。这样 `_set_defaults`（新面板）与 L6285（空 store 加载）走兜底分支仍得到 2 个默认（ISSUE-124 文档验收项保持），但按钮点击即使 resource_defs 为空也能补全 milestone/select_voucher 引入的其它资源，完全吻合「汇总扫描」目标（缺陷 B 修正）。空列表扫无副作用。
2. **非空时才扫描**：`self.resource_defs` 非空时，走汇总扫描。`_ensure_resource_registered`（L5117）语义是「已存在则跳过，不存在则追加 + 重建列表 + 刷新下拉」，天然只补不覆盖。
3. **`_register_resources_from_pools` 守卫写 `getattr(self, '_banner_defs', [])`**：若直接写 `if self._banner_defs:` 而 `_banner_defs` 从未初始化，访问会抛 AttributeError——那不叫防御。用 `getattr` 默认空列表，与 `_milestone_defs`/`_select_vouchers` 的 `getattr` 写法统一，才名副其实（缺陷 C 修正）。`_register_resources_from_pools` 内部遍历 `self._banner_defs`，空时循环体不执行、零副作用。
4. **`getattr` 防御（`_milestone_defs`/`_select_vouchers`）**：这两个列表在 `_setup_milestone_config`（L2163-2164）初始化，而 `_set_defaults`（L544）在 `_setup_ui`（L543）**之后**才调用，此时均已初始化。`getattr` 是低成本稳健性保险，防未来调整初始化顺序。
5. **按钮不需要确认弹框**：改成「只补」后无破坏性，无需「确定要覆盖吗」警告。

## 四、不改动的边界

- **`_set_defaults`（L5097）与 L6285 兜底调用点**：不动。它们仍调 `_auto_generate_resource_defs`，走空兜底分支，ISSUE-124 验收语义保持。
- **`_register_resources_from_pools`（L5099）**：不动。它是独立的正向同步机制（保存/刷新时自动补卡池资源），与按钮扫描是**同源复用**关系。
- **`_ensure_resource_registered`（L5117）**：不动。复用。
- **数据层 `resource_defs: Dict[str, str]`**：不动。本次纯 GUI 层按钮语义改造。
- **`config.toml`**：不动（默认配置已撤销 P78 示例，保持基线）。

## 七、决策记录

- **删按钮 vs 改造**：用户评估后倾向「改造为汇总扫描」而非直接删除。理由：函数本体被 `_set_defaults`/L6285 兜底依赖不能删；按钮「覆盖」语义无意义，但改造成「补全工具」后真正有用（新手点一下自动补全所有配置引用的资源）。代价 ~20 行，成本低。
- **保留兜底分支**：`_set_defaults`/L6285 需要兜底，且 ISSUE-124 有文档验收项，保留。
- **不确认弹框**：改「只补」后无破坏性，无需警告。
- **采纳审查 3 项修正**：缺陷 A 补测试锚定语义、缺陷 B 不 return 继续扫描、缺陷 C 用 getattr 守卫。
