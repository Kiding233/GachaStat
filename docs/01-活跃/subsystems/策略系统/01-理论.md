## 一、核心假设

### 1.1 启发式决策假设（缺陷 12）

所有 8 种策略均为**基于规则的启发式**，不追求期望效用最大化或贝尔曼最优性。

**内核假设**：
1. **一阶前瞻（或零阶）**：策略检查当前条件后立即行动，不递归评估未来状态的期望价值。
2. **无延迟价值评估**：没有策略权衡「现在花费资源抽此池」vs「等待更好的池子」。
3. **无保底跨期价值**：没有策略能预测保底计数器在未来池子中的价值。

**理论立场**：
> 抽卡游戏的最优策略通常是 NP-hard 的——多池 × 多保底 × 多资源 × 多目标的随机动态规划问题，其状态空间呈组合爆炸。实际游戏中玩家也使用启发式（如「攒石等到限定池」）。因此，策略系统采用基于规则的启发式而非贝尔曼最优是合理的工程决策。理论审查的重点不是要求实现最优策略，而是**明确文档化这一设计决策**。

**文献**：Simon (1956), *Psychological Review*——满意原则（satisficing）；Bellman (1957), *Dynamic Programming*

> **处置结论**（2026-06-13，P30）：由**关于页面「策略行为说明」tab** 覆盖用户核心需求——逐策略说明决策逻辑、适用场景与局限（`gui/about_dialog.py`）。原推荐方案经逐条评估后**均不予实施**：
> - 推荐 1（`strategy.py` 模块级 docstring）不实施——用户不读源码 docstring，关于页面是正确位置
> - 推荐 2（UI Tooltip 标注「启发式结果」）不实施——关于页面已覆盖，额外 Tooltip 冗余
> - 推荐 3（`future_schedules` 使用或标注为预留字段）不实施——字段后续需求明确时再启用（该字段后由 P69 阶段 2 补全派生计算，但至今仍无策略消费，见 §1.3）
> - 推荐 4（贝尔曼基准：极简化场景 DP 求解）不实施——研究级增强，无用户需求

### 1.2 无统一效用函数（缺陷 13）

各策略服务于不同的隐式目标——成功率最大化 / 资源最小化 / 风险规避——无共同度量标准。

**后果**：
- 「策略 A 优于策略 B」的断言在不指定元目标时无定义。
- 策略比较面板的排名依赖于 GDR 指标的选取——不同 GDR 下排名可能反转。
- 无法在多维目标间做有原则的权衡（如「成功率低 5% 但省 30% 资源」是否更好）。

**理论建议**（P30 方案）：
1. 策略比较结果应明确说明比较维度和 GDR 指标
2. 提供多维雷达图（成功率 / 平均资源消耗 / 最差资源消耗 / 目标卡收集率）替代单一排名
3. 元目标选择器：允许用户选择「按成功率」「按资源效率」「按稳健性」比较

> **处置结论**（2026-06-13 起）：本条**已委托 P19 Phase 3 #3「L5 偏好排序」**（λ 滑块 + CARA/CRRA 效用函数），P30 不再追踪。
>
> 现状：P19 Phase 3 八项整体**暂缓**（🟠），#3 的暂缓理由为「需要 λ 滑块 UI 调节效率/风险权重 + CARA/CRRA 效用函数，用户群体不熟悉」。P19 清单另拆出 **3a「极简前置」**——策略比较面板 L1 表上方加一行说明文字（「不同策略服务于不同目标，不存在绝对优劣。请根据你关心的维度（成功率/资源效率/稳健性）分别解读」），零新功能，来源正是本条缺陷。**3a 经裁决暂不实施**（2026-09-14），该条仍挂在 P19 清单中。

### 1.3 StrategyContext 信息完备性（缺陷 14）

**字段与计算分支已就位，但实际取值恒为默认常量**（2026-09-15 独立复核结论）：

| 字段 | 定义与计算 | 恒定取值与原因 |
|------|-----------|---------------|
| `future_resource_gains` | 复用抽卡/等待结算的同一 `resource_gain.compute()` | 恒为 `{}`——计算受 `if resource_gain is not None and lookahead` 门控，而 `lookahead` 取自 `self.strategy.lookahead`，8 个内置策略**全为 `None`** |
| `inter_pool_pity_links` | 从 `PityEngine._behavior_list` 中 `pools` 长度 > 1 的行为提取 | 恒为 `{}`——`create_behavior()` 构造 behavior 时从不传 `pools`，behavior 类也无 `_pools` 赋值点，提取分支恒不命中 |
| `time_discount` | 时间偏好因子（默认 1.0） | 恒为 `1.0`——唯一调用点 `gacha_service.py` 未传该参数，全库无其它传值处 |
| `future_schedules` | 未来 lookahead 天内的池子开放窗口（P69 前已存在） | 恒为 `[]`——与 `future_resource_gains` 同受 `lookahead` 门控 |

三者均带默认值，现有策略不经修改即可运行——**这正是问题所在**：默认值掩盖了「数据源未接通」的事实。

**仍未提供**：
- 未来池子的奖励分布（只有 `pool_id` 与时间窗口，没有各池的卡池构成）——需完整的未来卡池数据，超出当前配置范围

**遗留观察**：上述四个未来信息字段**当前无任何内置策略消费**（8 个策略全部为一级或零阶前瞻）。字段是 P30 §2.3 与 P69 阶段 2 的预留设施，其价值要等出现需要跨期决策的策略时才兑现；届时应先接通数据源，再谈消费。

**影响**：即使将来实现贝尔曼最优策略，缺少未来池奖励分布这一点仍会限制跨期决策精度——余下缺口需要配置层先能描述未来池的卡池构成。

## 二、策略分类学

### 2.1 按决策复杂度

| 层级 | 策略 | 前瞻 | 状态依赖 |
|------|------|------|---------|
| 零阶 | `fixed_count`、`stop_on_target`、`draw_target`、`no_draw` | 无 | 仅累计计数 / 恒定等待 |
| 一阶-简单 | `target_hunting`、`pool_quota` | 无 | 池可用性 |
| 一阶-综合 | `smart` | 无（但含兑换优先逻辑） | 目标/资源/池可用性 |
| 一阶-风险感知 | `pity_reserve` | 无（但消费保底概率） | 保底概率阈值 |

无任何策略使用 `lookahead` 窗口或未来信息字段。

### 2.2 按风险态度

| 风险态度 | 策略 | 特征 |
|---------|------|------|
| 风险中性 | `smart`、`target_hunting`、`pool_quota`、`stop_on_target` | 不考虑保底概率，按需求抽卡 |
| 风险规避 | `pity_reserve` | 仅在保底概率达到阈值时抽卡，等待更高出率 |
| 风险偏好 | 无 | 当前无策略偏好高风险高回报的「梭哈」行为 |
| 不适用 | `fixed_count`、`no_draw`、`draw_target` | 基线/工具型策略，不表达风险偏好 |
