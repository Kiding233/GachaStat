## 背景

当前策略系统采用「注册表字典 + if-elif 工厂 + 单一组合模式」，8 个策略全部硬编码。随着 P55/P56/P60 相继完成——保底系统实现了装饰器级的数据驱动工厂、事件驱动保底体系全面就绪、ConfigStore 基础平台成熟——策略系统成为下一个需要对齐这些模式以消除技术债务的模块。

用户期望的策略使用路径是：**委托 coding agent 编写自定义策略 → 放入 strategies 目录 → 应用自动发现并可用**。框架的职责是为 agent 提供清晰的 API 契约、完整的上下文、和可复用的 building block。

**P30 合并说明**：P30（策略系统与保底理论文档补充）的剩余两条未处置项并入本计划——#14（StrategyContext 信息不完备）在阶段 2 落地，#11（保底管道优先级）经 P55/P56 的 `_resolve_order()` 已实际解决。P30 在本计划验收后归档。

## 二、目标

1. 策略类通过 `@register_strategy` 装饰器自描述全部元数据——类定义即注册，消除分离维护
2. 工厂函数完全数据驱动——ParamDescriptor 自动解析参数 + 类型校验 + `cls(**kwargs)`
3. 插件扫描 `strategies/*.py`——importlib 加载，装饰器副作用自动注册
4. TOML 格式从 `type + name + params` 简化为 `key + params`
5. GUI 参数渲染通用化——ParamDescriptor 自动分派 Qt 控件，消除 6 分支 if-elif
6. ConfigStore 从三字段简化为二字段（`strategy_key + strategy_params`）
7. CompositeStrategy 降级为代码级 building block（不进入 TOML/GUI），新增 DrawSegment / PriorityChain / Conditional 三种
8. 未知策略降级处理——插件被删除后保留原始数据 + 警告，不静默回退

1. `meta = STRATEGY_REGISTRY.get(key)` —— key 不存在 → `ValueError("Unknown strategy: {key}")`

**`_validate_registry()` 自检函数（模块级别，`strategy.py` 末尾 ~40 LOC）：**

在模块末尾定义，模块导入时自动执行一次（与 pity.py:804-821 模式一致）。验证失败抛出 `AssertionError`（代码逻辑错误——注册表不一致表明工程缺陷）或 `TypeError`（类型错误——装饰器使用不当）。

```python
def _validate_registry() -> None:
    """STRATEGY_REGISTRY 自检——模块导入时自动执行。

    验证内容：
    (a) 每个 entry 的 cls 非 None——除非 internal=True 且 _invalid_state 非空
        （internal 策略如 no_draw 允许 cls=None 作为纯占位，但有 _invalid_state 的
        插件也可能 cls 非 None / 部分可加载——此情况不检查 cls）。
    (b) 每个非 internal、_invalid_state 为空的 entry，cls 必须为 Strategy 子类。
    (c) 每个 entry.params 中所有 ParamDescriptor.key 无重复（同一策略内参数名唯一）。
    (d) 所有 entry.key 唯一（STRATEGY_REGISTRY 的 key 天然保证，额外显式断言）。
    (e) internal 与 disabled 正交性校验——不存在同时 internal=True 且 disabled=True 的条目。

    失败行为：
    - (a)/(b) 违反 → TypeError——cls 类型不满足约束。
    - (c)/(d)/(e) 违反 → AssertionError——注册表数据不一致。
    - 抛出异常会阻止模块导入（ImportError 链），在应用启动阶段立即暴露问题。
    """
    all_keys = set()
    for key, meta in STRATEGY_REGISTRY.items():
        # (d) key 唯一性
        assert key not in all_keys, f"STRATEGY_REGISTRY key 重复: {key!r}"
        all_keys.add(key)

        # (e) internal 与 disabled 正交
        assert not (meta.internal and meta.disabled), (
            f"STRATEGY_REGISTRY['{key}']: internal 与 disabled 不能同时为 True——"
            f"internal 策略永不对外暴露，disabled 语义不适用"
        )

        # (a) cls 非 None 检查
        if meta.cls is None:
            # 允许 internal + cls=None（如 no_draw 纯占位），但不允许非 internal 有 cls=None
            if not meta.internal and meta._invalid_state is None:
                raise TypeError(
                    f"STRATEGY_REGISTRY['{key}'].cls 为 None——"
                    f"非 internal 且无 _invalid_state 的策略必须提供可实例化的类"
                )
            continue  # cls=None 且合法，跳过后续 cls 检查

        # (b) cls 类型检查
        if not isinstance(meta.cls, type):
            raise TypeError(
                f"STRATEGY_REGISTRY['{key}'].cls={meta.cls!r}——必须为类（type）"
            )
        # 仅检查非 internal、加载正常的条目——internal 可能不是 Strategy 子类
        if not meta.internal and meta._invalid_state is None:
            if not issubclass(meta.cls, Strategy):
                raise TypeError(
                    f"STRATEGY_REGISTRY['{key}'].cls={meta.cls.__name__}——"
                    f"必须为 Strategy 子类"
                )

        # (c) params 参数名无重复
        if meta.params:
            param_keys = [p.key for p in meta.params]
            if len(param_keys) != len(set(param_keys)):
                from collections import Counter
                dupes = [k for k, v in Counter(param_keys).items() if v > 1]
                raise AssertionError(
                    f"STRATEGY_REGISTRY['{key}'].params 存在重复 key: {dupes}"
                )

_validate_registry()
```

**设计决策：** `_validate_registry()` 在 `create_strategy()` 工厂函数之前调用——注册表未通过验证时模块导入立即失败，不会在运行中意外构造错误的策略实例。这与 `pity.py` 的 `_validate_registry()` 在同模块末尾调用的模式一致（模块级副作用，导入即执行）。

    return type(action).__name__, type(strategy)._strategy_key

from gacha_simulator.core.strategy import (
    register_strategy, Strategy, StrategyContext,
    FloatParam, IntParam,
    DrawSegmentStrategy,
)
from gacha_simulator.core.action import DrawAction, WaitAction

@register_strategy('plugin/phased_plan', '两阶段策略',
    params=[
        FloatParam('early_threshold', '前期阈值(%)', default=80.0, min_val=0.0, max_val=100.0),
        FloatParam('late_threshold', '后期阈值(%)', default=50.0, min_val=0.0, max_val=100.0),
        IntParam('switch_at', '切换抽数', default=50, min_val=1),
    ])
class PhasedPlanStrategy(Strategy):
    """前N抽高阈值保守，后期低阈值激进。"""

    def __init__(self, early_threshold=80.0, late_threshold=50.0, switch_at=50):
        from gacha_simulator.core.strategy import PityReserveStrategy
        self.inner = DrawSegmentStrategy([
            (0, switch_at, PityReserveStrategy(pity_threshold_pct=early_threshold)),
            (switch_at, None, PityReserveStrategy(pity_threshold_pct=late_threshold)),
        ])

    @classmethod
    def description(cls):
        return "前N抽高阈值保守，后期低阈值激进"

        return self.inner.select_action(ctx)

### 最小约定

```python
from gacha_simulator.core.strategy import register_strategy, Strategy, StrategyContext
from gacha_simulator.core.action import DrawAction, WaitAction

@register_strategy('plugin/my_strategy', '显示名')  # ← key 必须以 'plugin/' 开头
class MyStrategy(Strategy):
    @classmethod
    def description(cls) -> str:
        return "一句话描述"

    def select_action(self, ctx: StrategyContext):
        # 决策逻辑
        return DrawAction(pool_id=ctx.current_pools[0].id)
```

**重要：** `@register_strategy` 的第一个参数 key 必须以 `plugin/` 开头。扫描器加载后校验此规则——未加前缀的插件将被拒绝注册并标记 `_invalid_state`。

### 可用的框架接口

| 接口 | 用途 |
|------|------|
| `StrategyContext` | 全部只读字段：`state` / `current_pools` / `all_pools` / `future_schedules` / `target_cards` / `acquired` / `total_draws` / `pool_draw_counts` / `ssr_ids` / `get_pity_probabilities(pool_id)` / `future_resource_gains`（阶段 2 后） / `inter_pool_pity_links`（阶段 2 后） |
| `Action` 子类 | `DrawAction(pool_id=str)` / `WaitAction(duration=float)` / `NonDrawAction(action_id, params)` |
| 内置策略类 | `SmartStrategy` / `PityReserveStrategy` / `PoolQuotaStrategy` / `StopOnTargetStrategy` / `FixedCountStrategy` / `TargetHuntingStrategy`——可在插件中直接实例化作为子策略 |
| 协作策略 | `DrawSegmentStrategy` / `PriorityChainStrategy` / `ConditionalStrategy`（阶段 3 后） |
| 参数声明 | `FloatParam` / `IntParam` / `BoolParam` / `StringListParam` / `PoolIntMapParam`——在 `@register_strategy` 中声明，框架自动处理校验 + GUI 渲染 |

### 不能做的事

| 禁止 | 原因 |
|------|------|
| 修改 `ctx` 的字段 | 上下文由框架管理，修改会导致未定义行为 |
| 依赖模块级全局变量 | 多进程并行模拟时子进程不共享全局状态 |
| 在 `select_action` 中执行耗时操作 | 每步模拟调用一次，N 次模拟 × T 步，耗时成倍放大 |
| 在插件文件中执行副作用（除 `@register_strategy` 外） | 文件被 import 时执行，按需只定义类和函数 |
| 显式依赖 PyQt6 或 `gui/` 中的模块 | 插件应能在 CLI 模式下加载（无 GUI 环境） |

### 内部状态

**允许**。策略实例的生命周期是整个模拟运行——`__init__` 在模拟开始时调用一次，`select_action` 在每一步调用，实例属性跨调用持久。

```python
@register_strategy('plugin/adaptive', '自适应阈值')
class AdaptiveStrategy(Strategy):
    gap_threshold = IntParam('gap_threshold', '连续不中阈值', default=10)

    def __init__(self, gap_threshold=10):
        self.gap_threshold = gap_threshold
        self.consecutive_miss = 0         # ← 内部计数器，跨 select_action 调用保持
        self.last_ssr_count = 0           # ← 上一轮的 SSR 总数

    def select_action(self, ctx):
        current_ssr = sum(ctx.acquired.values())
        if current_ssr == self.last_ssr_count:
            self.consecutive_miss += 1     # 这步没出 SSR
        else:
            self.consecutive_miss = 0
        self.last_ssr_count = current_ssr

        if self.consecutive_miss >= self.gap_threshold:
            threshold = 50.0               # 连抽不中，降低阈值激进
        else:
            threshold = 80.0
        ...
```

内部状态在每次 `run_batch_parallel` 中创建新策略实例时自动重置——不需要手动清理。

### 组合模式

内置策略类和协作策略可直接作为 building block：

```python
from gacha_simulator.core.strategy import (
    PityReserveStrategy,
    SmartStrategy,
    DrawSegmentStrategy,
    PriorityChainStrategy,
)

@register_strategy('plugin/hybrid', '混合策略')
class HybridStrategy(Strategy):
    def __init__(self, switch_at=100, threshold=80.0):
        # 分段：前 switch_at 抽用保底预留，之后降级为按需追卡
        self.inner = DrawSegmentStrategy([
            (0, switch_at, PityReserveStrategy(pity_threshold_pct=threshold)),
            (switch_at, None, PriorityChainStrategy([
                SmartStrategy(),
                PityReserveStrategy(pity_threshold_pct=threshold * 0.5),
            ])),
        ])

    def select_action(self, ctx):
        return self.inner.select_action(ctx)
```
