## 实施后记（2026-06-13）

### 架构重构

原设计采用**专用运行按钮 + 左侧独立 QLabel 结果区**。实施中发现该设计与统计分析面板的统一模式不一致——其他所有分析项均勾选后点击统一「运行分析」按钮、结果输出到右侧 ChartWebView、同样参数自动跳过（`_needs_computation` 缓存）。

重构后：
- **配置区**：保留在左侧可展开项内（GDR 下拉框、阈值、范围、第k池、置信水平）
- **触发方式**：勾选「成功率分析」→ 点击底部统一「运行分析」按钮
- **计算引擎**：集成到 `AnalysisWorker._run_impl()`，作为第 15 步 `('success_rate', '成功率分析')`
- **结果输出**：`ChartSpec(chart_type="table")` → 右侧 ChartWebView 渲染
- **缓存复用**：`_get_conditions_for_key('success_rate')` 收集 4 个专用参数 → `_needs_computation` 同参数跳过

### 输出格式

横排三列表格，判定标准以脚注形式显示在表格下方（`layout_hints.footnote` → `plotly_charts.py` 渲染为 `fig.add_annotation`）：

```
成功数 / 总数  |  成功率   |  95.0% Wilson CI
71 / 100      |  71.00%   |  [62.34%, 86.63%]
─────────────────────────────────────────────
成功判定：GDR 简单目标达成率 ≥ 1.0 算成功
```

### 设计决策记录

| 决策 | 结论 | 理由 |
|------|------|------|
| 标准误 | 不展示 | Wald SE 与 Wilson CI 框架不一致（Wald 对称 vs Wilson 非对称） |
| 方向标签 | 移除 | 判定标准已在脚注中完整表述，UI 上冗余 |
| 阈值 spinbox 宽度 | `setMaximumWidth(120)` | 避免过度拉伸 |
| 第k池 spinbox | 右对齐（`addStretch` 前置） | 与面板其他控件视觉一致 |
| 脚注方案 | `layout_hints.footnote` | 表格下方独立行，不挤占表格单元格 |
| 错误路径 | `ok` 标志位 | 防止 NameError（原代码 fallthrough bug） |
| itemData 防御 | `_sr_gdr` 局部变量 + `_gdr_key_by_name` fallback | 防止 `_repopulate_gdr_combos` 丢失 itemData 导致静默跳过 |

### 已知局限

- 资源类 GDR 在 `single_pool` 范围不可用（CompactResult 无逐池资源数据）→ 输出提示表格
- 资源消耗类 GDR 依赖 `CompactResult.total_consumed` 非空，否则 GDR 恒为 0 → 成功率恒 100%
- 逐池分析依赖流式 `cumulative_snapshots`，若未启用则弹窗拒绝

              compute_transition_flags_from_gdr  <!-- REVIEW-R1-FIX: ISSUE-020 — AnalysisPanel 需独立局部导入 -->
