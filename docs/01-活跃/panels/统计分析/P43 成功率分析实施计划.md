### 阶段 2：核心计算（~40 行）

- [ ] **S2.1** 实现 `_run_success_rate_analysis()`

  位置：`analysis_panel.py` `AnalysisPanel` 类内。

  **关键：数据获取使用真实属性名。**
  - `self.results` — 当前批次的 `List[CompactResult]`（`update_results()` 注入，line 2282）
  - `self._gdr_context.target_specs` — 目标卡规格（line 2133）
  - `self._store` — ConfigStore（line 1388）
  - `self._cumulative_snapshots` — 逐池累积快照 `Dict[str, List[Dict]]`（line 2287，流式分析产出）

  ```python
  def _run_success_rate_analysis(self):
      """执行成功率分析：遍历 CompactResult → is_success → wilson_ci"""
      # 1. 取参数
      gdr_key = self.success_rate_gdr_combo.currentData()
      threshold = self.success_rate_threshold_spin.value()
      scope = self.success_rate_scope_combo.currentData()
      pool_idx = self.success_rate_pool_spin.value() - 1  # 0-based
      conf_level = self.success_rate_conf_spin.value()

      # 2. 取数据（真实属性名）
      results = self.results
      if not results:
          QMessageBox.warning(self, "无数据", "请先运行批量模拟")
          return

      target_specs = self._gdr_context.target_specs if self._gdr_context else {}
      store = self._store

      # 3. 构造判定器（遵守 GDR 调用规范——make_gdr_calculator 自动提取权重）
      calc = make_gdr_calculator(store, target_specs, gdr_key,
                                 gdr_threshold=threshold)

      # 4. 遍历判定
      if scope == "overall":
          # 总体——直接对每个 CompactResult 做 is_success
          success_flags = [calc.is_success(r) for r in results]
      else:
          # 逐池——使用 compute_transition_flags_from_gdr（S2.2）
          cumulative_snapshots = self._cumulative_snapshots
          pool_ids_ordered = list(cumulative_snapshots.keys()) if cumulative_snapshots else []
          if not cumulative_snapshots or not pool_ids_ordered:
              QMessageBox.warning(self, "数据不足",
                  "逐池分析需要 cumulative_snapshots，当前批次未提供。\n"
                  "请重新运行批量模拟（需启用流式分析）。")
              return
          if pool_idx >= len(pool_ids_ordered):
              QMessageBox.warning(self, "范围错误",
                  f"第 {pool_idx + 1} 个池不存在（实际共 {len(pool_ids_ordered)} 个池）")
              return

          all_flags = compute_transition_flags_from_gdr(
              cumulative_snapshots, pool_ids_ordered,
              target_specs, gdr_key=gdr_key, threshold=threshold,
              scope=scope, aggregates=results,
              ssr_ids=self._gdr_context.ssr_ids if self._gdr_context else set(),
              desire_weights=store.desire_weights,
              miss_cost_weights=store.miss_cost_weights,
              card_value_weights=store.card_value_weights,
          )
          # all_flags[i][k] = 第 i 次模拟第 k 池的成功标志
          success_flags = [flags[pool_idx] for flags in all_flags]

      # 5. 汇总
      success = sum(success_flags)
      total = len(success_flags)
      rate = success / total if total else 0.0

      # 6. Wilson CI
      from gacha_simulator.core.process_analysis import wilson_ci
      ci_lower, ci_upper = wilson_ci(success, total, conf_level)
      se = (rate * (1 - rate) / total) ** 0.5 if total else 0.0

      # 7. 展示
      defn = UNIFIED_GDR_REGISTRY.get(gdr_key)
      lower_is_better = defn.lower_is_better if defn else False
      self._show_success_rate_result(success, total, rate,
                                     ci_lower, ci_upper, se, conf_level,
                                     lower_is_better)
  ```

  ```python
  def compute_transition_flags_from_gdr(
      cumulative_snapshots: Dict[str, List[Dict]],  # ← self._cumulative_snapshots
      pool_ids_ordered: List[str],                   # ← list(cumulative_snapshots.keys())
      target_specs: Dict[str, int],                  # ← self._gdr_context.target_specs
      gdr_key: str = 'all_targets',
      threshold: float = 1.0,                        # ✅ 支持自定义阈值
      scope: str = 'cumulative',                     # 'cumulative' | 'single_pool'
      aggregates: List[Dict] = None,                 # ← self.results (CompactResult 列表)
      ssr_ids: Set[str] = None,
      **gdr_kwargs,                                  # ← 透传权重
  ) -> List[List[bool]]:
  ```

  **关键约束**：该函数依赖 `cumulative_snapshots`——由流式分析（`StreamingAnalyzer`）在批量模拟期间预构建，通过 `update_results(cumulative_snapshots=...)` 注入面板（line 2287）。若用户未启用流式分析，`self._cumulative_snapshots` 为空 `{}`，此时 S2.1 会弹窗提示并拒绝运行逐池分析。

  **`threshold` 参数已验证支持**（line 290）——直接传入用户自定义阈值即可，无需额外适配。

## 与 P22 的交互

本计划与 P22（多资源类型展开）的**唯一交互点**是 GDR 下拉框数据源：

```
当前（P22 未实施）: 遍历 UNIFIED_GDR_REGISTRY → 17 条
P22 合入后:         遍历 get_expanded_gdr_entries(resource_defs) → 21 条（含 :qualified key）
```

**切换方式**（P22 合入后单行改动）：

```python
# 旧（S1.2 初始实现）
for gdr_key, defn in UNIFIED_GDR_REGISTRY.items():
    self.success_rate_gdr_combo.addItem(...)

# 新（P22 后）
for key, display, lib, thr in get_expanded_gdr_entries(self._store.resource_defs):
    self.success_rate_gdr_combo.addItem(f"{display}", key)
```

S1.3 的 `_on_success_rate_gdr_changed` 同步改为 `resolve_gdr_definition(key).default_threshold`（P22 S1.2b 提供）。

**结论：两计划互不阻塞，任意顺序合入均可。** P43 先用原始注册表运行；P22 合入后改两行数据源即获得多资源类型支持。
