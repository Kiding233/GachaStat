GachaStat 图表标准

所有图表按 ECharts 5.6 交互式渲染，走 ChartSpec IR → renderer 这条真实管线。

本页同时是全图型的冒烟测试：每种 chart_type 至少渲一个实例，改渲染器后先看这一页。

依赖没加载上。本页需要 libs/echarts.min.js、libs/gs-charts.js、 libs/vuemin.js。三者都在仓库里，走 file:// 打开即可，不需要联网。

4. 版面纪律（与图注体系配套）

图题不画在图里。图注体系要求「图题在图下、表题在表上」， 所以标题、导语、图注、口径脚注全部由 HTML 承载，ECharts 主题里 title 默认关闭。

容器高度必须含轴标签带。定高裁掉 x 轴会让卡片长出一条细滚动条， 这是常见反模式；grid.containLabel 与显式 height 一起保证不裁。

网格线是一档深于表面的灰、发丝、实线。虚线留给阈值， 否则读者会把网格读成「预测值」。

5. 登记的偏差与待决

① 后端 IR 的默认色阶 Viridis 在浅色底上不成立。 校验器对 #440154…&fde725 跑 ordinal 模式：亮度单调 PASS，但色相跨 144°（非单一色相）， 且亮端 #fde725 对白底仅 1.26:1（门槛 2:1）。 本页矩阵一律渲成单色蓝。接线时需决定：改 chart_spec.py 的默认值，还是保留 Viridis 并接受这两条不通过。现状：探针按标准渲染，偏差已登记未消除。
② 两处 token 文件不一致。 tools/poc_webview/ui_compare/src/styles/tokens.css 里的 --gsc-chart-palette 是 matplotlib tab10（#1f77b4,#ff7f0e,#2ca02c,#d62728,…）， 含橙与红，与语义色纪律冲突；--el-border-radius-base:2px 与 layout_demo 的 6px 圆角也分叉。本页图表令牌定义在 libs/gs-charts.css， 是当前唯一真相源。合并两套设计时要么改 tokens.css，要么退役该文件。
③ 深色模式未做。 深色模式不是把浅色翻过来，而是从同一批色阶里另选步进并对着深色表面重新跑校验。 当前 GUI 与探针都只有浅色，故未做，登记为缺口而非「以后顺手翻一下」。
