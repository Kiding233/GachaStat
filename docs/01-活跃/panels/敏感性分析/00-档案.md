## 业务问题

批量模拟产出的是**一组固定参数下的样本**。用户拿到的结论——「策略 A 的成功率是 0.93」「B 比 A 多拿 0.4 张目标卡」「A 一阶随机占优 B」——都是**单点结论**。但决策者真正要问的是下一层：

1. **变动这个参数，我关注的量会怎么变？** 形状（单调 / 平台 / 跳变 / 非单调）与幅度（θ 动一点，s 变多少）。**这是主诉求。**
2. **哪个参数最要紧？** 资源投在哪个维度的改善上收益最大
3. **这个结论有多稳？** 参数动一点，结论还成立吗
4. **结论在哪里翻转？** 距离翻转还有多少余量。这是第 1 条的读法之一：曲线穿过判据线的位置

现有面板答不出这四个问题。对比分析（`gui/comparison_analysis_panel.py`）只比较给定数据集；统计分析（`gui/analysis_panel.py`）只描述当前数据集；方案搜索（P26）沿**资源**维度搜索，是单维度的特例。缺的是一层通用的「沿任意参数维度扰动、看结论怎么变」的能力。

同时本项目还有一类独家需求：**手册 §二十一 的 U1 到 U15 全是「官方未公布、社区假设」的机制参数**（U7 异环两套机制二选一、U8 异环武器池 UP 率 25% vs 75%、U13 战双命运池 T∈[80,100] 的分布）。这些不确定参数的处置方式是「在两种互斥取值下各跑一遍，看结论是否翻转」：翻转则该 U 项升级为必须查证的高优先项，不翻转则可安全标注「结论对 U8 不敏感」。这是本功能对项目推进最直接的贡献。

## 设计意图

### 核心抽象

- **可扫描参数分四类**，判据是「**模拟器读不读它**」，不是「它写在哪个文件里」：
  - **口径参数 分析层旋钮**：不重跑模拟，属复算侧。GDR 指标与阈值、desire／miss_cost／card_value 三权重、VaR 的 alpha、CI 水平、成功判据
  - **策略参数 策略参数**：需重跑，属派发侧。`store.strategy_params`，P69 的 `StrategyMeta.params` 已声明
  - **机制参数 机制与卡池参数**：需重跑，属派发侧。池子 cost／概率／batch_size／时间窗、`PityDef` 24 字段、`MilestoneDef` threshold、初始资源与收入规则
  - **精度参数 方法自身旋钮**：不重跑，属复算侧。bootstrap B、EVT 尾部起点、PAVA 参数、搜索的 `num_simulations` 与 `precision_draws`、`n_heatmap_bins`
- **扫描规格三种模式**：数值栅格（区间＋步长，出曲线）、离散枚举（布尔／字符串／列表／映射，出对比）、互斥分支（U 系列的二选一）
- **翻转点**：结论在参数轴上的翻转位置与裕度，是本功能的主产出
- **结果对象**：沿用 P86 的 `sections`（图表优先）。曲线与对比是 `ChartSection`；各点 CI 是同图上的误差带；翻转点是同图上的 `ChartAnnotation(vline)`；机器消费的数字进 `SummarySection`
- **一等产出是响应曲线**，含形状与幅度；「结论是否成立」只是曲线穿过判据线的一个特例，不是主诉求

### 与近邻概念的边界

| 概念 | 扰动对象 | 例子 |
|---|---|---|
| **敏感性**（本计划） | 确定性地改参数，看结论怎么变 | 阈值 θ 从 0.80 扫到 0.99，翻转点在 0.932 |
| **稳健性** | 改的是机制**假设** | P31 缺陷 28：虚拟池同质化假设抹掉了「连续高成本池」这一失败模式 |
| **不确定性** | 参数本身有分布，做传播 | 手册 U13 战双 T∈[80,100]，需先验分布 |

三者常被混用（`docs/架构设计.md` E3 写作「敏感性／稳健性分析」，P74 写「敏感度分析」）。本计划只做第一个；U 系列那种「互斥二选一」按敏感性处理（两点比较），不引入参数先验。

### 分层与调用关系

```
前端（P74 分析页「敏感性分析」专题）
    ↓
P90 敏感性分析          ← 与 GUI／WebUI 平级，是 AnalysisRunner 的第三个调用方
    ├── 复算侧：循环调 AnalysisRunner.run(dataset_ids, method, params_v)
    └── 派发侧：P87 变换器生成 N 个 sub 配置 → 运行器派发 → 分析侧读结果
    ↓
P86 AnalysisRunner / P87 变换器·运行器·汇合器
```

**不新增「分析调用分析」机制。** 敏感性分析不进 P86 的分析项注册表，因此不存在「注册表项调用注册表」的循环问题；它用 `AnalysisRunner.run()` 这个既有公开入口，与 GUI／WebUI 一样是客户端。

## 技术实现

### 复算侧：一次遍历 ＋ N 次归约

`StoredDataset.aggregate_data`（`core/result_store.py:92`）逐样本保留 `CompactResult` 的 dict，所有 GDR 都从单个 compact 算（O(1)）。因此口径参数扫描不需重跑模拟，只是对同一批 n 个 compact 反复归约。

其中 `gdr_threshold` 只在 `GDRCalculator.is_success()`（`core/gdr.py:677-679`）做**后置比较**，不进 `compute_gdr()`：扫阈值时每样本的 GDR 值算一次即可复用 N 次。`alpha` 与 `ci_level` 同理。三个权重则确实进 `compute_gdr()`（`core/gdr.py:668-670`），每点要重算 O(n) 的值，但仍不重跑模拟。

### 派发侧：复用 P87 编排

一次扫描的 N 个 sub 配置是一个**批次**（P87 §3.11 F 的派生批次标识）。运行器按 sub 配置调用，与 P87 既有形态一致，不需要「一次池派发跑完 N×M」的改造。依据是实测：`run_batch_parallel` 每次调用新建进程池，固定开销约 0.56 s/次，边际约 14.4 ms/样本（示例配置、4 worker），固定部分在「每点 1000 样本约 14.4 s」面前只占约 4%。

**流式分析默认开**。P74 的数据集选择器按可分析性过滤（`工作区交互形态.md` §5.2：样本数 > 1 且跑过流式分析），扫描派发出的数据集若不跑流式就进不了选择器，成为不可再分析的死数据；而 P87 §3.11 F 明确要「sub 配置也可以选中做其他分析」。

### 阶段 0a：ChartSpec 扩展

误差带（各扫描点各自的 CI）在 ChartSpec 里无处表达：`ShadedRegion` 只支持 x 方向区间（`visualization/chart_spec.py:194`），`ScatterTrace` 没有填充字段（`:62`）。因此给 `ScatterTrace` 加 `y_lower` / `y_upper` / `fill_color`，PlotlyRenderer 用 `fill='toself'` 实现。

**不用 Plotly 的 `tonexty`**：它的语义是「填到列表中下一条 y 轨迹」，依赖顺序，且是 Plotly 私有；ECharts 无此原语（POC renderer `tools/poc_webview/ui_compare/src/panels/workbench/specToECharts.js` 用堆叠 area 画带子）。IR 只表达意图，两个渲染器各自实现。

webui 序列化走 `webui/analysis_service.py:36` 的 `_spec_to_dict`（`dataclasses.asdict` ＋ 递归 `_clean`），新增字段自动跟随，四处副本都不用改。

### 阶段 0b：曲线工具提取

`core/vulnerability.py` 里已有「分箱 → 保序回归（PAVA）→ 变更点置信区间 → 连续区间提取」的完整工具链，现只服务脆弱性分析。两者结构同构，差异只在 x 轴的语义（脆弱性是**样本内变量**，敏感性是**数据集间标签**），故提取为 `core/curve_analysis.py` 共用。

`_find_contiguous_intervals_from_curve`（`:805`）/ `_wilson_ci`（`:175`）/ `_diagnose_monotonicity`（`:203`）零领域知识，可直接搬；`_changepoint_ci`（`:278`）搬方法与输出契约（`x_star_pt` / `x_star_lo` / `x_star_hi`，即 BMD / BMDL 形态）但换输入。`binsglm` 分箱看扫描密度，高密度时可开它自带的 `cb` 拿同时置信带；它**本身是非保序**的分箱平滑器。

**但 PAVA 不能默认用**：脆弱性的工具链建立在「响应单调」这个**强制假设**上（其 H4，依据是经济直觉），而敏感性分析的主诉求恰恰是问单调与否。默认套 PAVA 是循环论证。默认路径为不保序的逐点估计 ＋ 区间（或高密度时的非保序平滑 ＋ `cb` 带）；PAVA 仅在显式声明单调或作对照时使用。

**按扫描类型分开**：阈值型扫描（扫判据 τ）下 `ŝ(τ) = P(s ≥ τ)` 关于 τ **必然递减**，是结构性事实，PAVA 可用；非阈值型扫描下单调性待验，默认不用。

完整清点见 `01-理论.md` §八与计划 §3.7.1 / §3.8b。

**连带纪律**：这是对**已上线模块**的改动（P51 已完成脆弱性分析），须做基线固化 ＋ 等价对照。

### 呈现：三行子图

沿用脆弱性分析的图形语法（`plot_vulnerability` 的 `rows=3` 布局）。行的语义是「① 支撑情况 → ② 推断主图 → ③ 每点可靠性」；第②行**逐元素同构**（响应曲线 ＋ 误差带 ＋ 判据线 ＋ 成立域着色 ＋ 翻转区间 CI 带）；第①行**换变量后同构**（放与判据直接相关的样本内变量的分布，阈值型扫描下即响应值的生存函数视角）；第③行只是**换量占位**（等样本量下脆弱性那行的 `N_j` 本就接近常数，敏感性侧更是恒定）。
